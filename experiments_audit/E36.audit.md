# E36 audit — `toxi_proof.py` / `toxi_proof.{json,md,png}`

Audit date: 2026-10-20. Scope: the pre-clean toxicity proof (`toxi_proof.py` -> `toxi_proof.json`,
`.md`, `.png`, `.pid`, `toxi_proof_status.json`), its data inputs in `FredZhang7/toxi-text-3M`, and
its relation to E20 (`toxi_proof_clean.py`). No repo file was edited. Only `E36.md` and
`E36.audit.md` were written. `git status` on the four artifacts is clean; the dataset was read
read-only from the local HF cache.

Verdict of the audit: **the run is what it claims to be — a pre-clean run on the leaky shipped
splits — but its own report and its commit message overstate the leakage handling.** It must be
documented as provenance only, never as leakage-corrected evidence.

## Discrepancies

1. **"EN overlap is ~0, so EN is unaffected" is false at the pool level.** `toxi_proof.md:9` claims
   EN overlap is about zero. The stored removal of 3 EN rows is real, but it is a sampling artifact:
   only 20,000 of 2,528,002 EN rows are drawn. Measured directly, **473 of 525 EN eval-test texts
   (90.1%) appear verbatim in the shipped EN train file**. The correct statement is "the sampled
   training rows contain 3 EN test texts", not "EN is unaffected".

2. **The leak parenthetical measures the sample, not the pool.** `toxi_proof.md:9` says "it 97% /
   fr 76% / es 75% / de 85% of the test texts were in the train pool". Those are exactly
   `leak_removed / eval_test_n` (4,847/5,000 = 0.969; 3,807/5,000 = 0.761; 3,755/5,000 = 0.751;
   161/190 = 0.847). The true pool overlap is higher or equal: **99.9% (it), 99.9% (fr), 99.8%
   (es), 84.7% (de — its whole 12,255-row pool was sampled), and 90.1% for en**, which the sentence
   calls zero. The MD understates the problem.

3. **The commit message claims "leakage-corrected".** `ee65ab7` is titled "…toxi-text-3M (binary,
   unbalanced, multilingual; leakage-corrected)". That is wrong and contradicts COVERAGE.md §3 and
   the E20 entry. It must not be copied into any doc.

4. **The split defect is never mentioned in the run's own report.** The shipped test split has a
   label distribution that contradicts the train pool: en 0.625 vs 0.117, de 0.716 vs 0.299, it
   0.185 vs 0.295. The EN reference AUC is therefore computed on a distribution the model was never
   trained on, and it is not the same quantity as E20's EN reference. This is the strongest reason
   E20 supersedes the run; the MD is silent on it.

5. **`config.avail_train_rows` is misnamed and misleading.** The JSON key holds the *sampled* counts
   (`en 20000, it 20000, de 12255, fr 20000, es 20000`), not availability. The real pool sizes
   (2,528,002 / 20,611 / 12,255 / 26,175 / 26,726) are not stored anywhere in the payload, so the
   JSON alone cannot show that EN was sampled at 0.8% and it/fr/es at ~75-97%.

6. **"each target likewise sampled" implies 20,000.** `toxi_proof.md:7` reads that way; de has only
   12,255 rows, and 12,094 after leak removal.

7. **The reported verdict uses the wrong bar.** The code (and MD/PNG) use a 0.9 bar and only the
   EN/native ratio, and print "comparable". The study bar is 0.975 on both ratios: 1/4 and 1/4, and
   both are artifacts.

8. **Single seed vs E20's three.** E36 has one run and no variance. E20's sd cannot be compared to
   it; the de native swing (+0.280) is partly a 190-row test artifact, not a measurable effect.

9. **Reproduction is partial, not full.** The numbers in the JSON cannot be re-derived on this
   machine: `%TEMP%\opencode\toxi_cache` is empty and no model was saved. Re-verification requires
   re-embedding ~95k texts and refitting 5 models, and a plain rerun overwrites the committed
   provenance artifacts in the repo root.

## Bugs / risks

1. **`dedup_test` is partial leakage handling presented as correction** (`toxi_proof.py:336-362`).
   It removes exact eval-test texts from the sampled train rows only. The splits stay as shipped.
   Nothing removes near-duplicates, normalized duplicates or translation contamination. On this
   dataset that residue is large: E20 measured 39/70/91/37 residual normalized matches per target
   test, and this audit measured 84.7-99.9% verbatim pool overlap.
2. **No test-vs-train distribution check.** The script never compares per-language test pos rates to
   the train pool. The two differ by up to 0.42 absolute (de), which invalidates any native-vs-EN
   comparison on that split.
3. **`de` passes EN/native 0.975 on 54 negatives.** The native de model is trained on 29.9% positives
   and tested on 71.6% positives, so its AUC (0.5888) is below the EN model's (0.6254). The 1.0622
   ratio is an artifact of the split, not evidence that English transfer beats native training.
4. **Verdict logic is lenient and single-bar** (`toxi_proof.py:564-572`). It uses `>= 0.9`, checks
   only EN/native, and has a "largely comparable" branch at 3/4 that would fire even with 0/4
   target/EN. The PNG also draws a 0.9 line (`:591`), which visually reads as a pass.
5. **`f1_optimal_threshold` last-point clamp** (`:174-181`): if the F1 argmax is the final precision
   point, `k` is clamped to `len(thr)-1`, which is the second-to-last point. F1 is not the headline
   metric here, but the F1 column is slightly off.
6. **The EN threshold is applied to every target** (`:389`, `:410`). With the shipped splits this is
   visibly broken: de accuracy 0.295, de F1 0.029 at a 71.6%-positive test. AUC/AP remain valid
   (threshold-free); accuracy/F1/recall-at-FPR do not.
7. **`perlang_z` uses target train rows** (`:371-374`). The "English-trained" model consumes each
   target's train mean/std. Documented in the MD, but it means the model is not target-free.
8. **No dataset revision pin** (`:217`, `:236`). `load_dataset(DATASET, data_files=...)` uses
   whatever `main` is. The stored run matches revision `e1e50df2`; a future rerun would silently
   produce different samples.
9. **Rerun overwrites provenance.** Outputs are hard-wired to the repo root (`:71-75`) and there is
   no `--render`. Any re-execution replaces the committed JSON/MD/PNG at 2026-10-12.
10. **Empty cache is a trap for a future reader.** `toxi_cache` looks current (mtime 2026-10-20) but
    has zero files. `ensure_emb` (`:315-323`) keys on the tag only, with no data hash. If the cache
    is ever repopulated from different data, a rerun will silently mix it.

## Missing scripts

None. `toxi_proof.py`, `launch_hidden.vbs`, `gpu_limit.py` and `clean_toxi.py` all exist, the
`FredZhang7/toxi-text-3M` cache is present, and `toxi_proof.{json,md,png}` are committed at `ee65ab7`.

Missing **artifacts** (why reproduction is PARTIAL):
- `%TEMP%\opencode\toxi_cache` is empty (no `test.parquet`, no `samples.parquet`, no `emb_*.npy`).
- No saved models. E20 saved 15 `.ubj` files, which is what made E20's AUCs verifiable to 1e-6.
  E36 saved nothing.
- No `--render` path, so the MD/PNG cannot be rebuilt without retraining.

## Recommended changes

1. **Document E36 as a provenance note under E20, never as a result.** Suggested one-liner for
   `EXPERIMENTS.md`:
   > **Provenance (pre-clean, do not quote).** `toxi_proof.{json,md,png}` (2026-10-12) is the
   > predecessor of E20. It ran on the original leaky `toxi-text-3M` splits: 85-99.9% of its
   > eval-test texts appear verbatim in the shipped train file, and its test label rates contradict
   > the train pool (en 0.625 vs 0.117, de 0.716 vs 0.299). Its numbers (EN/native 0.94/1.06/0.91/
   > 0.93; target/EN 0.97/0.80/0.95/0.99) are not leakage-corrected and are superseded by E20.
2. **Do not add the E36 0.975 cells (1/4 and 1/4) to any results table.** They are artifacts of a
   190-row de test and a misaligned es test. If they are listed at all, mark them "leaky split".
3. **Keep the artifacts.** They are the evidence for why E20 exists. Keep them committed and keep
   the commit hash `ee65ab7` in the note.
4. **If a rerun is ever required:** copy the script to `%TEMP%\opencode\`, pin
   `revision=e1e50df2f511e62d921448c40bd64b7308ac6ede`, and write outputs to a temp dir. Never run
   `toxi_proof.py` from the repo root again.
5. **Fix the MD text if the script is reused** (`build_md`, `:486-491`): say "of the sampled train
   rows" instead of "of the test texts were in the train pool", and drop "EN overlap is ~0".
6. **Store the real pool sizes and the test pos rates in the JSON** (rename `avail_train_rows`, add
   `test_pos_rate` per language) so the split defect is visible from the payload alone.
7. **Split the two bars in `build_md`** and use 0.975. The current 0.9/single-bar logic produced a
   "comparable" verdict on a run that fails both 0.975 bars.
8. **Fix `f1_optimal_threshold`** (`thresholds[np.argmax(f1[:-1])]` or an explicit last-point rule).
9. **Do not reuse this script as a template for new data.** `clean_toxi.py` + `toxi_proof_clean.py`
   already provide the correct pattern (pool -> dedup -> re-split -> assert 0 overlap).
