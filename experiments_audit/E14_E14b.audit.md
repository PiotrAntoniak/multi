## Bugs / risks

1. **In-sample threshold tuning (critical).** `run_dataset` sets `tr = D["trval"]` and fits on it
   (`:785`, `:795`), then builds `Pv = clf.predict_proba(Xf["en"][va])` (`:800`) and calls
   `evaluate(..., y[va], Pv, ...)`, which picks the F1-optimal threshold on those same rows
   (`:371-373`). `np.isin(val, trval).all()` is True. Measured consequence: val micro-F1 and
   macro-F1 are **1.0000** at t = 0.04 for raw EN and for the it reference on both datasets (also
   confirmed for `l2_thenZ` and `pc+inlp` on sent), so
   `best_t_global` returns the lowest grid point (0.04) every time. On test, t = 0.04 is far from
   optimal: sent EN micro 0.4594 at t = 0.04 vs 0.6224 at the test-optimal t = 0.36; macro 0.4147
   vs 0.5086 at t = 0.28. Agg EN micro 0.4495 vs 0.6667 at t = 0.28. The reported numbers are
   neither held-out nor test-optimal; they are an in-sample artefact.

2. **The threshold bug is not uniform across methods.** kNN tunes on EN val with gallery = EN
   train only, so its threshold is honest (t = 0.30 sent, 0.32 agg). Translate-train / affine / MLP
   tune on target val whose **labels** are in the fit set, but the target text is unseen, so they
   land at t = 0.16–0.48 rather than the 0.04 floor. The 8 XGB feature methods and both references
   land at 0.04. The kNN-vs-XGB and ensemble-vs-member gaps are therefore partly threshold
   protocol, not representation.

3. **Honest control changes the raw gap materially (but not the verdict).** Fit on train only
   (997 / 276 rows), tune on val, evaluate test: sent raw EN→it/de/fr micro 0.388/0.403/0.399 vs
   reference 0.514/0.487/0.534 → ratios **0.755/0.827/0.747** (reported 0.712/0.623/0.736). Agg
   0.526/0.429/0.436 vs 0.591/0.606/0.598 → **0.889/0.708/0.730** (reported 0.676/0.599/0.648).
   EN self rises from 0.459 to 0.542 (sent) and 0.449 to 0.616 (agg). The honest model uses 997 /
   276 rows instead of 1501 / 416, so this is a conservative lower bound on the threshold effect.
   Raw still fails 0.975, but "raw closes 0% of the gap" is a protocol artefact in magnitude.

4. **Selection on test.** `knn_best` ranks 6 transforms × 5 k × 2 variants (60 options) by mean
   **target test** micro-F1 (`:447-456`, `:821-827`); `run_ensembles` picks the top-3 feature
   methods by mean **target test** micro-F1 (`:637-640`). No validation-based selection. The kNN
   row and both ensemble rows are optimistically selected.

5. **`--smoke` and `--datasets sent` destroy the committed artifacts.** `main` writes `OUT_JSON` /
   `OUT_MD` unconditionally (`:938-941`), and `--smoke` sets `dss = ["sent"]` with 60 trees
   (`:289-290`, `:927`). Running the documented `python flores_close.py --smoke` overwrites the
   2-dataset result with a sent-only, 60-tree result. `--launch --smoke` does the same, detached.
   No guard, no backup, no resumability.

6. **MLP alignment is not reproducible.** `_mlp_fit` (`:562-596`) uses unseeded `torch.randperm`
   and default torch initialisation. `mlp_align` numbers will drift between runs. XGB (seed 0),
   PCA (`random_state=0`) and INLP are deterministic.

7. **Missing provenance in the JSON.** Ensemble members are computed but discarded
   (`run_dataset:876` stores only `rec["metrics"]`); the JSON cannot say which three methods formed
   `ens_top3`. Reconstructing by the ranking gives sent `[pc+inlp, pc3, pc+l2_thenZ]` and agg
   `[inlp+l2_thenZ, l2_thenZ, pc+l2_thenZ]`, but that is inference, not a record. Only the top-6
   kNN variants are stored (`knn_best`), not the 60-cell grid; `knn_detail` is built (`:828`) and
   never written.

8. **"Ceiling" is not a ceiling.** Five methods exceed it on both datasets, and the reported
   reference itself is depressed by the t = 0.04 artefact (sent it reference 0.4291 vs 0.5807 at
   the test-optimal threshold). It is an in-language **reference** trained on 1501 labels with the same
   fixed XGB config, not an upper bound.

9. **Partial failures still look complete.** Alignment and ensemble errors are caught
   (`:867-880`); translate-train failures are logged per language (`:850-851`). The run still
   writes a JSON and a `finished` status with no error field, so a missing method row is not
   distinguishable from a successful run.

10. **Stale PID.** `flores_close.pid` holds PID 4900, which is not running. Harmless, but it
    violates the cleanup convention.

11. **MT cache is keyed only by dataset and language.** `CACHE/tt_emb_<ds>_<lang>.npy`
    (`:494-497`) is not keyed by the source CSV, the MT model or the embedder. If the input text or
    model changes, the old translations are silently reused.

12. **Dead duplicate of translate-train.** `run_translate_train` (`:528-547`) is never called; the
    inline block (`:831-859`) reimplements it. The two can drift.

13. **Latent kNN shape bug.** `knn_scores` sets `C = int(gallery_y.max()) + 1` (`:398`). If the EN
    gallery misses the highest class, the score matrix has fewer columns than `n_classes` and
    `prf_ovr` silently scores only the first `C` classes. Not triggered here (all classes present).

14. **Metric degeneracy at the chosen threshold.** At t = 0.04 the EN sent model predicts 2.80
    classes/row (1.36 at t = 0.20). Micro-F1 is a multi-label OVR score, not the single-label score
    used elsewhere in the report. The entry must say so.

15. **Tie-break amplifies the threshold bug.** `best_t_global` uses strict `>` and keeps the first
    maximum, i.e. the **lowest** threshold in a tie. On an in-sample-perfect val every threshold
    above 0.02 ties at 1.0, so it picks 0.04, the most aggressive choice.

16. **The INLP probes do not converge.** `flores_close.log` contains 16
    `lbfgs failed to converge` ConvergenceWarnings from `LogisticRegression(max_iter=200, C=1.0)`
    on 768-d features. The ignore filter at `:71-75` does not suppress them. The INLP basis is
    reproducible but comes from under-converged probes; standardize the probe input or raise
    `INLP_MAX_ITER`. Low impact here (both INLP rows fail by a wide margin).
