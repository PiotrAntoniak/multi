# E2 audit — translated SST-2 / emotion eval sets

Scope: EXPERIMENTS.md line 383 (the E2 bullet), REPRODUCE.md line 66, `rebuild_caches.py`,

## Verified

1. **All 36 data artifacts exist and match the script's naming.** 12 CSVs in `translated/`
   (`{sst2,emotion}_{it,de,fr}_{validation,test}.csv`, columns `text,label`) and 24 NPYs in
   `translated_emb/` (`{dataset}_{mean,bos}_{lang}_{validation,test}.npy`). File sizes are exactly
   consistent with shape: sst2 20,957,312 B = 6,822 x 768 x float32 + header; emotion 6,144,128 B =
   2,000 x 768 x float32 + header. Total 314.0 MB (310.2 MB embeddings, 3.8 MB CSVs).

2. **Row counts, row order and labels are exact against the English source.** For all 12 CSVs the
   row count and every label equal the corresponding `sst2.csv` / `emotion.csv` split in order
   (sst2 6,822 val / 6,822 test; emotion 2,000 / 2,000). No shift, no reordering, no label leakage
   from a neighbouring row. Source distributions: sst2 test 3,081 neg / 3,741 pos; emotion test
   581/695/159/275/224/66 over the 6 classes.

3. **MT provenance is exact for all three models.** Re-decoding rows with
   `Helsinki-NLP/opus-mt-en-{it,de,fr}` (greedy, `num_beams=1`; the 6-row check ran fp32 on CPU,
   the batch replays fp16 on CUDA) reproduces the stored strings character for character: 10/10
   checked (sst2 rows 0-1 per language, plus emotion rows 0-1 for fr and row 0 for de/it). This
   includes the low-quality outputs, e.g. de "im Gefuehl ziemlich faul so im nicht sehr ehrgeizig
   jetzt", so the cache is genuinely this pipeline and not a later edit.

4. **MT batching is reproduced, including a batch-dependent defect.** The 5 blank Italian outputs
   (sst2_it_validation rows 5606, 6014; sst2_it_test rows 5965, 6369, 6607) come from quote-only
   fragments such as "` gentle ' ". Decoded in a 3-row batch the three test rows return `''`;
   decoded in the original 64-row batches (rows 5568-5631, 5952-6015, 6336-6399, 6592-6655) all 5
   return the empty string, exactly as stored. `MT_BATCH=64` is thus confirmed, and decode is
   batch-composition dependent on these degenerate inputs.

5. **Embedding recipe is the documented one.** `embed_texts` (lines 183-214) is the same code as
   `xgboost_sst2.py::embed_split`: EuroBERT-210m, fp32, batch 256, max_len 512, masked mean over
   non-pad tokens including the appended end token; `bos` = position 0 after manually prepending
   the BOS id. Id 128000 is the tokenizer's real BOS (`<|begin_of_text|>`), not an arbitrary id.
   Re-embedding 10 rows (sst2/it and emotion/de, mean and bos) gives max absolute difference
   4.6e-4 and cosine >= 0.99999994 versus the cache. Magnitudes are sane: row norms 49.6-120.1, no
   zero or non-finite rows, mean != bos.

6. **The script's own cache validation passes on every artifact.** Calling `cached_npy` /
   `csv_is_complete` from the module for the full expected set gives 48/48 valid (12 source
   embeddings + 12 CSVs + 24 translated embeddings) with row counts matching the source splits.

7. **Run history is intact and explains the state.** `%TEMP%\opencode\rebuild_caches.log` records 3
   starts (10-11 22:24:53, 22:25:13; 10-12 04:33:01) and 2 FATALs:
   - 22:24:57 `TypeError: tuple indices must be integers` at `d["outdir"]` (pre-fix line 285), before
     any artifact was written;
   - 22:38:26 `TypeError: TextEncodeInput must be Union[...]` in the tokenizer, caused by NaN text
     in the freshly written Italian CSVs, after the 4 Italian CSVs but before their embeddings.
   The 04:33 resume cache-hit the Italian CSVs and re-embedded them with the current coercion fix;
   `status.json` (pid 29528) reports 32 artifacts in 1,052 s, all 24 translated NPYs plus the 8
   non-Italian CSVs. The 4 Italian CSVs and the 12 source embeddings came from the earlier run.

8. **Coverage of E4 is confirmed empirically.** E4's protocol (train on English, apply to translated
   it/de/fr) is executable with these files. A light re-run (XGBoost 200 trees, depth 6, mean,
   threshold 0.5) gives SST-2 0.775 / 0.576 / 0.608 / 0.622 and emotion 0.367 / 0.169 / 0.114 /
   0.184 (EN / it / de / fr), within 0.02 of every E4 entry cell (0.792 / 0.596 / 0.593 / 0.636 and
   0.370 / 0.170 / 0.118 / 0.174). The translated artifacts are the E4 data.

9. **No cache is stale by timestamp.** Source `sst2.csv` / `emotion.csv` mtime 2026-10-11 20:37:53;
   all 12 CSVs 22:34-04:47; all 24 NPYs 04:33-04:50 the next morning, i.e. every embedding is newer
   than its CSV and both are newer than the source data.

   checksum level.

## Bugs / risks

1. **Cache-hit path ignores shape and provenance** (`cached_npy` lines 122-135; `embed_cached`
   lines 217-220). Any finite 2-D array is accepted, and `embed_cached` returns it without comparing
   `arr.shape[0]` to `len(texts)`. A stale or truncated NPY with the wrong number of rows is used
   silently, producing mismatched X/y downstream instead of an error.
2. **CSV cache validation is row-count-only** (`csv_is_complete` lines 138-151): it checks the row
   count and the presence of `text`/`label`, not label values, order, or non-empty text. A CSV from
   a different model or an older dataset version with the same row count would be reused as-is.
3. **NaN translation text is silently converted into a signal-free embedding** (`_coerce_texts`
   lines 164-180; read at line 347). Five Italian rows (2 val, 3 test) contain an empty field; their
   cached vectors are identical to the embedding of the empty string (norm 120.04, cosine 1.0).
   `cached_npy` accepts them because they are finite. These rows are included in E4.
4. **Cache identity is the path plus row count, nothing else.** There is no hash of the texts, no
   model id/revision, no `MT_BATCH`, dtype or beam setting in the key. Changing `MT_BATCH` changes
   the 5 degenerate decodes (demonstrated), yet a rerun would still "cache hit" the old CSVs.
5. **NPY writes are not atomic** (`np.save` straight to the final path, line 156), unlike the CSV
   path which uses `tmp` + `os.replace` (lines 260-262). A kill during save can leave a partial file.
6. **Silent CPU fallback** (line 280) logs a warning and continues; on CPU the same job takes hours,
   and fp32-vs-fp16 numerics can change the degenerate decodes.
7. **No artifact-level provenance.** Model ids, HF revisions, decode settings, date and row counts
   live only in `%TEMP%\opencode\rebuild_caches.{log,status.json}`. Temp cleanup destroys them, and
   `status.json` lists only the last run's 32 artifacts, not the 48 that exist.
8. **HF models are not revision-pinned** (`from_pretrained(MODEL_ID)`, no `revision=`). Audit-time
   cache refs: EuroBERT-210m `39b51e15dd1f1a06f58b5cbf6a8a188cec60bd0e`, opus-mt-en-it
   `be5a254d936f1a8c8da080406ca582a6615e6658`, en-de `6183067f769a302e3861815543b9f312c71b0ca4`,
   en-fr `dd7f6540a7a48a7f4db59e5c0b9c42c8eea67f18`. `models_registry.json` covers experiment runs,
   not these snapshots.
9. **All artifacts are git-ignored** (`.gitignore` lines 69-70; `*.npy` line 11). `git ls-files
   translated translated_emb` is empty, so the 314 MB are restorable only by a ~18 min GPU rebuild.
   This is by design (REPORT.md line 95) but means the 2026-10-11 loss can recur.
10. **MT quality is a latent confound for E4.** Greedy base Marian produces literal, ungrammatical
    German/Italian on already-degraded sources (the emotion text is lowercase with apostrophes
    stripped), and SST-2 files carry 19-33 duplicate target rows versus 2 in English (translation
    collapse). The emotion transfer collapse (0.37 -> 0.11-0.18) cannot be attributed to language
    geometry alone without a stronger-MT control.
11. **Silent truncation at 512 MT tokens** (line 243). Not triggered on this data (max 70 MT tokens
    over val+test), so it is a latent, not an active, risk.
12. **Pandas NA-string round-trip risk** in `pd.read_csv(csv)` (line 144) and the default reader:
    a translation literally equal to "NA"/"null" would read as NaN. Checked all 5 blank fields;
    they are literal empty fields written by `to_csv`, not NA tokens, so no current impact.
