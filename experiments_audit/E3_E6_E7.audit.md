## Bugs / risks

1. **Unreproducible result presented as completed research.** Anyone reading Part C can quote
   0.234→0.334 / 0.246→0.356 as a finding. There is no code, artifact, seed, split, or
   denominator to audit. This is the highest-risk item.

2. **`.gitignore` hides several artifact classes.** `*.npz`, `*.log`, `*.pid`,
   `*_status.json`, `xgboost_flores_*.json`, `shap_flores_*.json`, and `*.smoke` are ignored.
   If E3 artifacts had been produced as `*.npz`/logs, they would not have been tracked. That
   does not explain the absence of a JSON/MD table (those would normally be trackable), but it
   does mean provenance by pattern is unreliable.

3. **Destructive-cleanup history.** `EXPERIMENTS.md:384-385` records: "a buggy cleanup deleted
   all files under `multi/`; tracked files restored from git, embeddings rebuilt, this log
   rewritten." Git can prove the scripts were never tracked; it cannot prove they never existed
   as untracked local files. Any such file is unrecoverable.

4. **No output contract.** Unlike E18, the entry names no JSON/MD/PNG and no command. A future
   auditor cannot know what the intended artifact was, so "missing artifact" is not even
   falsifiable beyond the absence of any `crosslingual*` file.

5. **No recovery path in git.** There are only three dangling blobs and all are unrelated;
   `git log --all --diff-filter=D --name-status` shows only `pertopic_accuracy.py` and
   `pertopic_accuracy_transfer.py` were ever deleted. There is no deleted `crosslingual*` blob
   to restore.

6. **`zero90` cannot be reimplemented faithfully.** A reimplementation would have to guess the
   dim-selection statistic (η²? PC? centroid rank?), the fraction, and whether it was applied
   before or after INLP. Any new number would be a new method, not a reproduction.

7. **Missing basis file blocks surrogate reconstruction.** `lang_inlp_agg.npz` is absent and
   gitignored, so the exact agg INLP directions used by `agg_pr_2models` cannot be recovered.
   The surviving `dim_removal` INLP basis is refit with k=5, not the claimed ~30 directions.

8. **`agg_pr_2models.py` is not a usable surrogate.** It imports the missing `agg_pr_methods`
   (and mentions missing `agg_pr_lang.py`), so it cannot be run from a clean checkout;
   `COVERAGE.md:88` already flags this. Its outputs (`agg_pr2.*`) are precision/recall-vs-
   threshold with Optuna, not the E3/E6/E7 raw-vs-neutralized macro-F1 table.

9. **No per-language rows, seed, CI, or EN-self.** Even if a script were found, the entry's
   format would not support a 0.975 check or an uncertainty statement. The claim is a point
   estimate with no spread.

10. **Risk of silently mixing label versions.** The FLORES labels were collapsed/merged in
    earlier commits (`196bbd3`, `b02f8b4`, `00d4823`, etc.). A 2026-10-12 "12-class" claim may
    refer to a different label mapping than the current `train_flores12` files; the entry does
    not pin a data commit or label scheme.

## Recommended changes

1. **Change the status of E3/E6/E7 from `DONE` to `UNVERIFIED (UNK)`** in `EXPERIMENTS.md`,
   with a footnote: "No script or artifact was ever tracked; the numbers are a 2026-10-12
   narrative record and have not been reproduced." Do not use the `(verified)` marker.

2. **Quarantine the four numbers.** Either remove them or move them to a clearly labelled
   "legacy/unverified" block. Do not include them in the master result, the 0.975 comparison,
   or any table that mixes them with E14/E18.

3. **If a numeric replacement is required, run a new, explicitly named experiment.** Use
   `flores_close.py` raw/`inlp` (or `dim_removal.py` fixed-k INLP) on sent+agg, report
   **macro-F1 mean over it/de/fr plus EN-self**, and store a new JSON/MD. Label it e.g. `E3r`,
   not E3, and state that it is a reimplementation with a different protocol. Do not claim it
   reproduces the old numbers.

4. **Pin the protocol in any replacement:** backbone, embedding precision, train/val/test
   indices, label-collapse commit, XGB params, seed, threshold policy, INLP rounds/rank, and
   whether INLP is fitted on train or train+val. The surviving scripts differ on all of these.

5. **Add an entry-level provenance check.** A small test or CI script should fail when a
   documented script/artifact name does not exist. At minimum, `REPRODUCE.md` should not imply
   E3/E6/E7 is reproducible (it currently does not list it, which is correct).

6. **Fix or quarantine `agg_pr_2models.py`.** Either restore `agg_pr_methods.py` /
   `agg_pr_lang.py` and `lang_inlp_agg.npz`, or mark the script non-runnable in
   `REPORT.md`/`REPRODUCE.md` and stop citing it as the E3 INLP provenance.

7. **Recover or regenerate `lang_inlp_agg.npz`** if any downstream analysis still needs it;
   record the basis rank, fit rows, and a hash in the JSON. Do not rely on a gitignored binary
   as the only provenance.

8. **Remove ambiguity around `zero90`.** If the method matters, define it in code and docs
   (statistic, fraction, fit split, order relative to INLP). If it cannot be defined, drop the
   name from the table rather than leave a non-reproducible label.

9. **State the 0.975 bar as N/A in the entry** (as done in the rewritten E18-style text) and,
   for any future rerun, store both the absolute score and the English-self denominator.

10. **Update cross-references.** `COVERAGE.md:48,147-148` already flags the missing scripts;
    keep that as the authoritative status and make `EXPERIMENTS.md` agree. Optionally add a
    "legacy/unverified" note under the E3 heading so the two documents cannot drift again.
