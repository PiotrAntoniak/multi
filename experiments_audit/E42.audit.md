**Scope.** `en_vs_enit_raw.py`, `en_vs_enit_raw.{json,md,png}`, `en_vs_enit_raw.ab_premerge.json`,

**Verdict.** Numbers are internally consistent, recompute exactly from the stored JSON, and every
merge is guarded so earlier numbers cannot move (A/B/C verified bit-identical through both later
merges). A/B still reads **0.9414, FAIL at 0.975**; with C, EN-only retention against the

## Discrepancies / notes

1. **The arms are tuned on different languages (real asymmetry, spec-mandated).** A selects
   hyperparameters on **EN val**, B on **IT val**. B's selection therefore targets the same
   language it is tested on, A's does not. Direction of bias: B is helped, A is not, so
   **A/B = 0.9414 understates** raw-feature retention. A clean isolation of the training-language
   effect would tune A on IT val as well (an extra arm, not in this spec).
2. **"A/B ratio" is read literally as A(IT)/B(IT).** The complementary reading B/A = 1.0622
   trivially clears 0.975 and carries no information about transfer; both are stored so the
   interpretation is not hidden behind one number.
3. **Validation AUC is not comparable across arms.** A's 0.8881 is on EN val, B's 0.8572 on IT
   val; B scoring lower does not mean B is a worse model — its IT test AUC (0.8370) is 4.9 pp
   above A's (0.7880).
4. **Selection noise is non-trivial.** A's 10 trials span 0.8552–0.8881 (3.3 pp), B's span
   0.8362–0.8572 (2.1 pp), on 504-row validation sets. The reported best-params models are
   therefore optimistic on val by ~1–2 pp, but test AUC is untouched by that optimism.
5. **The AUC verdict is metric-specific.** Same models, argmax metrics: accuracy ratio
   A/B = 0.7548, macro-F1 ratio A/B = 0.4665. AUC parity at 0.9414 coexists with macro-F1 at 47%
   of the in-language model — ranking transfers, calibrated decisions do not. Any claim built on
   AUC alone overstates practical transfer.
6. **Cross-reference to E18.** E18's `sent`/`raw` EN->IT AUC was 0.759 with a *fixed* param set
   and its 0.886 ratio used EN-self (0.856) as the denominator. E42's 0.7880 / 0.9414 comes from
   tuned params and a different denominator (in-language IT), so the two are not comparable
   numbers; only the direction (below 0.975) agrees.
7. **Test precision.** 505 rows, ~0.01–0.02 AUC standard error; the 0.029 A–B gap is ~2 SE.
   The FAIL verdict at 0.975 has a wide margin (3.4 pp of ratio), so it is robust to that noise;
   the exact value 0.9414 is not.
8. **Minor.** scipy emits a `NumPy < 2.5` compatibility warning on import (NumPy 2.5.4
   installed); it is benign and does not affect fits.

### Discrepancies / notes (arm D)

M-6. **MT quality is a ceiling, not a floor.** opus-mt-en-it output is not human translation; a

M-7. **The translate-train hypothesis is supported only in the weak form** ("equal value per row");

### Discrepancies / notes (D_clean)

N-1. **The premise that D's Optuna objective was in-sample is false for this implementation.**
    `add_b_en_and_d` tunes D on the **1994-row** train-only matrix (`Xd_tr`) and scores real IT val;
    the 3002-row matrix is used only for the reported refit (D5, M-4). E3 proves it: a fresh study

    have been near 1.0 (as D's `it_val_in_sample` = 0.9774 shows) and E's trials would not match.
N-2. **"Inflated" is the right word, but the mechanism is row count, not leakage.** D's 0.8860 is a

    comparable to 1994-row B or 997-row C. The marginal value is +4.42 pp for +1008 rows.
N-3. **E is numerically identical to D′, so the clean arm adds proof rather than a new point.**
    Anyone wanting an independent number should change `SEED` in `en_vs_enit_dclean.py`; expecting a

N-4. **E/B is the row-matched MT test; E/C is not.** Both E and B train on 1994 rows and differ only
    in whether the second half is real or MT Italian, so **E/B = 1.0057** is the clean
    "MT ≈ real per row" result. C has 997 rows, so E/C = 0.9994 despite double the rows means the
    extra English half does not lift the Italian ceiling — do not read it as MT outperforming real
    Italian.
N-5. **E/A_EN = 1.0101 is not evidence that translate-train improves English.** E trains on twice as
    many rows as A (1994 vs 997); the +1% is inside the noise band and partly row count. The
    defensible claim is "no English cost".
N-6. **Single seed, single test split.** E/B = 1.0057 and E/C = 0.9994 are 0.6% and 0.06% effects on
    505 rows; they are parity results, not demonstrations of an advantage.

### Discrepancies / notes (arm F)

G-1. **The AUC win is not statistically established.** F/E = 1.0227 is +1.9 pp on 505 rows, roughly
    1-2 standard errors. The defensible statement is "translate-test ties or narrowly leads on
    ranking, and clearly leads on macro-F1 (+20% relative)". Any summary that says "translate-test
    beats translate-train on AUC" without the margin overstates it.
G-2. **F and E see different test strings.** Same 505 documents, but F's input is MT English while
    E's is human Italian. That is the strategy difference, not an artifact; it also means F's errors
    include MT artifacts, and a better/worse it->en system would move F accordingly.
G-3. **F wins with half the training rows** (997 vs E's 1994), which strengthens rather than weakens
    the result.
G-4. **E23 cross-check is consistent but not identical.** E23's translate-test used this same cache
    with 1501 train+val rows and fixed params and scored 0.8969; F scores 0.8609 with 997 tuned
    rows. The +504 rows in E23 are worth ~3.6 pp, the same order as D's +1008 rows (+4.4 pp).
G-5. **The operational cost is not in any metric.** F needs MT per test item (505 here, and per new
    item forever); E needs MT once over 997 training items and none at serving. The 7.3 pp macro-F1
    edge has to buy that.
