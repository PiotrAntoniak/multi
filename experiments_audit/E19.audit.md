# E19 audit — calibration & ceiling feasibility

**Scope.** `EXPERIMENTS.md:261-270` (E19 section), `flores_calib.py`, `flores_ceiling.py`,
`flores_calib.{json,md}`, `flores_ceiling.{json,md}`. Read-only audit: no repo file was changed,
no model was trained. Derived numbers were recomputed from the stored JSONs.

**Verdict.** The E19 numbers are internally consistent and round correctly, but the section is
**stale at its 0.9 bar** (the repo standard is 0.975, `E18.md:44`), its denominator is undocumented,
and its headline finding ("ceiling/label-noise bound, not transfer") is contradicted by the
ceiling's own ratios. At 0.975 the three listed rows remain infeasible with 2.9-11.4x larger margins.
Reproduction status: **PARTIAL** — the derivation reproduces exactly from the stored JSONs, but
the end-to-end runs were not re-executed and no full `flores_calib` run log exists.

## Verified

1. **Metric is what the section says.** `flores_calib.metrics()` (`flores_calib.py:133-149`) takes
   `L.argmax(1)` and computes `f1_score(..., average="micro"|"macro", labels=0..C-1)`. The ceiling
   calls the same function (`flores_ceiling.py:163`). This is single-label argmax F1.
2. **For single-label multiclass, micro-F1 == accuracy.** Checked all 40 `per_lang` method cells
   (2 datasets x 4 languages x 5 methods) and all 8 ceiling cells: zero mismatches. `acc` and
   `micro_f1` are bit-identical in `flores_calib.json` and `flores_ceiling.json`.
3. **English-self values are exact.**
   - Train+val (ceiling protocol): sent **0.6059** micro / **0.4865** macro / 0.9038 AUC;
     agg **0.6187** / **0.5573** / 0.9142.
   - Train-only (calib ratio denominator): sent **0.5366** / **0.4032** / 0.8486;
     agg **0.5540** / **0.5014** / 0.8882.
   - These match `flores_ceiling.json` -> `analysis.*.en_self` and
     `flores_calib.json` -> `datasets.*.summary.en_baseline` exactly (1e-12).
4. **The ceiling is target-language, trained on the same rows.** `flores_ceiling.py:149-161` builds
   `trva = concatenate([train_idx, val_idx])` once and trains each language's own XGBoost on
   `Xt[lg][trva]`, then predicts `Xt[lg][te]`. FLORES rows are parallel at identical indices, so
   en/it/de/fr share row identity and labels. Sizes confirm it: sent 997+504 = 1501, test 505;
   agg 276+140 = 416, test 139 (`flores_ceiling.json` -> `datasets.*.sizes`).
5. **The denominator is correctly computed.** `summarize()` (`flores_calib.py:335-352`) divides by
   `per_lang["en"]["baseline"]` for every method, not by each method's own EN score. Stored ratios
   recompute exactly. The fixed-reference choice is documented in the MD (`flores_calib.md:20`).
6. **Calibrations are label-free.** EN val (504 / 140 rows) fits the temperature and quantile
   thresholds; `prior_sinkhorn`/`quantile_hardprior` use target softmax/argmax marginals only;
   `bbse` uses the EN-val confusion matrix and the target predicted rate. No target labels are read
   (`flores_calib.py:155-267, 294-329`). Temperature is one global value per dataset (1.2487 sent,
   1.0874 agg) applied to all languages, so it is consistent.
7. **AUC invariance is real.** Per language, all five methods store one unique AUC value
   (`flores_calib.json`, checked to 1e-12). Per-class offsets are monotone per class, so OVR AUC
   cannot move.
8. **`flores_ceiling.json` cites the current `flores_calib.json` exactly.** `best_method`,
   `best_min_ratio_both`, `en_baseline_self` and every `en_trained_calibrated_target` cell match
   the calib JSON at 1e-12 (sent `quantile_hardprior`, agg `prior_sinkhorn`). No stale-copy
   mismatch.
9. **The three E19 rows match the JSON at the stated rounding.**
   - sent/de: 0.9 x 0.6059406 = 0.54535 -> **0.545**; ceiling **0.5366** -> 0.537. Correct.
   - sent/it macro: 0.9 x 0.4864631 = 0.43782 -> **0.438**; ceiling **0.4343**. Correct.
   - agg/fr: 0.9 x 0.6187050 = 0.55683 -> **0.557**; ceiling **0.5324** -> 0.532. Correct.
   - All three are infeasible at 0.9: margins +0.0087, +0.0035, +0.0245.
10. **JSON -> MD rendering is consistent.** Spot-checked every table cell in
    `flores_calib.md` and `flores_ceiling.md` against the JSON; `%.4f`/`%.3f` formatting only.
11. **Run provenance for the ceiling exists.** `%TEMP%\opencode\flores_ceiling\flores_ceiling.log`
    shows the full run (114 s) and reproduces every stored ceiling value exactly; status
    `phase=done`, PID 8324.

## Discrepancies

1. **Wrong feasibility bar in the section.** E19 uses **0.9**; the repo's comparability bar is
   **0.975** (`E18.md:44`, and E18's own verdict is stated at 0.975). Consequences at 0.975:
   - sent: all six cells infeasible (was 3/6 at 0.9).
   - agg: three cells infeasible — de macro (+0.0111), fr micro (+0.0709), fr macro (+0.0892);
     it (both) and de micro are feasible (was 2/6 at 0.9).
   Every cell infeasible at 0.9 remains infeasible at 0.975; four new cells join it.
2. **The three listed rows are more infeasible at 0.975** (verified against stored English-self):
   | row | 0.975 bar | ceiling | margin @0.975 | margin @0.9 | growth |
   |---|---:|---:|---:|---:|---:|
   | sent de micro | 0.5908 | 0.5366 | **+0.0542** | +0.0087 | 6.2x |
   | sent it macro | 0.4743 | 0.4343 | **+0.0400** | +0.0035 | 11.4x |
   | agg fr micro | 0.6032 | 0.5324 | **+0.0709** | +0.0245 | 2.9x |
3. **The English-self denominator is not named, and the choice flips verdicts.** The section's
   0.545/0.438/0.557 are 0.9 x the **train+val** self, while `flores_calib`'s own ratios divide by
   the **train-only** self. At 0.975 with the train-only self, sent is 0/6 infeasible (all
   "feasible in principle"); with train+val it is 6/6. `flores_ceiling.md:35-37` prints both
   verdicts back to back for the same cell ("INFEASIBLE on macro only ... feasible in principle"),
   which reads as a contradiction unless the reader knows two different EN models are in play.
4. **The headline finding is not supported by the ceiling numbers.** The E19 text says the residual
   is "ceiling/label-noise bound, not transfer". But calibrated transfer / target ceiling is only
   **0.71-0.81 micro** and **0.66-0.74 macro** on sent, and **0.81-1.03 micro** / **0.63-1.01
   macro** on agg (best per metric), i.e. a large transfer gap remains *below* the ceiling. On
   agg-fr the transfer **beats** the in-language model (1.027 micro, 1.010 macro with the
   per-metric best), which also proves the "ceiling" is not an upper bound. Infeasibility of the
   0.9/0.975 *bar* does not explain the observed gap.
5. **One calibration method is applied to both metrics in the ceiling ratios.**
   `ratio_calibrated_over_ceiling` (`flores_ceiling.py:202-206`) uses `best_method`, chosen by
   `min_ratio_both` (`flores_calib.py:360`), for micro *and* macro. Per-metric best differs, and
   the table understates micro: sent-de 0.731 used vs **0.808** best (baseline); sent-it 0.708 vs
   **0.736**; sent-fr 0.721 vs **0.748**; agg-de 0.845 vs **0.857**; agg-de macro 0.688 vs
   **0.820**; agg-fr macro 0.907 vs **1.010**. The ceiling docstring says "best label-free
   calibration"; the code does not implement per-metric best.
6. **The E19 table mixes metrics without labelling them.** The de and fr rows are micro-F1; the it
   row is macro-F1 (only it is labelled "(macro)"). The header "target's own ceiling" does not say
   which metric. The row selection is undocumented, and de is infeasible on **both** metrics while
   the table shows only micro.
7. **`flores_calib.md:3` and `flores_calib.py:6-7` still state 0.9.** The code's summary flags are
   named `best_reaches_0_9_*` (`flores_calib.py:369-375`). This is not a numerical bug, but it
   propagates the stale bar into the rendered artifacts.

## Bugs / risks

1. **The ceiling is untuned while the transfer is tuned.** The ceiling is plain `argmax`
   (`flores_ceiling.py:163` -> `metrics`). The transfer uses EN-val-tuned thresholds and prior
   matching. Because the ceiling merges val into train, no target val is left for threshold
   tuning. The ceiling is therefore biased **downward**, which biases the test toward INFEASIBLE.
2. **The ceiling trains on 50% more rows than the transfer model** (1501 vs 997; 416 vs 276) while
   feature z-stats come from **train only** (`flores_ceiling.py:149`). The bar and the ceiling are
   internally consistent with each other (both train+val), but the transfer/ceiling ratio compares
   different training budgets, and val rows are standardized with train statistics.
3. **The "ceiling" is not a ceiling.** agg-fr transfer/ceiling = 1.027 micro. Single seed, small
   test sets, and a fixed untuned XGBoost mean the per-language model is not a strict upper bound.
4. **Statistical power is not reported.** n = 505 (sent) / 139 (agg). Binomial SE of micro-F1
   (== accuracy) is about **0.022** (sent) and **0.042** (agg). At 0.9, the margins are
   +0.0087/+0.0035/+0.0245 = 0.4/0.2/1.1 SE — not distinguishable from zero. At 0.975, sent-de
   (+0.054) and agg-fr (+0.071) are the only margins near 2 SE. Macro-F1 is worse: sent test class 0
   has **4 rows** and class 8 has **8**; agg has four classes with 4-5 rows. Macro-F1 over 12/11
   classes is extremely noisy, so the macro-based verdict rows (sent-it, agg-de) are the weakest.
5. **No per-row predictions anywhere.** The JSONs store aggregate metrics and `pred_dist` only.
   A paired test (McNemar) on the same parallel test rows — the correct test here — cannot be run
   from stored artifacts.
6. **"Create-only" is false in both scripts.** `flores_calib.py:531-534` and
   `flores_ceiling.py:376-379` open outputs with `"w"`. A rerun silently destroys the stored
   numbers. There is no resume logic despite the wording.
7. **Non-atomic calib JSON + ceiling reads it.** `flores_calib.py:531` writes the JSON directly;
   `flores_ceiling.py:118-120` loads it at start. Running the two concurrently can make the ceiling
   read a truncated file. Run order must be sequential, and the calib write should use
   `tmp + os.replace` (as the status writer already does, `flores_ceiling.py:97-100`).
8. **Bar is hardcoded.** `THRESH = 0.9` (`flores_ceiling.py:78`) and the 0.9 constants in
   `summarize` (`flores_calib.py:369-375`) cannot be changed without editing code. The stored JSON
   therefore cannot answer a 0.975 question; the 0.975 table above was recomputed externally.
9. **Environment risk.** `python 3.13.5`, numpy **2.5.4**, sklearn 1.6.1, xgboost 3.2.0. Importing
   xgboost emits `A NumPy version >=1.23.5 and <2.5.0 is required for this version of SciPy
   (detected version: 2.5.4)`. It is a warning today and does not change these numbers, but the
   environment is not pinned.
10. **`--launch` is fragile.** `flores_ceiling.py:326-327` builds an unquoted command string. It
    works only because `C:\Users\pedro\anaconda3\python.exe` and the repo path contain no spaces.
11. **`bbse` is unstable on both datasets** (cond 18.6 / 45.8, negative `p_hat` entries, degrades
    EN to 0.487 / 0.165). It is correctly reported as unstable and is never selected, so it does
    not affect the verdict. No action needed beyond keeping the warning.
12. **`perlang_z` uses unlabeled target train rows.** The section does not say this. "ONE English
    model" is true for the classifier but not for the feature pipeline (target-language mean/std
    are used).

## Missing scripts / artifacts

1. **No analysis-only / render-only path.** E18 has `--render`; E19 has neither, so a bar change
   requires a full retrain. A `--thresh` + "recompute analysis from JSON" mode is missing.
2. **No full `flores_calib` run log or status file.** Only
   `%TEMP%\opencode\flores_calib\flores_calib_smoke.*` exists. The full calib JSON has no log/PID
   provenance, unlike the ceiling run.
3. **No per-row predictions / scores** (`pred`, `prob`, ids) in either JSON.
4. **No seed repeats or confidence intervals.** Single seed 0 everywhere.
5. **No true ceiling with held-out target val.** The current artifact cannot separate
   representation/label noise from the untuned-argmax penalty.
6. **No 0.975 artifacts.** `flores_ceiling.json` stores only `feasibility_0.9` and
   `config.threshold = 0.9`.

   single-method and per-metric numbers.
5. **Drop "label-noise bound".** Rename the artifact "in-language same-protocol model". If a true
   ceiling is wanted, hold out target val (train on train only) and tune the same label-free
   calibration; add an inter-annotator / label-agreement estimate for the noise claim.
6. **Add uncertainty.** Bootstrap or McNemar on stored per-row predictions; report n and SE next to
   every margin. Save `pred` arrays and test ids.
7. **Fix output semantics.** Honor "create-only" or state clearly that outputs are overwritten;
   write JSON atomically; add a calib full-run log/status like the ceiling run.
8. **Label metrics in the section table** (micro vs macro per row) or use the full 6-cell grid.
9. **Pin the environment** (numpy < 2.5 for the current xgboost/scipy combination) in
   `REPRODUCE.md`.
