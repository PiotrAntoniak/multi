## Discrepancies

### Coverage: 20 of 48 cells are reported

`EXPERIMENTS.md:239-245` lists five dataset/backbone rows = 20 cells. The JSON/MD contain
48. The 28 omitted cells are:

| omitted group | XL macro-F1: mean / pc / inlp / D | EN self macro-F1: mean / pc / inlp / D |
|---|---|---|
| flores_sent / 210m | 0.199 / 0.207 / 0.206 / **0.209** | 0.375 / 0.378 / **0.386** / 0.375 |
| flores_agg / 210m | **0.294** / 0.282 / 0.292 / 0.293 | **0.493** / 0.457 / 0.492 / 0.493 |
| toxic / 210m | 0.470 / 0.450 / **0.482** / 0.447 | **0.770** / 0.750 / 0.767 / **0.770** |
| sst2 / 210m | n/a (EN-only) | 0.805 / **0.809** / 0.805 / 0.805 |
| sst2 / 610m | n/a (EN-only) | **0.765** / 0.762 / **0.765** / **0.765** |
| emotion / 210m | n/a (EN-only) | 0.365 / **0.374** / 0.365 / 0.365 |
| emotion / 610m | n/a (EN-only) | 0.358 / **0.399** / 0.358 / 0.358 |

The omission is not just "210m vs 610m": it also removes **sst2 and emotion entirely** (16
cells), which are EN-only and therefore not cross-lingual. The entry's title says "Backbone ×
dataset × method grid" but the table covers 4 of 6 datasets and 5 of 12 dataset/backbone
groups.

The omitted 210m rows materially change the finding:

- **flores_agg/210m:** no method beats raw mean (0.294); `pc` is 0.282. The entry's
  "help FLORES-sent" does not generalize to agg at 210m.
- **toxic/210m:** `inlp` is the best stored method (0.482 vs mean 0.470; +0.012), so
  "neutral/harmful for toxicity" is 610m-specific and even there `inlp` is within 0.006 of
  the best.
- **flores_sent/210m:** the best gain is +0.010 (D 0.209 vs mean 0.199), i.e. flat, not
  "helps".

### "inlp (~30-dir)" is wrong for three groups

`backbone_grid.md` labels every `inlp` cell "inlp (~30-dir)", but `inlp_dirs` is:

| dataset / backbone | `inlp_dirs` |
|---|---:|
| flores_sent/flores_agg/toxic, both backbones | 30 |
| mel / 610m | 30 |
| mel / 210m | **2** |
| sst2/emotion, both backbones | **0** (no-op) |

The `inlp` column therefore mixes a 30-direction projection, a 2-direction projection, and a
no-op. The entry does not disclose this.

### "10 Optuna trials" is true numerically, but not TPE tuning

`n_trials=10` is real, but `optuna.samplers.TPESampler` defaults to `n_startup_trials=10`.
With exactly 10 trials, all ten are startup random draws; TPE never proposes a trial. The
draw sequence is identical for every cell (same seed). Evidence:

- A synthetic `TPESampler(seed=0)` study with 10 trials produced the same 10 parameter sets.
- The JSON has only **4 distinct `best_params` sets across 48 cells**, with counts
  25/15/6/2. Each exactly matches one of those 10 startup draws:
  trial #1 (25 cells), #7 (15), #9 (6), #5 (2).
- Therefore the grid is a fixed 10-config random search, with the best config selected
  per cell from the same 10 configs. It is not "10 TPE trials" and it cannot adapt to the
  dataset/backbone/method.

This is the most important methodological discrepancy: the tuning claim is overstated.

### Entry reports only macro-F1; the method effects are much smaller in AUC

The entry's conclusion rests on macro-F1. AUC (in the JSON/MD) shows much smaller gains:

| cell | mean XL macro-F1 | best XL macro-F1 | mean XL AUC | best XL AUC |
|---|---:|---:|---:|---:|
| mel/210m | 0.059 | 0.299 | 0.807 | 0.866 |
| mel/610m | 0.115 | 0.349 | 0.839 | 0.881 |
| flores_sent/610m | 0.241 | 0.307 | 0.829 | 0.837 |
| flores_agg/610m | 0.302 | 0.340 | 0.885 | 0.891 |
| toxic/610m | 0.500 | 0.500 | 0.730 | 0.730 |

The mel gain is large in both, but flores_sent/610m (+0.066 macro-F1 vs +0.008 AUC) and
flores_agg/610m (+0.038 vs +0.006) are mostly calibration/threshold effects, not ranking
improvements. The entry does not say this.

## Bugs / risks

1. **Optuna startup bug (major).** `backbone_grid.py:656-658` creates
   `TPESampler(seed=SEED)` and calls `optimize(..., n_trials=10)`; it never sets
   `n_startup_trials`. With Optuna's default of 10, all trials are random. The md header
   (`backbone_grid.md:3`) and E28 repeat "10 Optuna TPE trials". Fix: set
   `n_startup_trials=3-5` and/or raise `n_trials` to 30+, and save the trial table.

2. **INLP is not reproducible (major).** Recomputing four inlp cells with the stored
   `best_params` and the current tree:

   | cell | stored EN / XL | recomputed EN / XL | ΔXL |
   |---|---|---:|---:|
   | flores_agg/210m/inlp | 0.4922 / 0.2916 | 0.4982 / 0.3135 | **+0.0219** |
   | flores_sent/210m/inlp | 0.3862 / 0.2057 | 0.3809 / 0.2164 | **+0.0108** |
   | flores_agg/610m/inlp | 0.4294 / 0.3015 | 0.4698 / 0.3063 | +0.0048 |
   | flores_sent/610m/inlp | 0.3911 / 0.3071 | 0.3854 / 0.3064 | -0.0007 |

   Mean/pc/D cells reproduce exactly (four checked). `_fit_inlp` is deterministic within
   one process (two runs gave a bit-identical 30×1152 basis), so the drift is
   environment/code-version dependent. The run did not record library versions or a code
   hash. NumPy was updated on **2026-10-14 08:52**, after the 13/10 run, and the current
   environment is NumPy 2.5.4; this is the likely cause (inferred, not proven). The INLP
   basis is not saved; only `inlp_dirs` is stored (`backbone_grid.py:710`). Consequence:
   the mel 610m `inlp` 0.349 vs `pc` 0.338, the mel 210m `inlp` 0.299 vs `D` 0.298, and the
   toxic 210m `inlp` 0.482 vs mean 0.470 are within the observed noise. The original E28
   table bolds `inlp` for mel/210m, mel/610m and flores_sent/610m; the full grid also makes
   it best for toxic/210m.

3. **mel target-label alignment is wrong but currently unused (latent bug).**
   `_load_mel` builds `Ytr`/`Yte` from `en_*.jsonl` and assigns `Ytr[tr_idx]` to every
   language (`backbone_grid.py:354-371`). Train rows are **not** parallel across languages:
   `multi_hot` matches only 169/11000 (en-de), 183/11000 (en-fr), 180/11000 (de-fr); test
   rows are parallel (5000/5000/5000). The current metrics use only
   `d["ytr"]["en"]`/`d["yva"]["en"]`, so the reported numbers are unaffected, but
   `ytr[de/fr]`, `yva[de/fr]`, and `Xva[de/fr]` (EN indices applied to target arrays) are
   misaligned. Any future target tuning/validation would silently use wrong labels.

4. **All non-mean methods are target-adaptive (confound).** `pc`/`inlp`/`D` are fitted on
   the stacked train pool, which includes unlabeled target train features. Only `mean` is
   target-free. The comparison therefore conflates "language-subspace removal" with
   "access to target-domain feature statistics". The evidence supports the latter more
   strongly: on mel, `D` (just a mean shift) reaches 0.298/0.329 vs the best 0.299/0.349;
   on flores_sent/210m, `D` is the best. E18's `perlang_center`/`perlang_z` are the relevant
   controls; E28 has no EN-only PCA/INLP control. The entry's "language-subspace methods"
   framing over-attributes the mechanism.

5. **No-op cells on EN-only datasets (minor).** `_fit_inlp` returns an empty basis when
   `len(langs) < 2` (`backbone_grid.py:454-455`); `D` has no targets (`:497-500`) and
   `apply_transform` returns EN unchanged (`:517-519`). So for sst2/emotion, `inlp` and `D`
   are exact duplicates of `mean` (same EN metrics; 8 of 48 cells). They are reported as
   distinct methods in the md, and the md labels inlp "~30-dir" even when `inlp_dirs=0`.
   They should be skipped or explicitly marked "not applicable".

6. **Fixed 0.5 threshold + prior shift (minor/moderate).** Binary and multilabel macro-F1
   use `pred = (S >= 0.5)` (`backbone_grid.py:617-636`); no target threshold tuning. Toxic
   target prevalence is 29.4-36.9% vs EN 12.1%, so a model trained on EN is systematically
   miscalibrated on targets. The XL mean is unweighted and target test sizes differ
   (de 1230, es 2919). This is a legitimate design choice for a fair comparison, but the
   entry should not read toxic macro-F1 as a pure transfer measure; AUC/PR-AUC are the
   threshold-free view.

7. **512-token truncation on "long-doc" mel (moderate).** `EMB_MAXLEN=512`
   (`backbone_grid.py:116`), and `_embed_mean` truncates (`:174-175`). MultiEURLEX documents
   are long; mean pooling sees only the first 512 tokens. The entry calls mel "long-doc"
   without this limit. This may understate what a full-document mean would do, and it makes
   the mel number not directly comparable to long-doc methods that use the full text.

8. **sst2/emotion duplicate leakage (minor).** `sst2.csv` has 61 exact texts in both train
   and test (58 train/val); `emotion.csv` has 11 train/test duplicates. sst2 is a 80/10/10
   re-split of the GLUE train+validation pool (68,221 rows; README confirms the re-split),
   so duplicates are inherited from the pool, not introduced by a bad split. These are
   EN-only cells, so E28's cross-lingual claims are unaffected, but they are still leakage
   in the EN-self numbers.

9. **Toxic cross-language near-duplicates are not removed (residual risk).**
   `clean_toxi.py:3-17` documents that the source (`FredZhang7/toxi-text-3M`) had exact-text
   train/test leakage; it pools all shipped splits and dedups per language. Verified: 0
   exact-text overlap train/test, val/test, and 0 duplicate train texts per language.
   However, dedup is **per language**, so a comment translated into EN and IT can remain in
   different splits. The source is a translation dataset, so this is a plausible residual
   leak. A sampled cross-lingual nearest-neighbour check (210m toxic embeddings, 800 IT test
   vs 5000 EN train) found 12/800 pairs > 0.95 cosine, but the top pairs were short generic
   phrases ("Impressive" vs "great news"), so the check is inconclusive; do not claim
   leakage, but do not claim it is impossible either. This is an **unresolved risk**, not a
   confirmed bug.

10. **Checkpoint reuse is unversioned (moderate).** `run_cell_task` returns any existing
    cell JSON without validating the config, data hash, or code version
    (`backbone_grid.py:665-672`). The current 48 checkpoints match the artifact, but a future
    edit to methods/data would silently mix old cells into a new table. There is no
    `--render` mode, so rebuilding md/png currently requires a full run or manual code.

11. **JSON contains bare NaN (minor).** `xl_mean` for sst2/emotion is serialized as `NaN`
    (`backbone_grid.py:141`, `write_outputs`); Python's `json` accepts it, strict JSON
    parsers do not. Use `null` or omit XL for EN-only cells.

12. **`toxi_pr_610.png` is a separate experiment (minor).** It is produced by
    `build_toxi_pr_610` with a fixed XGBoost config and per-language z-scoring
    (`backbone_grid.py:760-865`), not the grid's tuned per-cell models. Do not compare its
    curves numerically to the toxic grid cells. It is also not mentioned in the E28 entry.

13. **210m embedding provenance gap (minor).** The logged run says
    `embeddings[210m]: nothing to build`; the 210m arrays were created 2026-10-12
    18:54-19:09 by a preceding process, and that process's log is not retained. The arrays
    match the committed 210m caches (cosine ~0.998-0.9997), so they are almost certainly the
    same mean-pooled 210m features, but the run does not prove it. 610m is fully logged.

14. **Global warning suppression (minor).** `backbone_grid.py:64-69` ignores all warnings,
    including `ConvergenceWarning`. `_fit_inlp` does not check `n_iter_`; in the current
    data the probe converges (n_iter_ = 2/8/13 for three checked stacks), so this is not an
    active failure, but it would hide a future non-convergence.

15. **Cosmetic / housekeeping.** `EMB_DTYPE = "bfloat16"` is unused (arrays are fp32);
    `backbone_grid.pid` remains in `%TEMP%` with PID 20712 after the finished run; the
    `backbone_grid.png` x-axis has blank sst2/emotion groups with no caption explaining
    them; the md's `subset_acc` table prints 48 rows with `n/a` for non-mel datasets.

## Recommended changes

**P0 — correctness of the claim**
1. Fix the tuning: set `n_startup_trials=3-5` and `n_trials>=30`, or keep 10 trials but
   relabel them as "10 fixed random configs". Save the Optuna trial CSV per cell and report
   the best trial number. Re-run the table before using "TPE" or per-cell tuning language.
2. Rewrite E28 with all 48 cells, or explicitly label the 5-row table as a 20-cell subset.
   At minimum add flores_sent/210m, flores_agg/210m, toxic/210m, and a note that sst2/emotion
   are EN-only. Change the finding to "target-adaptive transforms help mel; the effect is
   backbone/dataset-specific; toxicity is neutral/harmful at 610m".
3. Do not bold `inlp` when its gap over pc/D is < 0.02. Either stabilize INLP (save the
   basis, fix `tol`/solver, run 3 seeds) or report mean ± sd across seeds. Re-run the inlp
   cells under the current environment.

**P1 — scientific controls**
4. Add the target-free controls: PCA/INLP fit on EN only, and E18's `perlang_center` /
   `perlang_z` (unlabeled target stats) as a separate method. This separates
   "language-subspace removal" from "target-domain adaptation"; `D` already shows the
   latter is the main driver on mel.
5. Report AUC and (for toxic) PR-AUC alongside macro-F1; use a target-calibrated threshold
   or a threshold-free headline. Note the 0.5-threshold and prior-shift caveats in the
   entry.
6. Fix `_load_mel`: use EN labels only for EN; for target train/val, either load the target
   jsonl labels or explicitly set them to `None` and document that they are unused. Add an
   assertion that `Xva[lg]` is not used for non-EN.

**P2 — hygiene / reproducibility**
7. Skip or mark no-op methods on EN-only datasets; print `inlp_dirs` per cell in the md
   instead of "~30-dir".
8. Add a `--render` mode that rebuilds md/png from the JSON; add a config/code hash to each
   cell checkpoint and validate it on reuse.
9. Store `null` instead of NaN in the JSON.
10. Document the 512-token truncation and the mean-pooling definition in E28.
11. Deduplicate sst2/emotion across splits or note the 61/11 duplicates; consider the
    official GLUE test split for a clean EN-self number.
12. State the toxic cross-language near-duplicate risk; add source IDs or a
    translation-aware dedup if the dataset supports it.
13. Record versions (Python, NumPy, SciPy, scikit-learn, XGBoost, Optuna, transformers) and
    the git hash in `config`; rebuild the 210m embeddings in a logged run, or log their
    build separately.
14. Add 2-3 seeds / confidence intervals for the headline mel and flores_sent claims.
