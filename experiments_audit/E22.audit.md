## Verified

1. **Four BLEU rows, both systems.** Recomputed every cell from the six cached hypothesis files against
   the `en` column (sacrebleu 2.6.0, 13a tokenizer, default chrF):
   | cell | JSON | recomputed |
   |---|---:|---:|
   | bil it / de / fr | 29.7733 / 40.6498 / 42.0677 | identical to 4 dp |
   | mul it / de / fr | 23.1609 / 29.2159 / 31.7873 | identical to 4 dp |
   | bil macro | 37.4969 | 37.4969 |
   | mul macro | 28.0547 | 28.0547 |
   Absolute agreement, not approximate.

2. **Delta arithmetic.** Per-language Δ = mul - bil: it -6.6124, de -11.4338, fr -10.2804;
   macro -9.4422. Entry rounds these to -6.6 / -11.4 / -10.3 / -9.4 — correct rounding in every row.
   Macro means check out: bil (29.7733+40.6498+42.0677)/3 = 37.49693; mul 84.1641/3 = 28.05470.
   chrF: -7.8356 macro (JSON), matching per-language means.

3. **0.975 bar.** Multilingual/bilingual BLEU ratios: **it 0.7779, de 0.7187, fr 0.7556; macro
   0.7482 -> 0/3 pass** (chrF ratios 0.9001 / 0.8564 / 0.8806, macro 0.8784 -> also 0/3).
   This is a **quality ratio between two MT systems, not a target/English-model ratio** (there is no
   English-system denominator in this experiment). BLEU is not linear in quality, so ratio 0.72
   understates the loss; the raw -9.4 BLEU gap is the more honest headline.

4. **Models match the code and the JSON.** Bilingual = `opus-mt-it-en`/`-de-en`/`-fr-en`; multilingual
   = the single `opus-mt-mul-en`, reused for all three languages (json lines 10-21, py lines 62-71).
   Local configs: all four are Marian 6+6 layers, d_model 512; it-en 85.8M params vs mul-en 77.5M.
   `mul-en` (opus2m-2020-08-01) source inventory includes `ita`, `deu`, `fra`, target `eng`, no
   language tag — so it is a legitimate many→en stand-in, not an unsupported language pair.

5. **Full data subset, no sampling.** `N_ROWS = None` (py line 54), `subset: false`, `n_rows: 2006`
   (json lines 3-4). CSV is 2006 rows: 997 `dev` + 1009 `devtest`; `REPRODUCE.md` documents it as the
   2009-row FLORES file minus 3 deleted rows. 2006 unique English references, no duplicate `en` text.
   No row filtering, no length filter, no dedup at run time.

6. **Same test rows for both systems (paired).** Both families consume `df[lang]` in the same order
   (py lines 145-151) and the single `refs` list (line 140). Confirmed by re-deriving the cache keys:
   the six existing caches are keyed on the current columns' hashes (`it 2c4c8fb86b13`,
   `de f86b3fdd3fb4`, `fr 9f5722ab0da2`) for both the bilingual and `mul-en` files, 2006 lines each,
   zero empty hypotheses. Cache mtimes (20:05:36-20:07:57) bracket the JSON write (20:08:03).

7. **Decode config.** Greedy `num_beams=1`, fp16 on cuda, batch 64, max_length 512, `torch.set_num_threads(2)`
   (py lines 50-58, 98-111; json lines 5-9). Longest source is 71 words (it) -> no 512-token truncation,
   so both systems saw complete inputs.

8. **No cherry-picking detected.** All three target languages, all 2006 rows, both systems, one
   pre-declared configuration, and one reference per sentence. Nothing is selected post hoc from a
   larger grid. The entry's BLEU numbers are honest for this data.

## Discrepancies

1. **chrF is missing from the EXPERIMENTS.md entry** although `mt_compare.json`, `mt_compare.md` and the
   PNG all report it (json lines 26-64; md lines 10-17). The entry shows BLEU only, so the reader sees
   -9.4 BLEU but not the corroborating (and smaller, better-behaved) -7.84 chrF. Reporting gap, not a
   contradicted number.
2. **Entry omits n, decode config, model ids, and date.** E18-style entries state inputs and protocol;
   E22 states only "DONE" and a table, so the row count (2006, dev+devtest pooled) and greediness cannot
   be recovered from EXPERIMENTS.md alone.
3. **"Three bilingual models beat one many→en model"** is operationally true but reads as a controlled
   architectural comparison. What ran is 3 x 85.8M dedicated models vs 1 x 77.5M opus2m model with a
   much broader language mix. No size- or data-matched control exists.
4. **"detokenized default settings"** (py docstring line 26; md line 6) is inaccurate: sacrebleu does not
   detokenize; it 13a-tokenizes already-detokenized text. Cosmetic, but it is the only metric-setting
   statement in the entry.
5. **Macro chrF 64.4173 in JSON vs 64.4172 from unrounded per-language values.** The macro is the mean
   of already-4dp-rounded values (py lines 163-172), so it can differ by 1e-4 from the true mean. Not
   material; BLEU macro is unaffected at 4 dp.
6. **Entry's "macro" is an unweighted mean of per-language corpus BLEU**, not pooled corpus BLEU.
   Pooled values are 37.4706 vs 28.0267 (Δ -9.4439) — headline moves by 0.03 BLEU only.

## Bugs / risks

1. **Cache key ignores everything but model + text** (py lines 80-93): no decode config, device, dtype,
   sacrebleu version, or code revision. Changing `NUM_BEAMS`, `USE_FP16`, `MAX_LENGTH` or the GPU would
   silently reuse old hypotheses and produce a JSON that misdescribes them. No `--force`/`--no-cache`.
2. **`fp16` in the JSON is the constant, not the effective dtype** (py line 184; the half() cast is
   CUDA-only at lines 98-100). A CPU rerun would report `fp16: true` while running fp32 (or reusing
   fp16 GPU cache).
3. **Docstring says outputs are "(create-only)"** (line 30) but `open(..., "w")` overwrites
   `mt_compare.json`/`.md`/`.png` unconditionally (lines 197, 228, 275). Accidental destruction of the
   tracked artifacts is one command away; this audit avoided it for that reason.
4. **No CLI at all** — no `--limit`/`--smoke`, no `--langs`, no `--metrics-only`. A subset smoke test
   requires editing `N_ROWS`; a metric-only recheck requires either deleting caches or rewriting outputs.
5. **Macro computed from rounded values** (minor, see Discrepancy 5).
6. **Dead code:** `row()` (lines 232-234) is defined and never used.
7. **Silent failure masking:** `except Exception: pass` around `gpu_limit` (lines 129-132) hides a real
   import/limit failure; the run then proceeds without the GPU memory cap.
8. **Temp-only cache is volatile and untracked.** Temp cleanup or another machine forces 4 model
   downloads + full GPU decode; nothing in the repo records the hypotheses or a config hash.
9. **No run log/status/PID** is retained (`mt_compare.log`, `.pid`, `_status.json` do not exist), unlike
   other experiments in this repo, so the run is only reconstructable from cache mtimes.

   **chrF column**, and the **0.975 ratio row (0.778 / 0.719 / 0.756 -> 0/3)**, explicitly labelled a
   system-vs-system quality ratio.
2. Add a caveat sentence scoping the finding to 2020 opus2m bilingual vs mul-en, with the
   parameter/data-mix confound named.
3. Add `--limit`, `--force`, `--metrics-only` and `--langs`; include decode config + a code/config hash
   in the cache key; record effective dtype (and device) rather than the constant.
4. Either label macro as "unweighted mean of per-language corpus BLEU" or also emit pooled corpus BLEU;
   compute the macro from unrounded scores.
5. Correct the "(create-only)" docstring and the "detokenized" wording; drop the unused `row()` helper.
6. Add an E22 section to `REPRODUCE.md` with `python mt_compare.py`, the cache location and the warning
   that a rerun overwrites `mt_compare.{json,md,png}`.
