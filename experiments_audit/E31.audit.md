## Discrepancies

1. **`completed_datasets` says toxic is done; it is not.** `gen_compare.json` has
   `completed_datasets: ["flores","toxic"]`, but SmolLM2 toxic is skipped and the status file shows
   4,800/8,000. `EXPERIMENTS.md:317` says "toxic in progress", which is right; the JSON flag is
   wrong. A consumer that trusts `completed_datasets` will treat the toxic arm as complete.

2. **"hung" is the wrong reason.** `smol_toxic_gen.log` shows steady progress: 200 -> 4,800 rows
   over 7,105 s, throughput falling from ~4.2 to ~0.68-0.70 rows/s, with no error, no `[guard]`
   line, and no timeout. The process was slow and then stopped (dead PID), not hung. The reason
   recorded in the artifact (`hung (generation incomplete)`) is inaccurate.

3. **The script's defaults do not match the stored run.** `gen_compare.py:121,127,150` now default
   to `GEN_BATCH=16`, `START_BATCH=16`, `_COMPILE=True`; the JSON config records 8/8/False. The MD
   documents 8/False, so the MD describes the old run, not the current default. A from-scratch
   reproduction must pass `--start-batch 8 --no-compile`.

4. **`--gen-batch` is dead.** It is parsed (`:957-958`), assigned to `GEN_BATCH` (`:1025`), and
   echoed into the config (`:1068`), but `generate_italian` starts from `START_BATCH` (`:501`) and
   never reads `GEN_BATCH`. Passing `--gen-batch N` changes nothing except the recorded value.

5. **The 0.975 pass set is metric-specific.** On macro-F1 the ratios are 0.994 / 0.980 / 0.956; on
   AUC they are 0.978 / 0.965 / **0.998**; on accuracy they are 0.946 / 0.986 / 0.943. So
   Qwen3.5-0.8B passes macro-F1 but fails AUC, and Qwen3.5-2B fails macro-F1 but passes AUC. The
   E31 finding quotes only macro-F1 and does not say that the conclusion flips with the metric.

6. **The "Qwen3.5-2B is worse" claim does not survive as a general claim.** At the 0.975 bar the
   order holds (Qwen0.8 0.980 pass, Qwen2B 0.956 fail), but each ratio is against real_it, not
   2B vs 0.8B; the bar does not test the pairwise ranking. The macro-F1 gap is -0.0099 (0.3968 vs
   0.4067). A paired bootstrap over the 505 test rows (2,000 draws) gives a 95% CI of
   **[-0.0512, +0.0296]** and P(Qwen2B worse) = **0.69**. On AUC the difference is **+0.0290**
   with a 1,000-draw 95% CI **[+0.0108, +0.0467]** (P(worse) = 0.00) — Qwen2B is significantly
   *better*. On accuracy the gap is -0.0238, CI [-0.0574, +0.0079]. This is a ranking of point
   estimates, not a 0.975 ratio, and it is not robust. Qwen2B/Qwen0.8 macro-F1 is 0.976, close to
   0.975, but that is irrelevant to the ceiling bar.

7. **The pass/fail labels are themselves fragile.** Bootstrap P(ratio >= 0.975) over the same 505
   rows: SmolLM2 0.62 (95% CI 0.879-1.122), Qwen0.8 0.54 (0.890-1.079), Qwen2B 0.37
   (0.853-1.079). The 505-row test has a class with only 4 examples (class 0), which carries 1/12
   of macro-F1 and adds variance. The point labels reproduce, but "pass" is not statistically
   established.

8. **`EXPERIMENTS.md` overclaims.** "matching the FinePhrase family result" has no support in this
   experiment: E31 compares 3 small instruct LLMs, none of them FinePhrase; E30 used SmolLM3-3B.
   "replicating the paper's '≈1B saturates' claim" is not tested: there is one 0.8B vs 2B
   comparison, the macro-F1 gap is 1 pp and not significant, and AUC reverses it. Also "SmolLM2 is
   best" is true on macro-F1 only; among the three generators it is 2nd on accuracy (0.5248 vs
   0.5465 for Qwen0.8) and 2nd on AUC (0.8648 vs 0.8823 for Qwen2B).

9. **The toxic comparison has two confounds.** The real_it ceiling trains on **18,472** rows, the
   synthetic arms on **8,000**; and the label prior differs (EN train 11.66% positive, IT test
   29.35%). F1 is computed at a fixed 0.5 threshold (`:213-221,1250-1258`), so "32% of the
   ceiling" mixes prior shift, row-count advantage, and generation quality. AUC is less affected
   but still not size-matched.

10. **The toxic union is invisible in the report.** The JSON holds a 16,000-row union
    (F1 0.2170, AUC 0.6836), but `build_md` never renders `unions`; the MD reader cannot see it.
    E32 uses a different union table, so the two artifacts can be confused.

11. **No output filtering.** `_clean` (`:436-446`) removes think tags and four prefixes but keeps
    enclosing quotes and leading bullets. Counts on the stored FLORES caches: SmolLM2 1,367/1,501
    fully quoted; Qwen0.8 189/1,501 leading bullets; Qwen2B 403/1,501 quoted. On toxic: Qwen0.8
    3,585/8,000 leading bullets and 114 prompt-echo rows; Qwen2B 5,043/8,000 quoted and 146
    prompt-echo rows. Those rows inject label noise and are not reported.

12. **The MD throughput table is empty.** `gen_stats` is empty because every FLORES generation was
    a cache hit and the SmolLM2 toxic generation never completed, so `build_md` emits the header
    only (`gen_compare.md:12-16`; generator code `:730-756`). It is cosmetic but looks like a
    missing measurement.

13. **Stale PID file.** `gen_compare.pid` still contains 4156 (dead). `main()` writes the PID
    (`:1052-1053`) and never removes it. A cleanup job that trusts the PID file will target a dead
    or recycled PID.

## Bugs / risks

- **Overwrite, no merge.** `write_outputs` always rewrites `gen_compare.json/.md/.png`
  (`:882-892`). `main()` builds a fresh payload per invocation (`:1062-1079`) and adds only the
  datasets requested. Therefore `python gen_compare.py --datasets flores` silently deletes the
  stored toxic block; `--datasets toxic` deletes FLORES. There is no `--merge`.
- **Partial ≠ complete.** `payload["completed_datasets"].append(ds)` happens whenever the dataset
  loop finishes (`:1192-1200`), with no check that every generator produced a result. The toxic
  block was injected externally and marked complete.
- **No skip path.** The current code raises on a short generation (`:1155-1156`) and has no
  `try/except` around a per-generator failure in the dataset loop (`:1148-1161`), so one slow model
  aborts the whole run (the exact failure mode that left toxic incomplete).
- **Cache keys are too narrow.** Generation cache = generator + dataset + source texts
  (`:470-472`); synthetic-embedding cache = texts only (`:664-666`). Prompt template, decode
  settings, `max_new_tokens`, model revision, dtype and `max_len` are not hashed; changing any of
  them reuses stale data. The embedding key can also collide across generators if two generators
  emit identical text (not a correctness bug, just a shared vector).
- **Determinism is not guaranteed for generation.** Greedy decoding is deterministic in exact
  arithmetic, but bf16 CUDA kernels, `torch.compile` (`reduce-overhead`, dynamic shapes) and batch
  shape can change tokens. The run used cached text, so the comparative result is internally fair,
  but a rerun is not guaranteed bit-identical. No `torch.use_deterministic_algorithms`.
- **`torch.compile` default on, stored run off.** `_COMPILE=True` (`:150`) compiles every generator
  (`:335-344`) and `_BENCH_COMPILE=True` runs a 16-prompt eager-vs-compiled benchmark on the first
  uncached generation (`:497-499`). This is extra time and a source of variance; the stored run was
  `torch_compile=false`.
- **Toxic threshold and prior.** Fixed 0.5, no calibration. EN train prior 11.66% vs IT test 29.35%
  means the synthetic arms are systematically under-predicting positives; F1 is not comparable to
  the real_it ceiling.
- **Ceiling size mismatch.** `real_it` uses `X_it_tr` with 18,472 rows (`:928-936,1224-1236`),
  synthetic arms 8,000. A size-matched ceiling (subsample 8,000) would be the fair comparison.
- **`_wait_for_gpu` can block 2 h.** `_WAIT_GPU_MB=7000`, `_WAIT_GPU_SEC=7200` (`:147-148,225-245`).
  A cached FLORES run does not need the GPU, but the toxic path still loads the embedder if a cache
  is missing, and a busy GPU stalls.
- **No CI anywhere.** `mc_metrics` reports point estimates only (`:197-210`); the JSON has no
  uncertainty fields, so downstream tables cannot show error bars.
- **Single seed.** `--seed` affects only the toxic cap (`:956,1126`); the FLORES split is fixed at
  0 in `train_flores12.py`, and XGBoost has no row/column subsampling, so there is no seed-to-seed
  variability at all.

## Recommended changes

1. **Fix the completeness contract.** Add a per-arm status and set `completed_datasets` to
   `"toxic_partial"` (or add `"complete": false`) until all 3 generators or an explicit skip
   decision are recorded. Never append a dataset on a partial run.
2. **Commit the injection/partial logic.** Move `inject_toxic.py` into the repo (or fold it into
   `gen_compare.py` behind `--allow-partial`) and record the skip reason, rows done/total, and the
   union in the JSON. Also render the union in the MD (or state why it is JSON-only).
3. **Fix `--gen-batch`.** Either make `generate_italian` start from `GEN_BATCH` or delete the flag
   and the config field. Align the defaults with the documented stored run (8, no compile) or
   update the documentation and JSON config generation.
4. **Add `--merge-json` / per-dataset outputs.** A subset run must not delete other datasets'
   results. At minimum, write `gen_compare_flores.json` / `gen_compare_toxic.json` and merge.
5. **Add uncertainty.** Run 3 seeds (bootstrap resamples of the 1501 train rows, as in E20) and
   report 95% CIs for macro-F1, AUC, and each ratio. A "pass" at 0.975 should require the CI to
   clear the bar, not just the point estimate.
6. **Report both metrics.** Show macro-F1 and AUC pass/fail side by side and declare the headline
   metric. The current finding is true only for macro-F1; AUC reverses two of the three cells.
7. **Filter generations.** Strip outer quotes and leading bullets, drop prompt-echo rows, apply
   `paraphrase_prompts.length_ratio_ok`, and log the counts per arm. Re-run FLORES to check whether
   SmolLM2's macro-F1 lead survives clean text.
8. **Fix the toxic comparison.** Size-match the ceiling (subsample `real_it` to 8,000 or expand the
   synthetic arms), calibrate the threshold on validation data or match the label prior, and make
   AUC/AP the primary toxic metrics. Do not quote "32% of ceiling" without those caveats.
9. **Harden cache keys.** Hash prompt text, `max_new_tokens`, decode flags, model id + revision,
   dtype and `max_len` into both the generation and embedding cache names.
10. **Clean the report.** Omit the throughput table when `gen_stats` is empty; print partial
    progress in the toxic row; remove the stale PID file on exit (`:1052-1053`).
11. **Correct `EXPERIMENTS.md`.** Replace "matching the FinePhrase family result" and "replicating
    the paper's '≈1B saturates' claim" with what was measured: 2/3 pass at 0.975 on macro-F1,
    metric-dependent, single seed, 505-row test, toxic NOT DONE. Also note that Qwen3.5-2B is worse
    on macro-F1/accuracy but better on AUC, and that the gap is within noise.
12. **Finish or close the toxic arm.** If finishing, the remaining 3,200 SmolLM2 rows at the last
    observed ~0.70 rows/s need about 76 min of GPU time; run it detached with PID/log, then
    recompute the toxic table from cache (no regeneration of the Qwen arms). If not finishing,
    record the permanent skip and drop the `completed` flag.
