## Discrepancies

1. **The EXPERIMENTS table omits the in-language ceiling.** The entry (lines 204–207) has EN test,
   MT it/de/fr, and untranslated, but not the target-trained reference. Add 210m
   0.434/0.435/0.467 and 610m 0.428/0.466/0.437 (macro-F1). Without it, the reader cannot see that
   MT exceeds the in-language reference.

2. **The metric is unnamed.** The EN-test column 0.486/0.495 is macro-F1. The entry says only
   "English test"; the MD and JSON make the metric clear. Add "(macro-F1)".

3. **The finding hides the 0.975 result.** "Ratio 0.96–1.05" is arithmetically right for macro-F1
   (0.9574–1.0498 after rounding), but it does not say that 210m it/de fail the project bar. The
   0.975 verdict is **4/6 macro-F1, 6/6 AUC** against EN and **6/6 macro, 6/6 AUC** against the
   ceiling.

4. **The shipped MD uses a stale 0.9 bar.** `translate_test_eval.md:19,33` says "MT reaches
   EN-level (ratio >= 0.9) in 3/3 targets". The code (`translate_test_eval.py:449–453`) hard-codes
   0.9. At 0.975 the 210m counts are 1/3 macro (fr only), not 3/3. This is the main narrative
   inconsistency between the artifact and `EXPERIMENTS.md`.

5. **"Untranslated" is not the repo's best transfer baseline.** E23 applies EN-train stats to the
   target embeddings (`apply_z(X[tg], mu, sd)`), deliberately holding the feature space fixed. That
   gives 0.231/0.299/0.288 and 0.276/0.311/0.340. E21's XGBoost EN→IT is 0.366 (210m) / 0.461
   (610m) because it uses each target's own train z-score. The entry should say "untranslated
   (EN-space transform)", otherwise the E23 column appears to contradict E21.

6. **E19's de ceiling 0.537 is not the same metric.** E19's `sent | de` 0.537 is the **micro-F1**
   from `flores_ceiling.json` (0.5366); E23's de ceiling 0.435 is **macro-F1** (0.4355). E19's
   `sent | it (macro)` 0.434 is the macro value. No numbers are wrong, but E19 mixes micro and
   macro in one table; E23 is consistently macro-F1.

7. **MT/EN ratios above 1 need interpretation.** 610m it 1.050 and fr 1.042 exceed the human
   English test, while 210m fr (0.978) and 610m de (0.998) are the closest passes (0.3 and 2.3 pp
   above the bar). "Recovers English-level" is fair, but the entry should not imply MT is
   uniformly at or below EN; on this split it can exceed it.

8. **No uncertainty.** Single seed, 505 test rows, rare classes (0: 4 rows; 8: 8 rows), no
   bootstrap or split resampling. Macro-F1 differences of ~0.01 are within noise, so the 210m
   it/de misses (0.957/0.958, 1.8 pp below) and the 210m fr pass (0.978, 0.3 pp above) should be
   called borderline, not decisive; 610m de (0.998) is 2.3 pp above but is the closest 610m cell.

9. **Docstring/code mismatch.** The script docstring (lines 17–19) says alignment is via
   `train_flores12.load_sent_embeddings`, but the code uses its own `load_sent_mean`
   (`:187–196`). The function is equivalent (both slice with `kept` and check 2009 rows) and is
   needed for the 610m root, but the docstring is inaccurate.

10. **`--launch --smoke` silently runs the full job.** `launch_detached` (`:493–501`) forwards
    `--backbones`, `--targets`, `--device` but not `--smoke`, so `--smoke --launch` launches a
    full run. Not triggered by the documented commands.

## Bugs / risks

1. **Stale 0.9 threshold in `build_md`** (`translate_test_eval.py:449–453`). It reports "3/3"
   for both backbones at 0.9. At the project's 0.975 bar, 210m is 1/3 macro. Change the constant
   to 0.975 (or make it a config field) and report MT/EN and MT/ceiling separately.

2. **MT cache key has no model revision, dtype, or device.** `mt_translate` keys only on
   `lang`, `len(texts)`, and the source-text md5 (`:260–262`). A Hugging Face model update, a
   different `transformers` version, or a CPU (fp32) rerun can silently reuse old hypotheses or
   produce new ones under the same key. Add the model id + revision + dtype/device to the key, or
   a `--rebuild-mt` flag.

3. **The cache is external and now shared.** It lives in
   `%TEMP%\opencode\translate_test_eval\`, outside the repo, and `en_vs_enit_translate.py` (E42,
   untracked) reuses it (`:36–37, :69`). Deleting it affects both experiments. Document the
   dependency and do not clean it casually.

4. **The figure omits the ceiling.** `plot` (`:375–408`) draws EN test, MT, and untranslated only.
   The ceiling is the key comparison in the corrected table; add three ceiling bars (and/or
   MT/ceiling ratio annotations).

5. **No `--render`.** Rebuilding the MD/PNG from the JSON requires rerunning the whole pipeline
   and refitting 8 XGBoost models (the spot-check fits took 10.8 s and 18.2 s per EN model on this
   box). E18/E24 provide `--render`; add one for E23.

6. **Macro-F1 has a hard zero component.** `mc_metrics` (`:168–183`) uses all 12 labels and
   `zero_division=0`. The 210m EN model predicts class 0 for 0/505 rows (see
   `flores_ceiling.json` `pred_dist[0] = 0.0`), so class 0 contributes F1=0 to that model's
   macro-F1; the target models predict it on only 2–3 rows. The comparison is consistent across
   arms, but report per-class F1 or micro-F1 as a sensitivity check, especially with 4 class-0
   test rows.

7. **The "ceiling" is not a tuned ceiling.** It uses the same XGBoost hyperparameters selected for
   English, 1501 target rows, and one seed. A tuned native model (E28-style Optuna) could be
   higher. The 210m values match `flores_ceiling.json` by construction, so they are internally
   consistent, but they are a same-recipe reference, not an upper bound on target-language
   performance.

8. **Round-trip/translationese confound.** FLORES it/de/fr are human translations of the English
   source. E23 machine-translates those translations back to English. The MT test therefore
   benefits from recovering source-like English. The EN test is the human-written English source
   for the same 505 documents — a reference, not a hard upper bound (610m MT exceeds it). This
   should be stated whenever MT is compared with the in-language ceiling; it is not a test on
   naturally occurring target text.

9. **`sanity` checks only EN stored embeddings.** `:311–319` compares a fresh EN mean-pool with
   `emb_en.npy` (max abs 1.7e-5 / 7.2e-5). It does not check the target embeddings or the
   translated-embedding cache. The audit checked the MT cache independently (cosine 0.99999999),
   but the script should ideally check one target row too.

10. **`load_sent_mean` duplicates `train_flores12.load_sent_embeddings`.** If the CSV/embedding
    alignment logic changes, E23 will not inherit the fix. Factor the alignment into
    `train_flores12` or make the duplication explicit.

11. **`build_md` has a meaningless phrase.** `:459` says "610m/210m note only where present";
    this is a leftover and should be removed/replaced with the actual cross-backbone note.

12. **No confidence intervals or seed sweep.** The 210m it/de misses are only 0.018 below the
    bar, and the 210m fr / 610m de passes are 0.003 / 0.023 above it; a different seed-0
    permutation or a bootstrap over 505 rows could move them. The verdict should be reported with
    that caveat (as `E23.md` does).
