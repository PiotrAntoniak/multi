1. **Coverage: 5 rows shown, 17 available.** E21 (`EXPERIMENTS.md:226-232`) lists SVC_linear,
   MLP, LogisticRegression, GaussianNB and XGBoost. The 12 omitted models are **SVC_rbf, SGD,

   - **QDA** is the only stored 610m model passing both 0.975 metrics; it is also the only one
     at 210m.
   - **SVC_rbf** and **SGD** pass the 610m AUC bar.
   - At 610m transfer, the top 7 are SVC_linear (0.562), MLP (0.517), LogisticRegression (0.514),
     KNN (0.502), SGD (0.501), GaussianNB (0.494), SVC_rbf (0.469). The four non-reference rows
     keep the top 3, skip #4 and #5, and keep #6; the fifth row is the XGBoost reference (#8).
2. **"transfer" is a mean of two directions.** `_transfer_mean` (`models_compare.py:340-342`)
   averages EN→IT and IT→EN, and the `.md` writes this mean (lines 454-458, 471-472). E21 does not
   say so. The asymmetry is large: 610m SVC_linear is 0.5187 (EN→IT) vs 0.6061 (IT→EN); 210m
   GaussianNB is 0.4638 vs 0.4427. A bar check on the mean is not the same as a check on EN→IT.
   Example: 610m SVC_linear mean ratio = 0.5624/0.5831 = **0.9644**, while the EN→IT ratio is
   **0.8895**. The mean hides the failed direction. Conversely, 210m GaussianNB mean ratio =
   **0.9799** (would pass 0.975), but IT→EN is **0.9571** (fails).
3. **The 0.975 bar is not part of E21.** `EXPERIMENTS.md:223-234` reports only macro-F1 means and
   the finding "a linear SVM beats XGBoost". The master result (`EXPERIMENTS.md:387-390`) uses a
   0.90 bar. No 0.975 claim exists in E21, `models_compare.md`, or `models_compare.json`. Any
   downstream 0.975 claim is not supported by the E21 artifact as written.
4. **QDA 610m pass does not reproduce.** Stored: F1 0.0739 -> 0.0813 (ratio 1.0995), AUC 0.4949

## Bugs / risks

1. **Partial runs destroy the full artifacts (P0).** `--only` and `--smoke` still write
   `OUT_JSON`, `OUT_MD`, `OUT_PNG`:
   - `models_compare.py:553-554` forces `run_names = ["LDA", "LogisticRegression"]` for `--smoke`.
   - `models_compare.py:601-602` writes the partial JSON after every model.
   - `models_compare.py:609-620` overwrites the final JSON, MD and PNG.
   The docstring line 37 says the outputs are "create-only". They are not. A 2-model run leaves a
   2-model artifact with `"smoke": true`. This is a reproducible data-loss hazard. The audit did
   not run `--only` or `--smoke` because of it.
2. **QDA is rank-deficient and the warnings are suppressed (P0).** `QDA()` at line 236 uses the
   default `reg_param=0.0`. With 1501 train rows and 12 classes (~125 rows/class) against 768 or
   1152 features, every class covariance is singular. Diagnostic: 12/12 classes emit
   `"The covariance matrix of class N is not full rank"`; effective ranks were 21-386 (210m)
   against 768 features. `warnings.filterwarnings("ignore")` at line 61 hides all 12 warnings.
   sklearn truncates the SVD at a fixed `tol=1e-4`; small numerical differences can change the
   retained rank, which is consistent with the observed cross-process drift. The row is not
   stable across processes. This is the only model that passes both 0.975 metrics in the stored
   JSON.
3. **No provenance (P1).** `models_compare.json:config` records seed, n_jobs and the XGBoost
   params, but not Python/sklearn/numpy/scipy/xgboost versions, git commit, BLAS/thread
   environment, host, or run date. The current environment is sklearn 1.6.1, numpy 2.5.4,
   scipy 1.15.3; scipy emits `A NumPy version >=1.23.5 and <2.5.0 is required` (detected 2.5.4).
   The QDA drift cannot be diagnosed from the artifact.
4. **No uncertainty (P1).** Single seed, single split, no CIs or bootstrap. Test n = 505;
   per-class n = 4, 31, 30, 46, 20, 20, 45, 42, 8, 97, 30, 132. Macro-F1 gives the 4-row class
   the same weight as the 132-row class. A 0.975 ratio cannot be distinguished from sampling
   noise at this sample size.
5. **The comparison is not a fair model-class comparison (P1).** Only LogisticRegression and KNN
   are selected on val. The XGBoost reference is a fixed project config that is not selected on
   this split. The other 15 models use one hand-set config each, several not default (see D7). A
   claim that "SVC beats XGBoost" compares a fixed SVC config to a fixed XGBoost config.
6. **Convergence checks are absent (P2).** `warnings.filterwarnings("ignore")` (line 61) hides
   `ConvergenceWarning`. `LinearSVC` at 610m took **751.7 s** (log line 23) with `max_iter=5000`;
   MLP uses `max_iter=400, early_stopping=False` (lines 232-233). `n_iter_` is not stored, so an
   under-fit row cannot be detected. The 610m LinearSVC F1 (0.521) is plausible, but the artifact
   does not prove convergence.
7. **Ratio of bounded metrics (P1).** AUC has a 0.5 floor. QDA 0.5057 -> 0.5111 is a ratio of
   1.0106 but is pure chance. At the top end, 0.9389 -> 0.9182 is a ratio of 0.978 but an absolute
   drop of 0.021. The same numeric bar means different things on F1 and AUC. Use absolute deltas
   and an absolute floor as well.
8. **Direction mean only (P1).** EN→IT and IT→EN are in the JSON but not in the `.md` tables.
   The mean can pass while one direction fails (210m GaussianNB mean 0.9799; IT→EN 0.9571).
9. **Transfer uses target train statistics (P2).** `perlang_z` (lines 148-157) standardizes IT
   test rows with IT train mean/std. This needs unlabeled target train data and is not a
   target-free zero-shot protocol. `models_compare.md:3` says so; E21 does not.
10. **Failed cells disappear (P2).** A cell that raises is logged (`line 597-599`) but then
    dropped from `results` before the summary (`lines 604-606`). The final JSON has no record of
    the failure; only the log does. A partial or failed run can look complete.
11. **No render-only mode (P2).** `--render` does not exist. Rebuilding `.md`/`.png` requires the
    full ~1449 s retrain. E18 has `--render`; E21 does not.
12. **Unused language loading (P3).** `LANGS` includes de/fr (line 78) and `load_backbone` loads
    all four (lines 163-175), but only en/it are used. Wasted I/O and memory, no result impact.
13. **Log/pid/status clobbered (P3).** `_open_log` opens with `"w"` (line 120) and `write_pid`
    overwrites (lines 126-128). Concurrent or repeated runs lose the previous log. There is no
    run tag, unlike `train_flores12.py --tag`.
14. **No model registry entry and no persisted models.** The E21 results exist only as loose
    files. No fitted sklearn model is saved (no joblib/pickle), unlike E20's 15 `.ubj` models, so
    predictions cannot be re-scored without retraining. `models/` has no E21 bundle and there is
    no `models_compare` manifest.

## Missing scripts

1. **No 0.975 checker.** `models_compare.py` computes no ratio, no pass/fail and no absolute
   floor. The table in this audit was computed post hoc from the JSON. A `--check` mode should
   emit it reproducibly.
2. **No render-only mode.** Cannot rebuild `.md`/`.png` from the stored JSON without retraining.
3. **No bootstrap/CI script.** No per-cell confidence interval or paired test over the 505 test
   rows.
4. **No QDA/rank diagnostic.** The run does not record covariance rank, condition number, or
   `reg_param`. The 12 rank warnings are suppressed.
5. **No provenance capture.** No versions, git commit, environment, or host in the JSON.
6. **No E21 section generator.** The 5-row `EXPERIMENTS.md` table is hand-curated and cannot be
   regenerated from the JSON; that is how 12 rows were lost.
7. **No per-direction table in the `.md`.** The JSON has EN→IT and IT→EN, but the rendered table
   only has the mean.
8. **No persisted models or inference path.** `models_compare.py` keeps every fitted model in
   memory and discards it. There is no script to reload a model and reproduce a single prediction
   or metric.

## Recommended changes

**P0 — correctness / integrity**

1. **Stop destructive partial runs.** Make `--only` and `--smoke` write
   `models_compare_<tag>.json/.md/.png` (or refuse to overwrite an existing full artifact).
   Delete the "create-only" claim or implement it. Guard the final write on
   `all models present`.
2. **Remove QDA or regularize it.** Set `reg_param` > 0 (e.g., 1e-2 to 1e-1) and record the
   effective rank per class; fail the cell if any class is rank-deficient. Narrow
   `warnings.filterwarnings` to known-benign messages so `ConvergenceWarning` and QDA rank
   warnings are visible.
3. **Re-run the full experiment in a pinned environment** after (1) and (2), and record
   Python/sklearn/numpy/scipy/xgboost versions, git commit, BLAS/thread settings and run date in
   `config`. Until then, mark QDA as "not reproducible" in the JSON/MD.
4. **Report EN→IT and IT→EN separately.** Replace the single "transfer" column with both
   directions and the mean. Apply the 0.975 bar to EN→IT (the stated target), and show the reverse
   direction as a robustness check.
5. **Add absolute floors to the bar.** Example: require EN-self macro-F1 >= 0.45 and EN-self AUC
   >= 0.85 in addition to the ratio. This removes chance-level QDA automatically. Report absolute
   deltas next to ratios.

**P1 — evidence quality**

6. **Add `--render` and `--check`.** `--render` rebuilds MD/PNG from the JSON. `--check` emits the
   17 x 2 ratio table, pass/fail, both directions, and absolute values.
7. **Add uncertainty.** Bootstrap the 505 test rows (e.g., 1000 resamples, stratified by class)
   for macro-F1 and AUC, and report 95% intervals. At minimum, report the per-class n and a
   paired bootstrap difference vs EN-self.
8. **Tune all families or relabel the study.** Either run a small val grid for SVC, MLP, SGD,
   boosting and forests, or rename the deliverable "one fixed configuration per model". Do not
   compare fixed SVC to a fixed XGBoost reference without saying so.
9. **Record convergence.** Store `n_iter_` for LinearSVC, SGD, MLP and LR; fail or flag a row that
   hits `max_iter`.
10. **Correct `EXPERIMENTS.md` E21.** Either show all 17 rows or state "top 5 by EN-self F1" and
    why. Add AUC. Replace the finding with: "SVC_linear has the best EN-self F1 and the best 610m
    mean transfer; GaussianNB and KNN beat it on 210m transfer. No model reaches 0.975 EN→IT
    parity on macro-F1; three 610m models pass the AUC ratio only."
11. **Add a note on the 0.975 bar.** State that it is an external bar, not an E21 result, and
    that the master result uses 0.90.
