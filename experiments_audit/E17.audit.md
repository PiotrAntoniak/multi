**Bottom line.** All 12 headline cells match the JSON/MD, and the computation is correct. The
Finding is overstated. "SHAP mass ≤ random" is false for mel (+4.7e-5) and the sent deficit is

   - Top-50 overlap: 0 / 1 / 1 (entry 0/50, 1/50, 1/50).

   - Random: 0.308594 / 0.328125 / 0.365885 (entry 0.309 / 0.328 / 0.366).
   All three MD rows and the per-dataset top-20 η² / top-10 SHAP tables also match the JSON.

2. **Artifact provenance.** `%TEMP%\opencode\lang_shap_dims.log` (1120 B) matches the JSON/MD
   line by line; elapsed 410.6 s; PNG timestamps 06:40:32 (sent), 06:40:37 (agg), 06:47:04 (mel)
   agree with a single run starting 06:40:13. Files are tracked in commit `21ab888`; `git status`
   is clean. `REPRODUCE.md:50-51` gives the correct command. The sent PNG is a correct 3-panel
   plot (sorted η², sorted |SHAP|, scatter titled "Spearman -0.076").

3. **η² is computed correctly.** `lang_neutralize.eta2_per_dim` (`lang_neutralize.py:10-20`) is
   the standard one-way ANOVA ratio SS_between/SS_total, per column, with group weights
   `len(mats[l])`; groups are balanced (2006 rows/language for FLORES, 16000/language for mel).
   `top_dims` (`:23-28`) sorts descending and takes `searchsorted(cumsum/total, frac)+1`.
   Spot-check: k50 is the count of dims covering 50% of the summed per-dim η², not a count of
   dims with η²>0.5 (that is a separate column).

4. **SHAP is computed correctly, as absolute/row-and-class means.**
   `lang_shap_dims.py:172-177` takes `mean(|SHAP|)` over explained rows and all class outputs for
   `multi:softprob`; `:180-188` takes class 1 of each binary model and averages over the 21 OVR
   models. Mass is normalised by `imp.sum()` over all 768 dims (`:198-205`), so it is a fraction
   of total attribution. I re-ran sent and agg with the exact code path and parameters: Spearman,
   overlap and mass reproduce to 6 dp, and the top-10 SHAP dim ids match exactly.

5. **The random baseline is correct but is only an expectation.** `random = k/d`
   (`:205`). 237/768 = 0.30859375, 252/768 = 0.328125, 281/768 = 0.36588542. A 20k-draw
   random k-subset null gives the same mean (0.3084, 0.3278) and sd 0.0182 (sent), 0.0302 (agg).

6. **Inputs, split, model, seed are consistent.**
   - sent: 2009-row embeddings sliced to 2006 kept rows (dropped git rows 997–999), 997/504/505,
     seed 0 (`train_flores12.py:324-351`); EN train labels only; SHAP on the 505 EN test rows.
   - agg: 562x768; URL split inherited from sentence `dev`/`devtest`, class 0 dropped, 276/140/139
     (`:354-413`); SHAP on 139 test rows.
   - mel: 11000/5000x768 per language; `en_train.jsonl` 11000 lines and `en_test.jsonl` 5000
     lines, `multi_hot` length 21; EN train used for fit; 1000 test rows explained (seed 0).
   - Config in JSON matches `TREE_COMMON` (`lang_shap_dims.py:79-80`): hist, max_bin 64, cpu,
     n_jobs 2, seed 0, depth 8, min_child_weight 5, lr 0.1, 400 trees.
   - The en/de/fr **test** `multi_hot` matrices are identical (parallel test); the train matrices
     are not, as documented.

7. **No label leakage / train-test mismatch.** The model is fit only on EN train rows and labels.
   η² is unsupervised (no labels). SHAP is computed on EN test features and does not use test
   labels. `_read_mel_labels` returns exactly 11000/5000 rows, so there is no silent length
   mismatch; a mismatch would have raised in `fit`.

8. **The η² dim selection does not depend on the test rows** (checked for sent/agg). Recomputing
   η² on train-only vs test-only vs all rows: sent k50 = 237/237/237, mass 0.2703/0.2812/0.2828,
   top-50 overlap vs all = 48/49; agg k50 = 251/253/252, mass 0.2637/0.2575/0.2666, overlap 45/45.
   The conclusion is robust to this selection choice.

9. **The deficit is not a within-English variance artifact.** Language dims have average
   within-English variance (sent 2.81 vs 2.74; agg 2.16 vs 2.14) and `|SHAP|` correlates only
   weakly with variance (Spearman +0.16/+0.14). A variance-decile-matched null gives sent
   z=-1.66, agg z=-2.01 — essentially the same as the uniform null (z≈-1.4/-2.1).

## Discrepancies

1. **mel contradicts the Finding.** Mass is 0.36593282 vs random 0.36588542, i.e. **+4.74e-5**
   (relative +0.013%). The entry table says "equal (0.366)", which is right; the Finding says
   "SHAP mass ≤ random", which is literally false for mel; the MD says "MORE" and the MD
   conclusion says "used by the classifier (SHAP mass >= random)". Three different verdicts for
   the same 5th-decimal difference. The cause is the strict `>` in
   `lang_shap_dims.py:214` and the strict `>=` wording in `:440-441`.

2. **sent "below" is within noise.** Observed deficit 0.02583, null sd 0.01826 → z=-1.41,
   one-sided p=.078. Per fraction: k25 z=-1.02 (p=.155), k50 z=-1.42 (p=.078), k95 z=-2.00
   (p=.026). The entry presents this as a firm "below (0.309)"; it is not significant at 5%.

3. **agg "below" is nominal only.** Deficit 0.06148, sd 0.0302 → z=-2.04, p=.019; k25/k50/k95
   z=-1.46/-2.04/-2.10. This is ~2σ and directionally consistent, but it does not survive a
   multiple-comparison correction for the 9 tests (3 datasets x 3 fractions). It is weak
   evidence of *under*-use, not proof.

4. **"The English classifier does not use the language dims" is an overclaim.** Mass ≤ k/d means
   attribution is not concentrated on those dims. A classifier that used all 768 dims uniformly
   would also produce exactly k/d. The data support "no preferential use", not "non-use".

5. **"Why mean pooling transfers" is a causal claim the experiment does not test.** The
   experiment measures attribution on English text only; it does not intervene on the dims or
   test transfer. The result is *consistent with* the explanation, not a demonstration of it.

6. **The top-50 overlap is weaker evidence than it looks.** Under the hypergeometric null the
   expected overlap is 3.26 (sd 1.69). Observed 0/50 has p=.031; 1/50 has p=.115. Only sent is
   nominally unlikely, and that is one of three datasets.

7. **The entry omits the Part A numbers** (k50, probe collapse), which are the other half of the
   result. Not an error, but the entry reads as if Part B were the whole experiment.

8. **"DONE" vs verified.** The entry has no "(verified)" marker. Sent/agg are exactly
   reproducible; mel (384 s) was not recomputed. Its numbers are internally consistent and match
   the run log, but the only unverified block is mel Part B.

## Bugs / risks

1. **3-D SHAP layout assumption (latent portability bug).**
   `mean_abs_shap_multiclass` (`lang_shap_dims.py:174-177`) averages `axis=(0,2)` for any 3-D
   result. That is correct only for `(n_rows, d, n_classes)`. If a SHAP version returns
   `(n_classes, n_rows, d)` (list-of-arrays form), the same line returns a length-`n_rows`
   vector and `part_b` later indexes it with dim ids — a crash if n_rows != d, silent garbage if
   n_rows == d. The current environment takes the `(n,d,C)` path (exact reproduction proves it),
   but the branch should assert `imp.shape == (d,)` or detect the feature axis. The binary
   branch (`:185-186`) has the same assumption for `(n,d,2)`.

2. **Strict `>` verdict has no tolerance.** `k50_lang_dims_more_shap` (`:214`) is true by
   4.7e-5. The MD then prints "MORE" and the conclusion says "used by the classifier" — a
   misleading result produced by floating-point noise. Use a tolerance (e.g. 1% relative or
   2 null sd) and report "equal" explicitly.

3. **No uncertainty on the random baseline.** Only `k/d` is reported. The null sd at k50 is
   1.8 pp (sent) and 3.0 pp (agg), which is the same order as the reported gaps. Report z/p or a
   seeded permutation CI. Without it, "below" is not interpretable.

4. **η² dims selected on all rows, including test.** sent/agg use train+val+test (2006/lang); mel
   uses train+test (16000/lang). It is unsupervised, so this is not label leakage, and the
   split-stability check above shows it is immaterial for sent/agg; mel was not checked. Best
   practice is to compute η² on train rows only (or report both).

5. **The script is not resumable and overwrites committed artifacts.** The docstring says
   "create-only" (`:30`) but `main` opens `OUT_JSON`/`OUT_MD` with `"w"` (`:450`, `:505`). JSON
   is written only at the end, so a crash loses sent/agg even though their PNGs exist. A
   `--datasets sent` run rewrites the JSON with only sent, destroying the 3-dataset record.
   There are no input hashes or timestamps in the JSON beyond `elapsed_s`. The PID file is
   written (`:481-482`) but never removed; `lang_shap_dims.pid` currently holds a stale PID 25840
   (gitignored).

6. **Import ordering.** `from lang_neutralize import ...` (`:58`) runs before `REPO` is added to
   `sys.path` (`:60-62`). It works when the process cwd is the repo (and `--launch` sets
   `cwd=REPO`), but fails if the script is imported from elsewhere. Move the path insert above
   the import.

7. **Equal class/concept weighting.** Multiclass SHAP averages the 12/11 class outputs equally
   even where test labels are scarce (agg test has 4 rows for classes 3 and 4). mel averages the
   21 concept models equally although positives per concept range 108–6121. This changes the
   scale of `mean_shap_total` but not the within-dataset mass comparison; it should be stated.

8. **mel Part A mixes non-parallel train corpora.** The en/de/fr train documents are not
   translations of each other, so part of the mel η² may encode corpus/topic differences as well
   as language. The top η² is 0.95, so language dominates, but "language dims" is not a pure
   construct for mel. The test rows are parallel, which mitigates this for the explained block.

9. **Dead code / unused args.** `yte_mel` is loaded (`:241`) and never used; `run_agg(sent, ...)`
   takes an unused `sent` argument (`:300`). Harmless, but noisy.

10. **Probe is at ceiling.** `full=1.000` on all datasets and `zero_top_k50=1.000` leaves no
    headroom to show a collapse. This is consistent with E1's redundancy result, not a bug, but
    the probe demonstrates "still separable", not "language information preserved exactly".

11. **Environment warning.** The audit interpreter emits
    `A NumPy version >=1.23.5 and <2.5.0 is required for this version of SciPy (detected 2.5.4)`
    on import. `spearmanr` still ran and reproduced the stored values exactly, but the SciPy
    install is outside its declared NumPy range; pin it before a clean reproduction run.

## Recommended changes

1. **Rewrite the Finding** to: "Language dims receive no more attribution than a random dim set:
   mel 0.366 vs 0.366 (equal); sent 0.283 vs 0.309 (z=-1.4, n.s.); agg 0.267 vs 0.328 (z=-2.0,
   nominal). The English classifier does not preferentially use the language-carrying dims."
   Drop "does not use" and mark "why mean pooling transfers" as consistent-with, not proven.

2. **Add uncertainty to `part_b`.** Store the null sd and z for each fraction (or a seeded
   permutation p-value), and make the verdict three-way: MORE / EQUAL / LESS with a tolerance
   (e.g. |mass − k/d| < 2 sd → EQUAL). Regenerate the MD so mel reads "equal", not "MORE", and
   fix the conclusion line `:440-441`.

3. **Harden the SHAP extractor.** Assert the output shape is `(d,)` and select the feature axis by
   shape (`(n,d,C)` vs `(C,n,d)`), or upgrade the `shap` pin and keep one explicit layout.

4. **Compute η² on train rows only** (or add `--eta2-split train|all` and report both). State the
   choice in the docstring.

5. **Persist the per-dim vectors.** Add `eta2` (768 floats) and `mean_abs_shap` (768 floats) to
   the JSON. They cost ~12 KB and make Spearman/overlap/mass re-checkable without retraining —
   the current JSON cannot be audited without a full re-run.

6. **Add resumability and provenance.** Write JSON after each dataset, include input file sizes /
   mtimes and a git commit hash, delete the PID file on exit, and stop calling the outputs
   "create-only".

7. **Report the null baseline as an interval**, not a point: e.g. `0.283 vs 0.309 ± 0.018`.

8. **State the weighting** (equal classes; equal concepts for mel) in the docstring and MD.

9. **Move `sys.path.insert(REPO)` before the `lang_neutralize` import**; remove `yte_mel` and the
   unused `sent` arg.

10. **Entry table:** add the z/p or a footnote that sent's "below" is not significant and mel is
    equal, not below. Keep the Part A numbers (k50, probe) in the entry.
