## Bugs / risks

1. **`at_recall` is not tie-aware** (`toxi_pr_models.py:280-291`). It takes the score at the row
   where cumulative positives reach 90%, then predicts `s >= thr`. With a tie mass at the threshold
   (KNN), that predicts every tied row and overshoots recall to 1.0. There is no tie-block check and
   no interpolation. This is the root cause of the KNN artifact.
2. **The percentile fix did not propagate to the headline metric.** Curves use `np.percentile`;
   `at_recall` uses raw sorted scores. For continuous scores the results coincide; for KNN they do
   not. The metric should be computed on the same axis as the figure (or from
   `precision_recall_curve` with interpolation).
3. **`f1_opt_threshold` takes the first optimum on a plateau** (`:266-278`, strict `>`). This is the
   same tie artifact the module docstring criticizes for KNN's old val threshold. RF and KNN have
   many ties.
4. **Val-marker mismatch** (`pct_of_value`, `:318-321`): the marker q is `mean(s <= v)` but the
   curve threshold is `np.percentile(s, q)`. Measured offsets up to **0.020 precision**
   (LogisticRegression/210m/EN-EN: plotted 0.66667 at q=89.47 vs 0.68671 at the raw val threshold;
   XGBoost/210m 0.66970 vs 0.68889). Plot-level only, but visible.
5. **`--backbone 210m` silently drops all per-model figures.** At `:866` the dict is built from the
   selected `backbones`, but `plot_model()` iterates `BACKBONES` (both) and raises
   `KeyError('610m')`; the exception is caught and only logged. The run still reports success.
6. **A failed model silently reuses its old results.** In `merged_snapshot()` a fresh model with
   both backbones `None` falls through to `existing[n]`. A `FAILED` log line can therefore still
   produce a complete-looking JSON.
7. **`--only` silently merges with stale results and re-stamps the payload** (`:757-769`, `:846`).
   The help text says only "comma-separated classifier names to run". This is exactly how the
   current JSON became a mixed-run artifact.
8. **Incremental save strips `config` and `generated`** (`:811`). A crash mid-run leaves
   `toxi_pr_models.json` with only `{"results": ...}`; the MD is then stale and inconsistent.
9. **Smoke writes into the repo root and shares run state.** `out_json + ".smoke"` (`:807-813`) and
   `toxi_pr_models_smoke.json` (`:850`); no PID is written in smoke mode (`:783`); the status file is
   shared. A smoke run can overwrite a real run's status and cannot be killed via the documented PID.
10. **Smoke artifacts are still committed/left in the repo:** `toxi_pr_models.json.smoke` (573,797 B,
    keys only `results`) and `toxi_pr_models_smoke.json` (576,252 B, full payload). Both stamped
    2026-10-13 14:06:54, **6 models (no XGBoost), 200-row splits** (`n_test = 200`). They are from a
    pre-XGBoost revision and are not comparable to the real run. Quoting them would be a 200-row
    artifact.
11. **Mixed `toxi_pr.*` provenance.** `toxi_pr.png`/`.md` = `toxi_pr_all.py` (RAW features, seed 0,
    14:03:30/31); `toxi_pr.json` = `toxi_pr.py` (per-language z-score, seeds 0/1/2, generated
    2026-10-12 10:49:46, script mtime 2026-10-14 09:00:42, i.e. the JSON also predates its script).
    `toxi_pr_610.png` (13/10 00:35) is an E28 side output of `backbone_grid.py:89,760` (610m,
    per-language z-score), not an E27/E37 artifact. Three pipelines, two transforms, one name
    prefix.
12. **`figures_only()` hard-codes the model order** (`:708-710`). A model added to `build_zoo()`
    will never be re-plotted by `--figures-only`.
13. **`toxi_pr_all.py` still sweeps raw probability** (`THR_SWEEP`, line 61) and its R90 points are
    compressed into t < 0.031, so the P@R90 operating point is not visible in `toxi_pr.png`. It
    writes the MD only if the file already exists (`:366`), so a clean checkout cannot regenerate
    `toxi_pr.md`. It also contains a dead first assignment (`:371-378`).
14. **No recall column beside P@R90** anywhere in `toxi_pr_models.md`; that is what hides the KNN
    recall=1.000 defect.
15. `requirements.txt` pins no versions; XGBoost emitted a SciPy/NumPy version warning during the
    earlier runs.
