### Discrepancies

1. **The report labels its data latin-1, but the CSV is UTF-8.** `gguf_quant_quality.md:3` and the `load_flores` docstring say latin-1; `gguf_quant_quality.py:64` opens it that way. All 150 Italian references came out mojibake (86/150 contain `Ã`). A perfect hypothesis scores **97.4 chrF**, not 100, against those strings. The absolute chrF/chrF++/BLEU values are therefore understated (roughly 1.4-2.6 points); the quant-vs-BF16 ratios are nearly unaffected because all three models see the same damaged references.
2. `tools/compare_pl.py:3-5` documents `out_qwen25_15b_pl.csv` and "Qwen2.5-1.5B" as the second model, but `MODELS` (`:20-23`) scores `out_qwen25_3b_pl.csv`. The file that exists and is commented in the docstring is never scored.
3. `out_timing.json` has the `tools/run_dual_translate.py` schema (`rc`, `wall_seconds`, `gen_seconds`, `n_ctx`), not the `tools/run_translate.py` schema (`seconds`, no `rc`, no `gen_seconds`). The 1.5B run's timing was overwritten and is lost; re-running `run_translate.py` would silently replace the tracked file with the other schema.
4. `compare_pl.json`'s `per_variant_chrF` block reports 41.77 for all four variants (and 37.86 for all four of the other model). The scorer is correct; the *inputs* are duplicates, so the block carries no information.
5. `gguf_quant_quality.md`'s "full GPU offload" and greedy/temp-0 claims are supported by the script defaults, but the exact CLI (threads, `--n-ctx`, model paths, seed) was never logged with the results.
6. Q4_K_M `wall_seconds` = 262.2 s against 81.5 s of generation, while Q8_0 (a larger file) reports 155.0 s. The first model absorbs load/warm-up; wall time is not a throughput measure and should not be compared across rows.
7. BLEU is not monotone in precision: Q8_0 22.527 < Q4_K_M 22.559 (0.03 points). chrF and chrF++ are monotone. This is consistent with decoding noise, but the report does not say so.
8. `TRANSLATE.md:71` documents `--para-sep '||'` as the batched alternative; that option was removed in commit b89bcef (`paraphrase_translate: drop batched (||) paraphrase mode`). `TRANSLATE.md:29` says "Why no max-token setting" while the CLI has `--para-max-new`/`--trans-max-new`.
9. E38 had no documentation entry: both `E38.md` and `E38.audit.md` were absent before this audit (this document and its companion are the first write).

### Bugs / risks

1. **Reference-encoding bug (highest impact).** `gguf_quant_quality.py:64` must read UTF-8. Until it does, every published EN->IT number for this line is scored against corrupted text.
2. **`gguf_translate.py` never re-seeds after `load_state()`** (`:104-116`). `load_state` restores the sampler RNG, so all N paraphrases repeat: 25/25 inputs in all three committed CSVs have 4 identical variants. `paraphrase_translate.py` fixed this at `:296-298`; the predecessor did not and still does not.
3. **Hypotheses are not stored** (`gguf_quant_quality.py:166`: `hyps` is `null` unless `--keep-hyps`). Only 3 examples per model survive. The 0.39 chrF Q4-vs-BF16 gap cannot be checked, bootstrapped, or re-scored after an encoding fix without a new GPU run.
4. Both generation loops stop silently at `n_ctx-1` (`gguf_quant_quality.py:107`, `gguf_translate.py:109`). A truncated sentence is scored as-is with no flag and no retry.
5. `write_report` indexes `results[0]` (`:180`, `:190`); an empty result set raises `IndexError` instead of writing an empty report.
6. `--n-threads` defaults to 4 (`:218`), above this repo's 2-thread cap, and the value used is not recorded anywhere.
7. Weights are gitignored (`models/`, `models/*.gguf`) and no checksum is stored. The numbers are tied to locally fetched files; `tools/fetch_gguf.py` and friends do not pin a revision.
8. `tools/compare_pl.py` aligns hypotheses to references by row position only. It is correct for the current files (25/25), but one missing output row would silently shift every later hypothesis onto the wrong reference.
9. `--resume` trusts `gguf_quant_quality.partial.json` by tag (`:247-259`); stale metrics survive a code fix without warning (same failure mode as the resumable JSON noted in E18). The partial file is also untracked (`*.partial.json` in `.gitignore`), so it does not exist in a clone.
10. Single seed, 150 (quant) and 25 (EN->PL) sentences, no confidence intervals. The 0.39 chrF spread is within plausible noise; only the direction of the ranking is supported.
