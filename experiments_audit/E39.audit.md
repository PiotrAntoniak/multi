# E39 audit — retrieval protocol (FLORES + Europarl)

**Scope.** `table1.py`, `table1_agg.py`, `table1_europarl_multilang.py`, `fetch_europarl_langs.py`,
`tools/fetch_flores_en_pl.py`, `europarl_all_5k.csv`, the README retrieval sections
(`README.md:9-12, 17-27, 58-92, 94-113, 115-178, 281-309`), and the missing
`europarl_multilang_table1.md`. No repo file was edited. All work ran in
`%TEMP%\E39_flores\` (copy of `table1.py` + the `196bbd3` CSV + a junction to `embeddings/`).

**Verdict.** The protocol is correct and deterministic, and both cheap FLORES tables reproduce
**exactly** — but only against the historical 2009-row CSV. The repository as shipped cannot run
`table1.py` (`IndexError`), its README caption (`N=1012`) contradicts its own repo-contents row
(`1009`), and the Europarl table has no surviving artifact of any kind: no embeddings, no markdown,
no progress JSON, no log. Reproduction status: **PARTIAL**.

## 1. Verified

1. **FLORES table reproduces exactly.** An unmodified copy of `table1.py` run against
   `git show 196bbd3:flores200_en_it_de_fr.csv` (2009 rows: 997 dev / 1012 devtest) plus the
   shipped `embeddings/` prints the header `dev=997 devtest N=1012 | chance rank 506.5` and all 16
   range cells of `README.md:121-124` — e.g. `mean` raw `38.5-60.6%`, `+D` `83.9-90.0%`,
   `MRR +D 0.882-0.931`, `median +D 1`. `lead`/`bos`/`eos` also match to the last digit
   (`eos` `+D` `10.0-15.8%`; `bos` median `+D` `116-224`).
2. **FLORES-agg table reproduces exactly** on the shipped files. `python table1_agg.py` prints
   `dev=281 devtest N=280`, chance `140.5`, one warning for agg row 281, and `README.md:151-152`
   cell for cell (`mean` `92.9-98.9%` / `98.2-100.0%`, MRR `0.962-0.994` / `0.989-1.000`;
   `bos` `4.3-13.2%` / `11.4-21.1%`, MRR `0.076-0.201` / `0.158-0.298`, median `+D` `11-60`).
3. **The CSV drift is identified and quantified.** The three deleted rows are git rows 997-999,
   i.e. devtest ids 0,1,2 (first three devtest sentences). Slicing the 2009-row arrays with the
   `(split, id, en)` alignment already implemented in `train_flores12.py:419-439` and re-running
   the same protocol on the shipped CSV gives 1009 devtest, chance `505.0` and: `mean` raw
   `38.6-60.6`, `+D` `83.8-90.0`, MRR `+D` `0.882-0.931`; `lead` `+D` `11.0-25.9`; `bos` `+D`
   `4.5-10.7`; `eos` `+D` `10.0-15.8`. So the README numbers are substantively valid for the
   current data; only the N/chance header is stale.
4. **`+D` definition is identical in all three scripts and correct.** `table1.py:43-44`,
   `table1_agg.py:50-51`, `table1_europarl_multilang.py:388-391`:
   `D = mean(emb_a[dev] - emb_b[dev])`, then `sim = l2norm(emb_a[test]) @ l2norm(emb_b[test] + D).T`.
   `D` is fitted on **dev only**, added to the **key side only**, and both sides are L2-normalized
   before the dot product. Direction convention (`a` = foreign, `b` = en) is consistent with the
   README and with the "foreign-to-English only" scope.
5. **Splits are disjoint and leak-free.** FLORES uses the CSV `split` column (`table1.py:53-55`);
   dev and devtest share **zero** `en` texts (checked). `id` is a per-split counter (dev 0..996,
   devtest 0..1008) and is **not** a global key — alignment must use `(split, id, text)` as
   `train_flores12` does. Agg has no `split` column (562 rows verified), so the split is inferred
   per URL from the sentence CSV (`table1_agg.py:59-79`); exactly one URL is unresolvable
   (row 281 `Toronto_tea`, `n_sentences=0`, all four texts empty), 561 URLs map to a single split,
   and no URL spans splits. Europarl takes `split` from the combined CSV
   (`table1_europarl_multilang.py:407-409`); dev is the first 1,000 of the shuffle, devtest the
   last 4,000 (`:206-208`), so `D` never sees a test row.
6. **Europarl data file is well-formed.** `europarl_all_5k.csv` has 30,000 rows and columns
   `lang, split, id, en, de, es, fr, it, nl, pt`; six contiguous blocks in the order
   `de, es, fr, it, nl, pt`; each block has 5,000 unique non-empty `(en, xx)` pairs, ids 0..4999,
   1,000 `dev` / 4,000 `devtest`. `read_combined_lang()` returns 5,000 rows with those split counts
   for all six languages (executed without a model).
7. **Chance rank is computed, not typed.** `(N+1)/2` at `table1.py:58`, `table1_agg.py:95`, and in
   the Europarl summary text (`:454`): 506.5 / 140.5 / 2000.5, matching README. Chance top-1 `1/N`
   (0.1% at N=1012) matches `README.md:130`.
8. **Rank, MRR, top-1 and median are computed identically in all three scripts.**
   `ranks() = 1 + (sim > diag).sum(1)` (`table1.py:36-38`, `table1_agg.py:43-45`,
   `table1_europarl_multilang.py:382-383`); `MRR = mean(1/r)`; `top-1 = mean(r <= 1)`;
   `median = np.median(r)`. Strict `>` means ties with the true key are not counted against it
   (optimistic, measure-zero in float32 practice). Europarl additionally asserts `1 <= r <= N`
   (`:397`).
9. **The Europarl markdown is missing and was never committed.**
   `europarl_multilang_table1.md` does not exist on disk; `git log --all -- europarl_multilang_table1.md`
   is empty; `git ls-files` for this experiment lists only `europarl_all_5k.csv`,
   `fetch_europarl_langs.py`, `table1.py`, `table1_agg.py`, `table1_europarl_multilang.py`.
   `europarl_multilang_progress.json`, `europarl_multilang_run.log`,
   `europarl_multilang_status.txt` and `europarl_multilang.pid` are also absent. All six
   `europarl_*_5k_embeddings/` trees contain only the four empty mode directories — no `.npy`
   anywhere (`evaluate()` fails with `FileNotFoundError` before computing any metric).
10. **The missing md would be generated correctly if the metrics existed.** With a synthetic
    progress dict, `write_summary()` (redirected to a temp path) emits the protocol line, the
    mean-mode summary table, the per-language bullets and the all-mode detail table — the same
    shape as the README Europarl table. The generator is sound; only its input is gone.
11. **The 0.975 bar does not apply and no ratio is stored.** The only `0.975` in the retrieval
    scope is absent; the repo's 0.975 constant is `en_vs_enit_raw.py:82` (`BAR = 0.975`, E42,
    classifier). These tables are rank metrics, and no English self-retrieval baseline exists, so a
    target/English ratio cannot be formed. E18-style parity is **N/A** here.
12. **Determinism and environment.** Pure numpy after loading `.npy`; no RNG in the retrieval
    scripts. Both FLORES runs were executed in the foreground with `OMP/MKL/OPENBLAS/NUMEXPR=2`,
    no model load, no child processes, no visible windows.

## 2. Discrepancies

1. **README contradicts itself on the FLORES split.** `README.md:18` says the CSV has "2006 rows
   (997 `dev` / 1009 `devtest`)"; `README.md:117` and `127-128` say the printed table has
   `devtest N=1012`, `chance rank 506.5`, and "1012 candidate keys". Both statements were true of
   different CSV generations.
2. **The documented FLORES command fails.** `README.md:99` (`python table1.py`) raises
   `IndexError` at `table1.py:43`: a 2006-row boolean mask indexes 2009-row arrays. The README
   table cannot be regenerated from the working tree as shipped.
3. **"six Europarl pairs" is wrong for the fetch script.** `README.md:26` says the fetch script
   downloads/extracts the six xx-en pairs; `fetch_europarl_langs.py:42` sets
   `LANGS = ["de","es","fr","nl","pt"]` — five. `it` comes only from legacy artifacts that are not
   in the repo.
4. **Europarl docstring vs code.** `table1_europarl_multilang.py:1` lists five languages
   (`de/es/fr/nl/pt-en`), while `LANGS` (`:59`) has six and the README reports six.
5. **`smoke` fixtures are from a different sample.** `KNOWN` (`:561-563`) expects `it->en` raw
   `9.8%` / MRR `0.277` and `+D` `50.0%` / `0.574`; the README's it-en row is `19.6%` / `0.304`
   and `45.6%` / `0.527`. The smoke fixture is the legacy single-pair sample, not the 5k combined
   sample.
6. **"chance 506.5" is attached to the wrong statistic in prose.** `README.md:130-131` gives
   chance 506.5 for the **median** rank; 506.5 is `(N+1)/2`, the expected **mean** rank. The
   median's chance value is also ~N/2, so the claim is only approximately true and the reader is
   left to infer it.
7. **Agg split convention differs between retrieval and classification.**
   `table1_agg.py:72-79` labels the orphan URL `unknown` and drops it; `train_flores12.prepare_agg`
   maps the same orphan to `devtest` (`fillna("devtest")`). Retrieval numbers are unaffected, but
   the two "agg dev/devtest" sets are not the same set.
8. **README describes `+D` on normalized keys.** `README.md:61-63` says "adding `D` to every key"
   after stating that embeddings are row-normalized. In code, `D` is computed in raw space and
   added to raw keys, and only the sum is normalized (`table1.py:44`). The result is a direction
   shift, not a translation of a unit vector; the doc omits this.
9. **`flores_en_pl.csv` is a tracked file that no document mentions.** It is committed (25 rows,
   `en,pl`), produced by `tools/fetch_flores_en_pl.py` with its default `n_rows=25`, and is used by
   no retrieval protocol. `README.md` never references it or the tool.

## 3. Bugs / risks

1. **Fatal: `table1.py` has a stale 2009-row assumption.** It loads arrays and masks them with the
   CSV length without alignment (`:43`, `:62`). `train_flores12.py:419-439` already has the correct
   loader (`kept` indices into the 2009-row files). Any future CSV edit will break the script again
   in the same way; there is no guard that compares CSV rows to array rows.
2. **`fetch_europarl_langs.py` cannot rebuild `europarl_all_5k.csv`.**
   `COMBINE_LANGS = ["de","es","fr","it","nl","pt"]` (`:50`) requires `europarl_it_en_5k.csv`, but
   no shipped code path writes per-language CSVs: `sample()` is documented as provenance and is
   never called, and `run_lang()` reads the combined file (`table1_europarl_multilang.py:350`,
   `:529`). `combine_5k()` therefore returns `None` (`fetch_europarl_langs.py:120-124`) and the run
   still reports "fetch done" (`:391-393`) while leaving a stale combined file. A clean clone cannot
   regenerate the corpus file.
3. **Europarl embeddings are gone; the documented "reuse" path does not exist.**
   `README.md:27` says the script "reuses already-computed embeddings". The six embedding trees are
   empty, so `run_lang()` takes the embed branch (`:535-541`) and would re-embed 60,000 texts with
   two forwards each. The model is in the HF cache (`models--EuroBERT--EuroBERT-210m`), so this is
   possible but not cheap and not what the README promises.
4. **`smoke` can never pass.** It requires `europarl_it_en.csv` and `europarl_embeddings/`
   (`:567-571`); the CSV is absent and the directory is empty. It exits 1 with "legacy it-en files
   missing". The only model-free regression test for this pipeline is dead.
5. **Europarl evaluation hard-requires all four pooling modes.**
   `evaluate_rows()` loads `<mode>/emb_en.npy` and `<mode>/emb_xx.npy` for every mode
   (`:411-413`) and `run_lang()` treats a language as cached only if all eight files exist
   (`:534-536`). One missing mode aborts the language. `table1_agg.py:99-102` does the opposite and
   skips incomplete modes.
6. **No rank sanity check in the FLORES scripts.** Europarl asserts `1 <= r <= N` (`:397`);
   `table1.py` and `table1_agg.py` do not. A silent index misalignment would produce plausible but
   wrong ranks instead of an error.
7. **Repo-root write coupling.** `SUMMARY`, `PROGRESS_FILE`, `RUN_LOG`, `STATUS_FILE`, `PID_FILE`
   are module constants (`:76-80`) with no CLI override; any run writes into the repository tree.
8. **Europarl sampling provenance cannot be checked.** The corpora (`europarl_{xx}_en/`) are
   absent, so the docstring's "seeded rng(0), skip ~1,000,000 lines, exact-pair dedupe"
   (`:8-10`) is unverifiable. Only the derived CSV is shipped, and its `it` block came from a
   different, missing run.
9. **`tools/fetch_flores_en_pl.py` is an unguarded, unverified downloader.**
   `urllib.request.urlretrieve` (`:30`) has no timeout, no retry, no hash, and no post-download
   validation beyond the >=1 MB check on the *cached* path (`:28`). It writes `flores_en_pl.csv`
   into the current working directory (`:47`), which is a **tracked** file, so re-running it mutates
   the repo.
10. **README table omits printed columns without saying so.** `table1.py:72-80` prints MRR raw and
    both mean ranks; `README.md:119-124` shows only four of the eight columns. Nothing states the
    omission, so a reader cannot cross-check the full output against the table.

## 4. Missing scripts / artifacts

- **Legacy single-pair Europarl script.** `smoke()` (`:567-568`) needs `europarl_it_en.csv` and
  `europarl_embeddings/`, written by a script that is not in the repo. That same missing script is
  the only producer of `europarl_it_en_5k.csv`, which `COMBINE_LANGS` requires. This is a
  chicken-and-egg gap in the documented end-to-end path.
- **Europarl result artifact.** No `europarl_multilang_table1.md`, no progress JSON, no log, no
  status file, and no commit anywhere in history containing the markdown. The README table is
  therefore hand-carried evidence.
- **Europarl embeddings.** Six empty directory trees (`europarl_{de,es,fr,it,nl,pt}_en_5k_embeddings`)
  and one empty `europarl_embeddings/`.
- **No retrieval-side 0.975 ratio script** — intentional, since the bar is N/A.

## 5. Recommended changes

1. **Fix `table1.py` row alignment.** Reuse `train_flores12.load_sent_embeddings(mode, kept, 2009)`
   (or re-run `extract_embeddings.py`, which now reads 2006 rows and would write 2006-row arrays),
   then update the printed expectation and the README caption to `devtest N=1009`,
   `chance 505.0`. Add a hard check `n_rows(csv) == n_rows(npy)` before masking.
2. **Resolve the README split contradiction.** State which CSV each table came from, or regenerate
   Table 1 from the current CSV and replace the numbers (expected change <= 0.1 pp, verified above).
3. **Make the Europarl data path self-consistent.** Add `"it"` to `fetch_europarl_langs.py:42` or
   remove `"it"` from `COMBINE_LANGS`; treat `combine_5k() is None` as a fatal error instead of a
   printed note followed by "fetch done".
4. **Publish or retract the Europarl numbers.** Either commit `europarl_multilang_table1.md` plus
   the progress JSON after a rerun, or mark the Europarl table in `README.md` as "artifacts lost,
   not re-verified" so it is not mistaken for stored evidence.
5. **Repoint or delete `smoke`.** If kept, rebuild `KNOWN` from the shipped 5k `it` sample and ship
   the two files it needs, or make it a self-test on synthetic arrays.
6. **Add the rank assert to `table1.py` and `table1_agg.py`**, and add `--csv` / `--emb-root`
   overrides so the historical 2009-row reproduction is a documented flag, not a manual `git show`.
7. **Document the raw-space `+D`.** One sentence: `D` is fitted on unnormalized embeddings, added to
   unnormalized keys, and the sum is renormalized before the cosine.
8. **Document or delete `flores_en_pl.csv` / `tools/fetch_flores_en_pl.py`.** It is tracked, unused
   by retrieval, and downloads without a timeout.
