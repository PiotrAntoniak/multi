## Discrepancies

1. **`COVERAGE.md:98` is wrong.** It says the SHAP JSON/MD are "deleted, in git history". They
   were never tracked (see Verified 8). There is no history to recover from.
2. **`COVERAGE.md:99` describes the wrong method.** `shap_flores_dropped.py` does **not** zero any
   dimensions. It ranks dims by η², calls the top-k group "dropped" and the rest "kept", and
   compares their summed attribution. The actual zeroing experiments are
   `xgboost_flores_drop_optuna.py`, `xgboost_flores_lang.py`, `xgboost_flores_matrix.py`,
   `dim_removal.py`.
3. **`REPORT.md:59-61` overstates the result.** "SHAP mass on the language dims ≤ random (below
   random on FLORES, equal on MultiEURLEX)" is contradicted by the surviving `bos` figure:
   at k=211 the mass is ≈0.280 against 0.2747 (above, by 0.5 pp). The `mean` cells are below
   (≈0.119 vs 0.135; ≈0.291 vs 0.309). The word to use is "≈ random", not "≤".
4. **`pca_plots.py:1-5` docstring is stale.** It says "local analysis; script + outputs are
   gitignored". Both the script and all 10 of its PNGs are tracked (`git ls-files`).
5. **Model spec differs from the E17/E18 line, and no doc says so.** Both SHAP scripts use
   `xgboost_topic_optuna.BASELINE_PARAMS` = depth 6, 300 trees (`xgboost_topic_optuna.py:94`),
   with 8 `binary:logistic` tag models. E17's FLORES analysis uses depth 8, `min_child_weight=5`,
   400 trees, `multi:softprob` 12/11-class (`lang_shap_dims.py:78-82`). E41 is therefore a
   precursor on a different model, not a replication. README:39-40 calls it the "baseline", which
   is accurate but easy to confuse with E17.
6. **`lang_dims.py` covers 2 of 4 modes.** The docstring says "the FLORES embeddings"; the loop is
   `("mean", "bos")` (`:22`). `eos` has the largest language mass (289.2 vs 256.0) and `lead` the
   smallest (93.0). The figure omits the strongest and weakest pooling modes.
7. **`E17.audit.md:176` classifies these files as "legacy files not referenced by E17".** They are
   the code ancestor of E17's Part A (`lang_metrics.eta2`) and the precursor of its Part B; the
   first 237 dims are identical (Verified 4). "Not referenced" is true of the E17 document, but
   "not related" would be wrong. `COVERAGE.md:243` gets this right.
8. **`EXPERIMENTS.md` has no E41 entry.** E17 (lines 139-148) is the nearest entry; it cites only
   `lang_shap_dims.py`.
9. **`shap_flores_lang.py:1-9` says "Writes ... shap_flores_lang.md (+ .json)"**, which is correct
   for the code but no longer true of the tree. Nothing in the repo records the deleted numbers.

## Bugs / risks

1. **The `+D` panel is an identity, not evidence.** `pca_plots.py:62-67` adds
   `mean(E_en − E_l)` to every row of language `l`. Every language centroid then equals the English
   centroid exactly, so the visual overlap on the right-hand panel is guaranteed. A reader can
   easily read it as "language information is gone". The suptitle ("+D — PCA fit on English only")
   does not say that the shift was applied. The shift is mean-only, so it fixes centroids and not
   spread: in `pca_lang_bos.png` the English cloud stays the widest and a handful of outlier rows
   remain stranded in a detached cluster.
2. **`shifts` is computed over all 2009 rows, test included** (`:62`). README:58-60 defines the
   protocol shift `D` over **dev** rows. Harmless for an unsupervised diagnostic, but it is not the
   shift the retrieval and transfer experiments use, and it is not what E18's `perlang_center` uses
   (unlabeled target train rows).
3. **P0 — three scripts are broken against the current data.** `xgboost_topic_optuna.load_data`
   asserts `len(df) == 2009` (`:230`), but `flores200_en_it_de_fr.csv` has 2006 data rows since
   `00d4823` (2026-10-05 21:05). `pca_plots.py:93`, `shap_flores_lang.py:36` and
   `shap_flores_dropped.py:51` therefore raise `AssertionError` (confirmed by direct call).
   `pca_plots.py` fails *after* rewriting 8 of its 10 tracked PNGs, which is the worse case: the
   tree can silently end up half-regenerated. `train_flores12.prepare_sentence` asserts 2006 on the
   same file, so the two modules now disagree. `lang_dims.py` is unaffected (no CSV read).
4. **A stale import couples the PCA script to the training stack.** `pca_plots.py:14` imports all of
   `xgboost_topic_optuna` (optuna, pandas, xgboost) only to read lenient topic labels, which is why
   the CSV assert above reaches a plotting script. A 10-line local label reader would remove the
   dependency and the failure.
5. **`all_but_top_coords` (`pca_plots.py:51-54`) computes the all-but-the-top residual twice**
   (once for the reference PCA, once for the transform), and `all_but_top` is called twice per
   panel. Correct but wasteful; at k=1 it is cheap.
6. **SHAP list handling is tuned to binary output.** `shap_flores_lang.py:51-52` and
   `shap_flores_dropped.py:44-46` do `sv = sv[1] if len(sv) == 2 else mean(|s|)`. For a two-class
   `multi:softprob` model this silently keeps class 1 only. For the current `binary:logistic`
   models the result is a single `(n, d)` array, so the branch never runs — but a change of
   objective would change the metric without an error.
7. **No CLI, no resume, no status.** The SHAP scripts run in the foreground, write the JSON and MD
   only after both modes finish (`:117-120`, `:170-173`), and always overwrite. A crash after the
   first mode loses it. Compare `lang_shap_dims.py`, which has `--launch`, `--datasets` and
   `--smoke`.
8. **η² is computed on train+test rows** (`lang_metrics.eta2_lang` → all 2009). The dims that
   define the "dropped" group are therefore selected with the explained test rows included. This
   is ranking-only circularity, not label leakage, but E17's audit already recommends a
   `--eta2-split` flag; E41 needs the same.
9. **`xgboost` is unpinned** (`requirements.txt:4`). The PNGs were made 2026-10-05; the installed
   version is 3.2.0. A re-run can change splits and therefore every SHAP number.
10. **Unused work in `shap_flores_dropped.py`:** `probs` and `probs_it` (`:64`, `:72`) are computed
    and never used. `shap_flores_lang.py` has the same unused `probs`.
11. **Environment warning (same as E17).** `scipy 1.15.3` warns that it requires
    `numpy >= 1.23.5, < 2.5.0`, and `numpy 2.5.4` is installed. Nothing failed in the checks run
    here, but pin before a clean reproduction.
12. **The SHAP scripts never score the models they explain.** No F1/AUC is computed, so no E41
    artifact can be tied to model quality even indirectly.
