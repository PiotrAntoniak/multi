## Discrepancies

1. **Rounding makes fr look comparable.** `EXPERIMENTS.md:93` shows fr EN/native as `0.90` and
   the finding says 0/4. The exact value is **0.8959** (< 0.9); target/EN is 0.8613. The entry's
   2-dp table therefore appears to contradict its own verdict. Show 3 decimals or `<0.9 (0.896)`.

2. **Ratio denominator differs from the study convention.** E18 (`EXPERIMENTS.md:37-42`) and the
   master result (`:388-390`) define comparability as **target/English >= 0.9**. The E20 table
   uses **EN/native**. Both give 0/4, so the finding is unchanged, but the E20 table omits the
   target/EN values (0.720/0.752/0.861/0.709) that the convention asks for.

3. **"3 seeds" is imprecise.** The entry (`EXPERIMENTS.md:87`) says "3 seeds". The actual
   variation is three bootstrap resamples of train rows; the XGBoost config is deterministic.
   The script and MD explain this, but `EXPERIMENTS.md` does not.

4. **`perlang_z` is omitted from the E20 entry.** The English model uses each target's train
   mean/std for feature normalization (`toxi_proof_clean.py:130-139`, `:305-306`). "English-trained"
   is true for labels/model, but the pipeline uses unlabeled target train rows. The master result
   mentions `perlang_z`; the E20 entry should too.

5. **"0 cross-split overlap" is exact-text only.** The MD (`toxi_proof_clean.md:3`) and
   `leakage_report.md` say 0 overlap without the "exact text" qualifier. After normalization
   (lowercase, strip punctuation, collapse whitespace), residual train/test matches remain:
   it 39, de 70, fr 91, es 37 test rows. These are 1.3–5.7% of test. Removing them changes AUC by
   at most 0.013 (de EN 0.6718 -> 0.6593; fr EN 0.7666 -> 0.7646; it 0.6567 -> 0.6594;
   es 0.6333 -> 0.6351). The verdict is unaffected, but the claim should say "0 exact-text
   overlap".

6. **Train sizes are not matched.** EN trains on 24,000 rows sampled from a 2.53M pool; de native
   trains on 9,836, it 18,472, fr 21,011, es 23,349. EN has the largest training set, so the
   observed EN deficit is conservative. The opposite concern (EN sample is only 1.2% of its pool)
   does not create leakage because the sample is drawn before the 80/10/10 split.

## Bugs / risks

1. **`f1_optimal_threshold` edge case** (`toxi_proof_clean.py:179-186`). `precision_recall_curve`
   returns `len(prec)-1` thresholds. If the F1 argmax is the last precision point
   (`k == len(thr)`), the code clamps to `len(thr)-1`, which corresponds to the second-to-last
   precision point, not the last. The returned threshold can be slightly off. F1 is not the
   headline metric here (AUC/AP are), so the impact is small. Fix by using
   `thresholds[np.argmax(f1[:-1])]` or an explicit last-point rule.

2. **Embedding cache has no data version.** `ensure_emb` keys only on
   `emb_<lang>_<split>.npy` (`toxi_proof_clean.py:270-278`). If `data/toxi_clean/*.parquet`
   changes, a rerun silently reuses old embeddings. The old `toxi_proof.py` uses a different
   cache (`toxi_cache`), so there is no cross-run contamination now, but the risk remains for
   future data rebuilds. Delete `%TEMP%\opencode\toxi_clean_cache` after rebuilding data, or add
   a hash/mtime to the cache key.

3. **Bootstrap changes the estimand.** Each seed trains on a with-replacement sample, so about
   36.8% of rows are omitted and the unique-row count is ~63% of `n_train`. The reported AUCs are
   bootstrap averages, not the full-data model's AUC. The effect is small (sd 0.004–0.013), but
   the mean is slightly pessimistic and the sd is not a data-split confidence interval.

4. **No confidence interval over data splits.** The sd covers bootstrap resampling only. The 0/4
   verdict is far from the bar for it/de/es, but fr is genuinely borderline: EN/native 0.8959
   +/- 0.0099, target/EN 0.8613 +/- 0.0132. A different 80/10/10 draw could move fr across 0.9
   on the EN/native bar. The entry's 0/4 is correct for this split, but fr should be called
   borderline.

5. **EN threshold is miscalibrated for targets.** The EN model uses the EN validation threshold
   on every target test (`:320-325`, `:346`). Target F1@val-thr is 0.119–0.224, while accuracy is
   0.668–0.716. This is expected and is reported honestly in the MD, but a reader who looks only
   at accuracy/F1 would misread the result. AUC and AP are the correct headline metrics.

6. **Residual near-duplicate label conflicts.** Among the normalized train/test matches, labels
   disagree for 3 (it), 2 (de), 6 (fr), 0 (es) pairs. This is a small label-noise/leakage
   residue. It does not change the verdict.

7. **`load_parquet` has a redundant assignment** (`toxi_proof_clean.py:217`:
   `name = split if split != "validation" else "validation"`). Cosmetic only.

8. **Verdict wording is lenient in code.** `build_md` (`:657-659`) would say "largely comparable"
   if 3/4 EN/native ratios passed, even if 0/4 target/EN ratios passed. Not triggered here, but
   the two bars should be handled separately.

## Recommended changes

1. **Fix the E20 table** in `EXPERIMENTS.md`: add a target/EN column, print 3 decimals
   (0.778/0.780/**0.896**/0.802 and 0.720/0.752/0.861/0.709), and state which bar the 0/4 refers

2. **Add two parentheticals** to the E20 entry: "3 bootstrap seeds (not independent splits)" and
   "`perlang_z` uses unlabeled target train stats".
3. **Qualify the data claim**: "0 exact-text cross-split overlap". Optionally rebuild
   `data/toxi_clean/` with normalized-text dedup; the measured AUC effect is <= 0.013, so this is
   low priority.
4. **Fix `f1_optimal_threshold`** to handle the last precision point.
5. **Version the embedding cache** (hash of parquet mtime/size or a `--rebuild-cache` flag).
6. **Add a size-matched control** (e.g. subsample EN to each target's train size, or all to
   9,836) to separate transfer loss from train-size loss. This matters most for de.
7. **Keep the saved models and manifest.** They are the strongest reproducibility asset: all 15
   reproduce the published per-seed AUCs exactly.
