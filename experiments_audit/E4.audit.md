## Discrepancies

1. **"DONE" vs no artifact.** `EXPERIMENTS.md:211` says DONE. No script, JSON, MD, PNG, log, or PID
   exists. The correct status is UNVERIFIABLE (lost 2026-10-11), not DONE.

2. **E5b claims an exact reproduction that also has no artifact.** The Oct-13 rewrite says
   "E5b: reproduced E3/E4/E6 headline numbers (match ≥4 decimals)"
   (`git show 6cff2d5:EXPERIMENTS.md:181`). The current log drops E5 entirely. No E5 script or output
   survives. For E4, this claim is contradicted by the missing JSON and by the absence of any
   reproduction driver. If E5b ran, its driver was untracked and lost too.

3. **The EN self-scores disagree with the only surviving SST-2/emotion table.** E4 0.792 / 0.370 vs
   README 0.8052 / 0.3740. The gap is 1.3 pp and 0.4 pp. Small, but the entry gives no config, so a
   reader cannot tell whether E4 is a baseline, a single Optuna trial, or a different split.

4. **"raw" is called `full` in the JSON.** `chk_a.py:30,41` uses `full/en` and `full/it`; the entry
   says "raw". `chk_c.py:57-61` shows the condition list includes `full`, `centroid`, `zero90`,
   `subspace`, `abtt`. The entry reports only two of five conditions.

5. **The protocol is undocumented.** The entry gives no pooling, classifier, tree count, depth,
   learning rate, threshold rule, split sizes, or seed. The old log says "SST-2 (mean)"
   (`git show 21ab888:EXPERIMENTS.md:44`); `chk_a.py:24` uses depth 6, lr 0.1, 400 trees, hist,
   max_bin 64, n_jobs 2, seed 0. Those may be the E4 settings, but nothing states it.

6. **"centroid" is undefined.** It could mean subtract the EN-train mean, each target's mean, a
   validation-only mean, or a val+test mean. The difference matters: a target mean fitted on test
   features is transductive. The surviving primitive and smoke test do not resolve it.

7. **The entry does not say which split is scored.** It says "English -> translated it/de/fr". The
   caches have validation and test. `chk_a.py` scores test and tunes on validation. The entry does
   not state this, so "which rows" is ambiguous.

8. **The threshold objective is unknown.** `chk_a.py:13` tunes the SST-2 threshold to maximize
   accuracy, not macro-F1. `cl_sent_sanity.py:26` calls `C.best_binary_threshold`, whose body is lost.
   If the original maximized accuracy, the reported macro-F1 is not the optimum of the reported
   metric.

9. **The "residual gap ~0.15" is arithmetic on the same unverified cells.** SST-2: 0.792-0.649=0.143.
   Emotion: 0.370-0.219=0.151. The sentence "sentiment more language-specific + MT noise" is an
   interpretation, not a tested cause. The experiment has no MT-quality arm and no language-specific
   control.

10. **The 0.975 bar belongs to E18 and a different metric.** `E18.md:43-46` defines 0.975 on AUC.
    E4 reports macro-F1. A 0.975 ratio on macro-F1 is not the same difficulty as 0.975 on AUC.
    The audit computes the ratio because the task asks for it, but labels it a cross-experiment
    check, not an E4 criterion.

11. **The entry stores 3 dp with no uncertainty.** SST-2 test has 6,822 rows and emotion 2,000.
    At these sizes, 1-2 pp differences are not meaningful. No seed, no CI, no repeated run.

## Bugs / risks

1. **Per-target threshold oracle.** If the cross-lingual SST-2 cells use a threshold tuned on
   translated validation labels (`chk_a.py:34-40`), the table needs target labels. That is an oracle
   setting, not the deployable fixed-0.5 setting. The entry does not disclose it, and the numbers
   are optimistic relative to deployment.

2. **Possible transductive centroid.** If the centroid uses translated **test** rows, it uses
   unlabeled test features. That is not label leakage, but it is not deployable and it breaks the
   train/test separation. The lost definition cannot rule this out.

3. **Cache provenance mismatch.** The reported run predates the 2026-10-11 cleanup. The current
   caches were rebuilt on 2026-10-11/12 (mtimes 22:24–04:50 and 04:33–04:50; `rebuild_caches.py:1`
   says it rebuilds "cached artifacts lost in the 2026-10-11 cleanup"). Same recipe, but not proven
   to be byte-identical. MT and transformer revisions are not pinned.

4. **Weak cache validation.** `rebuild_caches.py:138-151` accepts a CSV if it has the expected row
   count and the two columns. `:122-135` accepts any finite 2-D `.npy`. A stale or corrupted cache is
   silently reused. There is no text hash, no model id record, and no language check.

5. **Empty MT rows are embedded as text.** `translated/sst2_it_test.csv` has 3 empty `text` rows;
   `..._it_validation.csv` has 2. `_coerce_texts` (`rebuild_caches.py:164-180`) maps `NaN`/`None` to
   `""`, and all empty rows get the same embedding (pairwise cosine 1.0). They are scored with their
   source labels. The effect is small (5/13,644 rows) but it is a silent data defect.

6. **Duplicate and conflicting labels in the translated sets.** SST-2 splits have 19–33 duplicate
   translated texts; up to 4 text groups in one split carry conflicting labels. Emotion has 0–2
   duplicates. MT collapses distinct English sentences, so exact-match dedup would be unsafe, but the
   duplicates add label noise to the evaluation and are not reported.

7. **No language verification and unpinned MT.** Nothing checks that the output is German, Italian,
   or French. A failed or wrong-direction MT model would silently pass English through and inflate
   the scores. The HF revision of `Helsinki-NLP/opus-mt-en-{it,de,fr}` is not recorded.

8. **No translated train split.** The entry's "English -> translated" phrasing is translate-test, not
   translate-train. That is fine, but the caches cannot support a translate-train comparison. Anyone
   reading "translated" as training data will be blocked.

9. **Source-data leakage inflates the EN reference.** `sst2.csv` has 61 test sentences and 58
   validation sentences that also occur in train (237 duplicate train sentences). `emotion.csv` has 11
   test texts in train. This is a pre-existing dataset/split issue, but it affects the EN-self
   denominator and therefore every ratio.

10. **The emotion de-raw cell is near chance.** Majority-class macro-F1 on the emotion test split is
    0.086 (class 1, 695/2,000). E4 reports 0.118 for de raw. The cell is only +0.032 above a trivial
    predictor; the low ratio (0.319) is partly a low-signal cell, not only transfer loss.

11. **Stale docstring in the nearest surviving SST-2 script.** `xgboost_sst2.py:11-13` says "train
    67,349 rows, validation 872 rows". The current `sst2.csv` is a seeded 80/10/10 re-split:
    54,577/6,822/6,822. The script logic uses the CSV, so the code is right and the docstring is
    wrong. This makes it easy to mis-state E4's split.

12. **`bos` pooling is degenerate, and it is cached anyway.** `check_tokens_cos_sim` reports id
    128000 norm 0.0028 and inverted related/unrelated ordering for `bos`. `rebuild_caches.py` still
    produces all 12 `bos` files. The old E4 log says mean, so `bos` was probably not used; if any cell
    used it, the number would be low for a known reason.

13. **Environment is not pinned.** `requirements.txt` lists package names with no versions. XGBoost
    3.2.0 and NumPy 2.5.4 are installed, and SciPy warns that NumPy is outside its supported range.
    Tree-model results can shift across versions. No environment record accompanies E4.

14. **No confidence intervals or seed.** One run, 3 dp, no seed. The 0.975 verdict is robust to this
    (the gaps are 12–66 ratio points), but individual cells are not.

## Recommended changes

1. **Change the status** from DONE to `UNVERIFIABLE — script and artifacts lost 2026-10-11` until a
   new run exists. Keep the numbers only with that label.

2. **Add a provenance footnote** to the table: single run, 3 dp, mean pooling (old log), exact
   EN/it-raw values quoted from the lost JSON by `chk_a.py:30,41`; all other cells unsourced.

3. **Write and commit a new driver** (`crosslingual_sentiment.py` or `e4_driver.py`) that consumes
   `sst2_emb/` + `translated_emb/`. Train on EN train, score translated test, and report both a fixed
   0.5 threshold and a validation-tuned threshold. Commit script + JSON + MD + PNG.

4. **Report both threshold policies.** Label the validation-tuned number "oracle threshold (needs
   target labels)" and the 0.5 number "deployable". Do not mix them in one table without a column.

5. **Define `centroid` precisely** in the new script: which rows fit it (train only vs val+test),
   whether it is EN or target, and whether it is applied to both sides. If it uses test features,
   label it transductive.

6. **Add a data manifest.** Record MT model ids and revisions, EuroBERT revision, rebuild timestamp,
   row counts, CSV hashes, and the count of empty/duplicate rows. Store it next to the JSON.

7. **Harden `rebuild_caches.py`.** Add a text hash and a model-id field to the cache check
   (`:138-151`), verify the npy row count against the CSV inside `cached_npy` (`:122-135`), and fail
   loudly on empty translations instead of embedding them.

8. **Fix or drop the 5 empty SST-2-it rows.** Either re-translate them, drop them from both CSV and
   npy with a recorded mask, or report their effect.

9. **Add E4 to `REPRODUCE.md`** with an exact command and expected runtime; state that it needs a GPU
   only for the optional cache rebuild.

10. **Reconcile the EN references** with `README.md:269,276` (0.8052 / 0.3740). State which model,
    split, and selection rule produced 0.792 / 0.370.

11. **Remove or qualify the E5b sentence** "reproduced E3/E4/E6 headline numbers (match ≥4 decimals)".
    No E5 artifact exists.

12. **Keep the 0.975 check separate.** It is E18's AUC criterion; present it as a cross-experiment
    comparison, and keep the absolute macro-F1 values beside the ratios.

13. **Report uncertainty.** Add a seed or a bootstrap CI for the 6,822/2,000-row test sets. At the
    observed gaps, the 0.975 verdict will not change, but the cell values need error bars.
