### 2.2 The 0.975 bar fails in both directions

not evidence of English-to-Italian parity. Comparing EN/EN with IT/IT mixes test sets with 12.10%
and 29.35% prevalence; precision at fixed recall is prevalence-sensitive, so that comparison is
invalid.

## 3. Bugs and risks

### 3.1 `toxi_pr.py`

- `:251-252` silently skips missing seed models. A cell can run with fewer than three seeds, or with
  zero seeds, without an error. Zero seeds would produce a NaN score mean and a broken plot.
- `:275` checks only row counts between the cache and the parquet. There is no content hash. A stale
  cache with the right row count is accepted silently.
- The cache key (`emb_<lang>_<split>.npy`, `:138`) does not encode backbone, pooling, dtype, or
  script version. A cache built by a different pipeline is indistinguishable.
- `:326-335` writes `toxi_pr.json`, `toxi_pr.md`, and `toxi_pr.png` unconditionally. There is no
  `--out-dir`, `--dry-run`, or `--no-overwrite`.
- `:292` computes a per-cell score mean over seeds for the figure, while `:203` computes P@R90 per
  seed and `:235` averages the metrics. The figure's curve is not the curve of the averaged metric.
  This is defensible but easy to misread.
- `:409` hard-codes "mean probabilities over seeds 0/1/2" in the figure title, even if models are
  missing.

### 3.2 `toxi_pr_all.py` and cross-script threshold rules

- `:103-110` searches a fixed 0.01 grid for the F1-optimal threshold. `toxi_pr_models.py:266-277`
  searches validation percentiles. The same XGBoost model therefore gets two different "val-tuned"
  thresholds:

| backbone | language | `toxi_pr_all.py` thr | `toxi_pr_models.py` thr | val P/R (all) | val P/R (models) |
|---|---|---:|---:|---|---|
| 210m | en | 0.150000 | 0.149348 | 0.6911 / 0.5978 | 0.6889 / 0.5978 |
| 210m | it | 0.220000 | 0.222012 | 0.6290 / 0.6726 | 0.6307 / 0.6726 |
| 610m | en | 0.140000 | 0.115547 | 0.7245 / 0.5868 | 0.6945 / 0.5950 |
| 610m | it | 0.180000 | 0.187634 | 0.5939 / 0.6903 | 0.5987 / 0.6844 |

The 610m EN difference is large. `toxi_pr.md` states the 0.01 grid; `toxi_pr_models.md` states
neither the grid nor the percentile rule, while `toxi_pr_models.json` records the percentile
search. Use one rule everywhere.
- `:366-367` writes `toxi_pr.md` only if it already exists. A clean checkout produces JSON and PNG
  but no markdown.
- `:358-360` overwrites `toxi_pr_all.json`; the docstring claims create-only for outputs except
  `.png/.md`. The JSON is also overwritten.
- `:371-378` builds a log line, then immediately overwrites it with a second assignment. Dead code.
- `:51` uses one seed. There are no confidence intervals.

### 3.3 `toxi_pr_models.py`

- `:266-277` picks the first percentile on an F1 plateau because the comparison is strict `>`.
  This is the same tie artifact the docstring criticizes for the old 0.01 grid. RF and KNN have many
  ties (104–155 and 1093–1439 distinct scores), so their validation thresholds are still arbitrary
  within a plateau.
- `:318-321` `pct_of_value` uses `mean(s <= v)`, while `:306` uses `np.percentile(s, q)`. These are
  not exact inverses. For unique scores the error is about 100/n (0.03–0.04 percentile points), but
  ties can move the marker by whole percentage points. The marker and the curve can disagree.
- `:426` loops over both `BACKBONES`, but `main:866` passes only `backbones` (the selected subset).
  `--backbone 210m` therefore raises `KeyError('610m')` in every per-model figure. The exception is
  caught at `:861-869` and only logged, so the run reports success with missing figures.
- `:809-813` writes a partial `{"results": ...}` JSON during the run. A crash leaves the real JSON
  without `config` or `generated`, and the MD from the previous run.
- `:849-856` smoke mode writes `toxi_pr_models.json.smoke` (incremental, keys only `results`) and
  `toxi_pr_models_smoke.json` (full payload) into the repo. Both contain 6 models (no XGBoost) and
  200-row splits. They are not comparable to the real run.
- `:783` writes a PID only when not smoke. `:163-169` uses a shared status path. A smoke run can
  overwrite a real run's status and cannot be killed through the documented PID path.
- `:1` says "NON-XGBoost classifiers" but XGBoost is the first row and the reference model.
- `figures_only` (`:706-723`) always uses both backbones. That is fine for the committed JSON but
  fails for a single-backbone JSON.
- The script writes JSON before MD and figures. If a later step fails, JSON is new and MD/figures are
  old. There is no transaction or temp-then-replace.

### 3.4 Data and evaluation risks

- EN test prevalence 12.10%, IT test 29.35%. P@R90 is not comparable across these test sets. Only
  same-test comparisons are valid for the 0.975 bar.
- Single seed for `toxi_pr_all.py` and `toxi_pr_models.py`; no CIs. The IT test has 678 positives;
  at 90% recall, the operating point uses about 611 positives. Precision has non-trivial variance.
- `at_recall` uses the first threshold whose cumulative positives reach `ceil(0.90 * n_pos)`.
  Observed recall is 0.9008 (EN) and 0.9012 (IT), slightly above target. Ties could overshoot more
  for discrete scores.
- `requirements.txt` pins nothing. The run emitted a SciPy/NumPy version warning from XGBoost. A
  future environment may not reproduce the exact trees or sklearn defaults.

## 5. Recommended changes

1. **Split the section.** Rewrite E27 as:
   - E27a — XGBoost P/R 2x2, with `toxi_pr.py` (per-language z-score, 3 seeds, 210m) and
     `toxi_pr_all.py` (raw, 1 seed, both backbones) reported as two separate pipelines.
   - E37 — seven classifiers, `toxi_pr_models.py`, with the percentile-axis note.
   - E27c — provenance table for every artifact and owning script.
2. **Replace the table.** Use `toxi_pr_all.json` values or regenerate from a script. Recompute
   deltas to +0.041652 / +0.017530 / +0.016427. Change the `?` header to `Δ 610m − 210m`.
3. **State the 0.975 result.** Add a column `EN/IT ÷ IT/IT` and a pass column. Report 0.7082 /
   0.7708 from JSON, or 0.7232 / 0.7804 from the old table. State `0/2 backbones pass`. Add the
   reverse direction (0.7197 / 0.7886).
4. **Remove or relabel EN/EN.** It is a backbone control, not a transfer comparison. If kept, label
   it "EN self (not transfer)" and add prevalence.
5. **Do not mix transforms.** Report per-language z-score and raw separately. State the seed count
   in every column header.
6. **Fix the calibration wording.** Use "cross-lingual threshold shift" unless Brier/ECE/reliability
   evidence is added.
