# E35 audit — `it_errors.py` / `list_errors.py` (FLORES EN-trained vs IT-trained error buckets, MT caches)

Audited 2026-10-20. Repo: `C:\Users\pedro\Documents\random_projects\multi` (git repo, HEAD
`b89bcef`). No repo file was modified: `git status --porcelain` for the eight E35 paths is empty
before and after, and all six artifact hashes are unchanged (see "Verified").

**Overall:** the numbers are real and fully reproducible. Both scripts regenerate their stored
artifacts **byte for byte**, the bucket algebra is internally consistent with the stored totals,
and the MT cache is a faithful opus-mt record. The main issues are documentation-level (schema
name drift between the two scripts, a no-op CLI flag, a "create-only" claim the code does not
honour), plus stale side-effect artifacts and a deterministic 30-item prefix sample.

## 2. Discrepancies

1. **Schema name drift between the two scripts for the same bucket.** `it_errors.json` stores
   `bucket_counts.it_only_wrong` (`it_errors.py:191-196`); `list_errors.json` stores
   `bucket_counts.target_only_wrong` (`list_errors.py:349-354`). Anything that merges the two
   artifacts (or a reader comparing them) must special-case the key. `transfer_gap` and
   `both_right` agree; only this one differs.
2. **"Outputs (create-only)" is false.** `it_errors.py:23` and `list_errors.py:40` promise
   create-only outputs; both then open with `"w"` (`it_errors.py:324-327`,
   `list_errors.py:534-537`) and overwrite unconditionally. This is how the earlier agg/de runs
   were lost (see §3).
3. **`--no-calib` is a no-op.** Declared at `list_errors.py:493-495`, never read; `calibrated` is
   hard-coded `False` at `:521`. Cosmetic but misleading in `--help`.
4. **Double period in both MDs.** `"...Evaluated on Italian (it) test rows.."` (`it_errors.py:225`)
   and `"...Evaluated on IT test rows.."` (`list_errors.py:389-391`): the format string appends
   `"."` to a value that already ends in `"."`. Present in the stored artifacts.
5. **`it_errors.md:220-222` prints the test size twice** ("test %d ... Italian test = %d rows"),
   both from `sizes.test`.
6. **`md_dataset(res, max_show)` ignores `max_show`** (`list_errors.py:378`) — the MD is driven by
   the `*_listed` fields instead; the parameter is dead.
7. **Accuracy vs the project's headline metric.** These artifacts report **accuracy** only, while
   E18/E19 headline on FLORES is **AUC** (0.856 EN-self sent) with micro/macro-F1 reported
   alongside (`flores_ceiling.md`: IT in-language micro-F1 0.5624 with train+val). 0.4139 must not
   be read as contradicting the AUC-based E18 tables; it is a different metric on a 12-class,
   strongly imbalanced task (majority-class rate 0.261, chance 0.083). No AUC/F1 is stored here at
   all, so nothing in E35 can be directly compared to the E18 0.975 bar.
8. **`it_errors.py` uses `it_only_wrong` in JSON but never lists those items** — only counts. So
   the "damage" bucket is not inspectable from the artifact, while the other two are.

**0.975 bar: N/A**, as required. The artifacts are descriptive error analysis and store no ratio
against a headline metric. A ratio *is* derivable from the two accuracies stored (0.857 sent,
0.753 agg), but accuracy is not the E18 headline metric and must not be presented as a pass/fail
of the 0.975 bar. `E35.md` states this explicitly.

## 3. Bugs / risks

1. **Single fixed output path = silent run clobbering (highest impact).** `list_errors.py` always
   writes `list_errors.json` / `list_errors.md` (`:75-76`). Evidence that runs were lost:
   - `mt_cache_it2en.json` holds **118** entries; exactly **60** are the current sent listing and
     **58** are Italian strings from `flores_agg.csv` that appear in no stored artifact. So an
     `--dataset agg --source en --target it` run happened and its outputs were overwritten.
   - `mt_cache_de2en.json` holds **6** entries, all from the agg German column. A completed
     60-string run writes 60 entries in one shot (`:147-153`), so 6 entries implies a
     `--show 3` (2 buckets x 3) **smoke run** on agg de, again with no surviving artifact.
   - The stored `list_errors.json` is sent/en->it only; there is **no agg artifact** for the
     general lister, and no de artifact.
2. **MT cache is keyed on text only** (`:126-136`). No model id, revision, direction or fp16 flag
   is stored in the payload; `mt_model` lives only in the JSON config, not in the cache. A model
   update, or a cache file copied to another pair's name, is silently reused. Keys are raw strings
   → any whitespace/typo variant misses.
3. **MT cache staleness is invisible.** 58 of 118 it2en entries are unused by the current
   artifact. The cache is gitignored (`mt_cache_*.json` in `.gitignore`), so it is untracked
   derived state that silently accumulates across runs.
4. **`--show` is the only sampling control, and it is a prefix.** `collect()` walks `np.where(mask)`
   in `test_pos` order (`:298-303`) and `attach()` truncates to `MAX_SHOW` (`:318-324`). The test
   rows themselves are a seed-0 permutation, so the prefix is arbitrary-but-deterministic rather
   than random or severity-ranked. On sent, the 30 listed `both_wrong` items all sit in
   `test_pos` 1-62 (14% of 209 items). Two runs on different `--show` values produce different
   subsets, so bucket counts stay valid but the *examples* are not a sample of record.
5. **"Hard items" cannot be separated from label noise.** 209/505 (41%) are wrong for both
   models; the lister has no ceiling/oracle reference (E19 / `flores_ceiling` do). Reading
   `both_wrong` as "genuinely hard" overstates it — the 12-class FLORES topic labels are known to
   be noisy, and the IT model is confidently wrong on some listed items (e.g. CSV row 1619:
   IT pred `sci/tech` at 0.69 vs gold `geography` at 0.02).
6. **The IT model is not at its ceiling.** It fits 997 train rows (`it_errors.py:124-133`), while
   `flores_ceiling` fits 1501 (train+val) for IT. A stronger Italian model would move items out of
   `transfer_gap` and into `it_only_wrong`/`both_right`, so **87 is a lower bound** on the
   in-language gain. Nothing in the artifact records this.
7. **The pair differs in two factors.** EN model = EN features (EN z-stats), IT model = IT features
   (IT z-stats). `transfer_gap` therefore conflates "trained on another language" with "scaled with
   another language's statistics". The two cannot be separated from these artifacts.
8. **`perlang_z` uses unlabeled target-train data.** The documented "EN-trained" model is not
   target-free: it is normalised with Italian train statistics (`flores_calib.py:113-121`, same as
   E18 `perlang_z`). Correct for the project recipe, but the label "EN-trained" alone understates
   what is used.
9. **Small-n buckets.** sent: `business and economy` 4 test rows, `safety` 8; agg: 11 classes over
   139 test rows, 276 train rows. Any per-class bucket count under ~10 is noise; `both_wrong`
   composition is dominated by `travel` (26% of the test set).
10. **Minor robustness.** `assert texts[row] is not None` (`it_errors.py:162`, `list_errors.py:285`)
    passes a pandas `NaN` through (`str(nan)`), so a missing text would be silently written as
    `"nan"` instead of failing. `list_errors.py` imports `torch` unconditionally (`:63`), so even a
    fully-cached run fails on a torch-less environment. `gpu_limit.limit_gpu()` (`:502-506`) caps
    the process at 10 GiB (`TORCH_GPU_LIMIT_GB`) — fine here, but it is a hidden global side effect.
11. **Artifact/config staleness is not detectable.** No git commit, no embedding file hash, no
    dataset mtime is recorded in either JSON config, so a swapped `.npy` would still "reproduce".
    Note the mtime oddity: `list_errors.json` is 2026-10-12 08:34 but `list_errors.py` is
    2026-10-14 09:00 (a bulk touch of ~20 files). Byte-identical reproduction proves the code did
    not drift, but mtime alone would suggest the artifact predates the script.

## 5. Missing scripts

1. **No aggregator.** Nothing produces an E35 table across pairs. Every `list_errors.py` run
   destroys the previous one, so a language matrix (en->it/de/fr) has to be re-run one at a time.
2. **No equality harness.** The claim "list_errors reproduces it_errors" is a docstring statement
   (`list_errors.py:40-42`) with no script or recorded check; this audit verified it by hand.
3. **No stored IT-model detail.** Only the EN-model confusion matrix is stored
   (`confusion_en_rows_gold_cols_pred`). Per-class recall/F1 of the IT model, and any AUC, would
   need `flores_calib` / `flores_ceiling`, not these scripts.
4. **No reproduction of the agg / de list_errors artifacts** — they no longer exist.
5. **No cache-maintenance path.** There is no prune/verify command for `mt_cache_*.json`
   (`rebuild_caches.py` exists but does not cover these).

## 6. Recommended changes

Ordered by value per unit of work (none applied — audit only):

1. **Give each run its own output.** Add `--out-prefix` or default to
   `list_errors_{dataset}_{source}2{target}.json`, and write a `.status.json`. Otherwise every new
   pair destroys the evidence for the previous one.
2. **Fix the doc/flag drift.** Unify the bucket key to `target_only_wrong` (or `it_only_wrong`) in
   both scripts; delete `--no-calib` or implement it; drop "create-only" or honour it with an
   `os.O_EXCL` guard (or a `--force`); fix the doubled period.
3. **Record the sampling rule.** Store in the JSON: seed, bucket size, `test_pos` selection mode
   (prefix vs random vs confidence-ranked). Prefer ranking by `gold_prob` and/or emit a random
   `--show` sample with its own seed, so the documents stop depending on argument order.
4. **Store the descriptive ratio explicitly, labelled N/A.** Put
   `"accuracy_ratio": {"value": 0.8566, "headline_metric": false, "note": "0.975 bar N/A"}`
   next to the accuracies. Same for agg (0.7531). This prevents a later reader from mistaking
   0.857 for an E18 comparison.
5. **Add metric fields** (micro-F1, macro-F1, AUC for both models) so the artifact is comparable to
   E18/E19 without a re-fit of `flores_calib`.
6. **List `it_only_wrong` items** (and store the IT-model confusion matrix) — the bucket is counted
   but not inspectable.
7. **Version the MT cache**: a header field `{"_model": ..., "_revision": ..., "_fp16": ...}` and
   cache-file validation against `mt_model_id`; prune entries not touched by the last N runs.
8. **Record provenance in the JSON config**: `git rev-parse HEAD`, sha256 of the four `.npy` files
   and the CSV, and the interpreter/xgboost versions (versions are already there).
9. **Quantify the "hard" bucket against a ceiling** — at minimum cite `flores_ceiling` (IT micro-F1
   0.5624 with train+val) in the MD caveats, and note that 87 is a lower bound because the IT model
   fits 997 rows, not 1501.
10. **Add a class-support table** to the MD so small-n classes (4 and 8 test rows) are visibly
    small, and report per-class counts for each bucket.
