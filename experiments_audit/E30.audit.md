## Discrepancies

1. **Stored toxic log/status do not belong to the stored toxic result.**
   `synth_toxic_it.json`/`.md`/`.png` are cap=160 (18:12), but `synth_toxic_it.log` and
   `synth_toxic_it_status.json` are cap=2000 (18:22–18:55). The cap=160 run's log was overwritten.
   A reader checking status sees an incomplete `generate` phase and may think the stored result is
   invalid.

2. **E30 line 315 says "full run pending"; the full run is not merely pending.** It is absent. The
   last attempt (cap=2000) stopped after 256/2,000 rows (~2 h 33 min for 256 rows), and no cap=2000
   result exists.

3. **"Toxic pipeline validated" overstates what was measured.** At 0.5 the synth arm reaches
   **11% (210m) / 14% (610m)** of the real F1 ceiling; at a val-tuned threshold **71% / 74%**. The
   stored cap=160 has 160 rows vs 18,472 real-IT rows (115x), and cap positive rate 0.125 vs IT
   train 0.283 / test 0.294. This is a plumbing run, not a scale-fair test of the recipe.

4. **`python synth_it.py` does not reproduce the stored FLORES artifact.** The script default is
   `Qwen/Qwen3-0.6B` (`synth_it.py:108`) with `--gen-batch 32` (line 111); the JSON is
   SmolLM3-3B with batch 16. The exact invocation is not in the docstring, the commit message, or
   the JSON. The reconstructed command is
   `python synth_it.py --generator HuggingFaceTB/SmolLM3-3B --gen-batch 16`.

5. **`--launch` silently drops generation flags.** `synth_it.py:532–543` forwards only
   `--generator`, `--backbones`, `--device`, `--gen-limit`; it drops `--gen-batch` and `--max-new`.
   `synth_toxic_it.py:688–704` likewise drops `--gen-batch` and `--max-new`. Therefore the stored
   FLORES artifact (batch 16, non-default) **could not have been produced via `--launch`**; it was
   foreground or via an external wrapper. The launcher is not a faithful repro path.

6. **The FLORES and toxic tasks use different prompts.** FLORES uses the short custom prompt
   (`synth_it.py:109–110`); toxic uses `paraphrase_prompts` (`synth_toxic_it.py:240–242`). E30
   describes both as one "cross-lingual rewrite template". This is a prompt confound between the
   two datasets and prevents attributing both results to one template.

7. **Metric switch vs E18.** E18's FLORES headline was AUC and found no 0.975 cells; E30 uses
   macro-F1 and finds four passing cells. Different training arms (synthetic IT vs EN transfer), so
   not a contradiction, but the two "pass/fail" statements are not directly comparable. E30 should
   say which metric the bar uses.

8. **E30's toxic statement does not report the toxic ratios at all.** The stored verdict says
   "only 11% of the ceiling"; the MD table also shows F1@val-thr 0.4615 vs 0.6496 (71%). Neither
   number appears in E30. A reader cannot tell whether "validated" means 11% or 71%.

9. **Toxic verdict wording is confusing.** `synth_toxic_it.json` verdict: "It changes EN-transfer
   by +0.043 F1 (0.020)" — the parenthetical is the EN-transfer value, not a second delta. Should
   read "raises F1 from 0.020 to 0.064". Same wording in the MD/script (`synth_toxic_it.py:811–813`).

10. **Stale-provenance risk on `synth_it.py --from-json`.** `build_md` prints the current
    `SYSTEM_PROMPT` constant (`synth_it.py:407`), not `cfg["system_prompt"]`. If the constant is
    edited, rebuilding the MD misreports the prompt used for the stored run. Toxic uses
    `cfg` for the prompt description.

## Bugs / risks

### High
1. **Toxic chunk-resume ordering bug.** In `synth_toxic_it.generate_italian` (`302–361`), cached
   chunks are appended to `out` during the scan, while missing chunks are generated afterwards and
   appended after all cached chunks (`320–353`). If the cache is non-contiguous (e.g. chunk 0
   missing, chunk 128 cached), the final list order is wrong relative to `y_en_tr`. The current
   cap=2000 cache is contiguous from 0 (chunks 0, 128), so this run is safe, but a resumed/deleted
   chunk can silently scramble text↔label alignment. Fix: collect `(c0, preds)` and sort by `c0`.

2. **No generation filtering, contrary to the documented recipe.** `PARAPHRASE_TEMPLATE.md:104–115`
   requires termination/repetition, length-ratio, dedup, and optionally geometric filtering.
   `paraphrase_prompts.py:97–116` defines `length_ratio_ok` and `geometric_filter`, but a repo-wide
   grep finds **no call sites**. Neither synth script filters. Measured on the stored caches:
   - FLORES: 1/1,501 outside length ratio [0.6, 2.0] (min 0.583, max 1.833); 118/1,501 contain
     quote characters; 0 empty; 0 exact duplicates.
   - Toxic: **9/160 outside [0.6, 2.0]** (min 0.033, max **19.286**); **79/160 contain `"""`**;
     146/160 contain quote characters; 0 empty; 0 exact duplicates.

3. **`"""` delimiter echo is a prompt bug, not just a cleaning bug.** The cross-lingual template
   wraps the input as `""" {text} """` (`paraphrase_prompts.py:35`). SmolLM3 copies the delimiter
   into its output; `_clean` (`synth_toxic_it.py:271–282`) strips `<think>`/labels but **not**
   quotes. 49% of toxic outputs are triple-quoted. The FLORES prompt has no `"""` delimiter and
   produces no triple-quoted outputs, which supports the causal link. Fix: strip paired `"""` and
   surrounding quotes in `_clean`, and/or remove the delimiters for SmolLM3.

4. **Toxic generation is too short for long documents.** `GEN_MAX_NEW=256`; FLORES already needed
   384 because 256 truncated long sentences (`synth_it.py:112`). Toxic Reddit texts are longer and
   generation input is truncated at 1,024 tokens (`synth_toxic_it.py:340–341`). The 19.3x length
   outlier and 0.033x short outputs are symptoms. Raise max_new or scale with input length, and
   filter.

5. **Toxic comparison is not size- or balance-matched.** `synth_it`/`en_transfer` use 160 rows;
   `real_it` uses 18,472; cap positive rate 0.125 vs IT 0.283. The "11% of ceiling" conflates
   language, 115x data volume, and prior shift. A cap sweep (160 / 1,000 / 2,000 / 8,000) or
   class-reweighting is needed before any recipe claim.

6. **No label-preservation check for toxicity.** Translation can flip toxicity (negation, slurs,
   quoted vs asserted hate). The prompt says "preserve meaning", but 49% quote artifacts and 9/160
   length failures show the generator errs. No filtering, no agreement check against a strong
   real-IT model, no human spot-check. This is a correctness risk for the labels, not just quality.

### Medium
7. **`--launch` flag passthrough is incomplete** (see Discrepancy 5). Fix both `launch_detached`
   call sites to forward `--gen-batch` and `--max-new`; add a unit check that the detached argv
   equals the interactive argv.

8. **`synth_toxic_it` does not store `n_empty`.** It computes it at `756–757` but the payload
   (`762–778`) omits it; FLORES stores `n_empty=0` (`synth_it.py:610`). Add it for both.

9. **`paraphrase_csv.py` uses right padding.** It does not set `tok.padding_side = "left"`
   (`42–46`), unlike `synth_it.py:232` and `synth_toxic_it.py:293`. Batched decoder-only greedy
   generation with right padding is padding-sensitive and can differ from single-row output. It is
   a utility, not part of the E30 numbers, but it is cited in the E30 template review.

10. **Embedding-path consistency is claimed, not proven, for FLORES.** Synthetic text is embedded
    at runtime by `synth_it.embed_mean` (`294–314`) with plain tokenization, max_length 511, fp32;
    real text comes from `extract_embeddings.py` (`85–128`), same conventions. The conventions
    match, but runtime length-sorted batching is a different code path; small numerical differences
    are possible. Toxic matches `backbone_grid._embed_mean` (`backbone_grid.py:157–185`,
    `EMB_MAXLEN=512`, bf16 forward, fp32 arrays) more closely.

11. **Toxic threshold is selected on IT val and scored on IT test.** That is legitimate calibration,
    but `f1_pos_val_thr` is an optimistically selected threshold; it is not a threshold-free result.
    The 0.5 F1 is the honest fixed-threshold number and is the one that gives 11%.
    `f1_optimal_threshold` (`215–222`) has no nested split.

12. **400 trees on 160 rows (toxic) is heavily overparameterized.** With ~20 positives, variance
    dominates. The fixed params are fair across arms but not a tuned baseline. A smaller
    `n_estimators`/`max_depth` sensitivity check would clarify whether the 11% is capacity noise.

13. **Single seed, 505-row FLORES test, no CIs.** The 0.9888 and 0.9834 margins over 0.975 are
    0.0046 and 0.0084 macro-F1; the binomial standard error on 505 rows is roughly 0.02. The pass
    is not statistically robust. No bootstrap or seed sweep exists.

14. **The 0.975 bar is applied post hoc and only to FLORES.** It comes from E18, where the FLORES
    headline was AUC. E30 applies it to macro-F1 and never applies it to toxic. This is a
    metric/selection choice, not a preregistered criterion.

15. **"Ceiling" is a same-size real model, not an upper bound.** For FLORES, real-IT 1,501 is a
    fair same-size comparator. For toxic, real-IT 18,472 is a different-size model; calling it a
    "ceiling" for a 160-row arm is misleading.

### Low
16. **`synth_it.py` docstring still says the default generator is `Qwen/Qwen3-0.6B`** (`31–40`) and
    the usage example uses `Qwen/Qwen3.5-0.8B` (line 61), while the stored run is SmolLM3-3B.
    Update the docstring with the exact repro command.

17. **FLORES prompt is not the reviewed template.** E30 says "cross-lingual rewrite template", but
    FLORES uses a shorter custom prompt without the "never add/drop" constraints. Unify or
    explicitly label the two prompts as different cells.

18. **`n_empty` / generation-quality counters are not in the JSON.** No count of quote artifacts,
    length-ratio rejects, or dedup drops. These are needed to audit generation quality without
    re-reading the temp cache.

19. **Temp-only generation cache is not tracked.** The 1,501 FLORES generations and 160 toxic
    generations live only under `%TEMP%\opencode\...`; a temp cleanup destroys the ability to
    rebuild the JSON without a GPU re-run. Consider a compressed copy under `multi/` or a tracked
    checksum manifest.

20. **The environment warns that XGBoost expects NumPy < 2.5 but NumPy 2.5.4 is installed.**
    XGBoost still ran and reproduced exactly, but the warning is a latent environment risk for
    future reruns.

## Bottom line

The **FLORES result is verified and reproducible**: synthetic Italian reaches **0.9888 (210m) /
0.9834 (610m)** of the same-size real-IT macro-F1 ceiling, and the mixed arm is **1.0263 / 0.9859**.
All four pass the 0.975 bar on macro-F1 (and on AUC); the 210m `synth_it` accuracy ratio (0.9714)
does not. EN transfer is confirmed at 0.233 / 0.328. Generation sources are the EN train+val rows
only; no test leakage was found.

The **toxic arm is only a cap=160 plumbing run**: 11% / 14% of the real-IT F1 ceiling at 0.5,
71% / 74% at a val-tuned threshold. The full run is **NOT DONE / NOT AVAILABLE**; the last
cap=2000 attempt stopped at 256/2,000 rows and its log/status are stale. The cap=160 comparison is
115x smaller than the real-IT arm and has a different positive prior, so it cannot support a
recipe-level claim. The main code risks are the `--launch` flag drop, the toxic chunk-resume
ordering bug, the unfiltered `"""` echo (79/160), and the missing full run.
