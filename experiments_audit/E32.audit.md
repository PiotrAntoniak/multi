# E32 audit — Union of all generators' paraphrases

**Entry:** `EXPERIMENTS.md` §E32 (lines 333–344).
**Script:** `all_paraphrases.py` (519 lines, commit `7ea97fc`). **Artifacts:** `all_paraphrases.json`,
`all_paraphrases.md`, `all_paraphrases.png`.
**Audit date:** 2026-10-20. **Repo files modified:** none. All writes are in
`C:\Users\pedro\AppData\Local\Temp\opencode\`.

**Bottom line.** The pooled FLORES table is correct and reproduces exactly. The pipeline has no
leakage: the union is built from the generators' 1501 **train+val** paraphrases, and the test is the
505 real Italian rows. The 0.975 bar passes on macro-F1 (all_combined/real_it **1.145**,
all_combined/best_single **1.151**). The headline is nevertheless confounded: the union has **3x the
rows** (4503 vs 1501) while every comparator has 1501, so the entry's "same-size real-Italian
ceiling" is false, and the real_it arm is not a ceiling once it is exceeded. At volume-matched 1501
the union (0.4089) is **below** the best single (0.4125). The toxic arm is **partial (2/3
generators)** and is not reported in the entry. The defensible claim is "three paraphrastic views
per source example help", not "pooled synthetic data beats a same-size real model".

   - en_transfer: 0.4158415842 / 0.2332034564 / 0.7920247787 (entry 0.4158 / 0.2332 / 0.7920).
   - Single generators: Qwen3.5-0.8B 0.5465 / 0.4067 / 0.8533; Qwen3.5-2B 0.5228 / 0.3968 / 0.8823.
   - `+0.062` over best single is exact: 0.474866 - 0.412492 = **+0.062374**. "+0.0599" over real_it
     is exact: **+0.059945**.

2. **The 0.975 bar passes.**
   - `all_combined / real_it` = 0.4748662374 / 0.4149217280 = **1.144472** full precision;
     from the 4-dp table values 0.4749 / 0.4149 = **1.144613 -> 1.145**. Pass.
   - `all_combined / best_single` = 0.4748662374 / 0.4124920126 = **1.151213 -> 1.151**. Pass.
   - Both are far above 0.975; the verdict is not sensitivity to the 1.145-vs-1.1445 rounding.

3. **Full independent re-fit reproduces the whole table.** All six FLORES arms were re-fit from the
   cached embeddings using the exact `gen_compare._eval_flores` path and `XGB_PARAMS`
   (CPU, `n_jobs=2`, seed 0, depth 8, 400 trees, `multi:softprob`, 12 classes):
   real_it 0.554455/0.414922/0.883795; en_transfer 0.415842/0.233203/0.792025;

   SmolLM2 0.524752/0.412492/0.864752; all_combined 0.588119/0.474866/0.882055.
   Every value is identical to the stored JSON at 6 dp (zero difference at stored precision).

4. **The pooled set is train paraphrases only; the test is real Italian; no leakage.**
   - `flores_struct()` (`all_paraphrases.py:79-90`) sets `trva = concat(train_idx, val_idx)` and
     `en_src = cur.iloc[trva]["en"]`, `it_ref = cur.iloc[trva]["it"]`. `train_idx` is the 997-row
     `dev` split and `val_idx` is the first half of `devtest` (504), `test_idx` the second half
     (505) - `train_flores12.py:324-351`.
   - Verified at runtime: `len(trva)=1501`, `len(test)=505`, **intersection = 0**.
   - The generator cache path (`all_paraphrases.py:117-121`) hashes
     `[generator, dataset] + list(texts)`. All three FLORES caches exist with exactly 1501 entries,
     so they were generated from the 1501 train+val EN texts, not from test text.
   - The union is `vstack` of the three cached per-text embedding matrices (each 1501x768) with the
     same 1501 labels repeated: 4503x768 / 4503. The test matrix is `emb_it[test_idx]` (505x768).
     No test row enters training. **No leakage found.**

5. **Union construction is mathematically valid.** EuroBERT mean pooling is per-text, so stacking
   per-generator embeddings equals embedding the pooled text; no cross-row state is involved. All
   three cached matrices are finite (checked), and the label vector matches the row count.

6. **Arm definitions are consistent with E31.** `real_it` trains on `X_it_tr` (1501 real IT rows),
   `en_transfer` on `X_en_tr` (the same 1501 source rows in English), singles on their 1501 synthetic

   table (0.4125/0.4067/0.3968), which cross-validates the shared pipeline.

   `X=(4503, 768) y=(4503,)` and the same metrics as the JSON.

8. **Provenance and code state are clean.**
   - Log: FLORES 1.4 s -> 181.7 s, toxic -> 273.7 s; metrics printed line-by-line match the JSON.
   - Outputs and JSON were committed in `3ae8703` (2026-10-14 07:03); `git status` is clean for the
     tracked E32 files.
   - `all_paraphrases.py` changed after the run in `7ea97fc` (09:01). The diff is **only** the

## Discrepancies

1. **"the same-size real-Italian ceiling" is false (material).** `EXPERIMENTS.md:343-344` compares
   the 4503-row union with the 1501-row real_it arm and calls it same-size. `all_paraphrases.md:21`
   and the JSON verdict also say "real-IT ceiling" without the volume caveat. This is the main
   inferential flaw in the entry.
2. **real_it is not a ceiling.** The union exceeds it on accuracy (0.5881 vs 0.5545) and macro-F1
   (0.4749 vs 0.4149). It is a 1501-row real-Italian **reference**, not an upper bound.
3. **"1.145" is table-rounded.** Full precision is 1.144472 (1.144 at 3 dp); 1.145 comes from
   0.4749/0.4149. The pass is unaffected, but the entry should not present 1.145 as a full-precision
   ratio. The /best_single 1.151 is exact to 4 dp (1.151213).
4. **"AUC ties at the top" is imprecise.** Pooled AUC 0.882055 is below the best single
   (Qwen3.5-2B 0.882251) and below real_it (0.883795). It is a near-tie with Qwen3.5-2B, not a tie
   at the top.
5. **E32's heading omits the toxic arm.** `EXPERIMENTS.md:333` says "FLORES done", but
   `all_paraphrases.json`/`.md` contain a toxic result. The entry should either report it as partial
   or state that only FLORES is claimed.
6. **The toxic MD table labels a 2-generator union "ALL generators".** `all_paraphrases.md:28` and
   `all_paraphrases.py:319-320` use the constant `COMBINED_LABEL = "ALL generators"` even when
   `gaps` is non-empty. The verdict line does mention the missing SmolLM2, but the table does not.
7. **`n_train=1501` is train+val, not the 997-row training split.** This matches `gen_compare` and
   E31, but the entry calls it "train" without qualification. It is not a leakage issue because
   hyperparameters are fixed, but it overstates the training-set size.
8. **Minor:** the entry says "3×1501 = 4503 rows", correct; "AUC ties at the top", see item 4.
   No other numeric mismatch was found.

## Bugs/risks

1. **No volume control in the verdict logic.** `verdict_for()` (`all_paraphrases.py:242-264`) computes
   `pct_ceil = 100 * comb / ceil` and declares "UNION WINS" without matching `n_train` or reporting
   the row-count ratio. The artifact therefore invites the "beats the ceiling" reading. This is a
   design/reporting bug, not a numeric one.
2. **`toxic_ready()` treats a partial cache as ready.** `all_paraphrases.py:415` globs
   `gen_*_toxic_8000_*.json`, which matches `gen_HuggingFaceTB__SmolLM2-1.7B-Instruct_toxic_8000_<hash>.json.partial.json`.
   On a rerun the toxic branch would run (instead of recording `pending`), then
   `collect_generations()` would find the exact full-cache path missing and skip SmolLM2. The final
   2-generator numbers are unchanged, but the `pending`/`completed` bookkeeping is wrong. Use an exact
   full-filename match and validate the row count.
3. **Partial unions are presented as complete.** If only 2 of 3 generators are cached,
   `completed_datasets` still includes toxic, `pending` stays empty, and the table says "ALL
   generators". The only warning is the parenthetical in the verdict text. Add a `partial` flag and
   surface it in the header, or mark the dataset pending.
4. **Cache validation is length-only.** `collect_generations()` (`:142-152`) checks `len(cached) !=
   len(en_src)` but not that entries are non-empty or that the JSON is a complete generation. A
   truncated file that still parses with 1501 entries would pass. Low risk given the hash naming,
   but a `None`/empty-string check is cheap.
5. **Cache key excludes generation settings.** `gen_cache_path()` hashes generator, dataset and source
   texts, not the prompt template, `GEN_MAX_NEW`, dtype, or decoding. Changing the paraphrase prompt
   or generation config reuses stale Italian text silently. Include a prompt/config version in the
   hash, or document "delete the cache after prompt changes".
6. **The union implicitly weights every source example 3x.** `ycomb = concatenate([y_tr] * n_gen)`
   (`:186`, `:228`) gives each original label three identical copies. That is the intended design,
   but it is not stated in the entry; a reader may assume 4503 independent examples.
7. **If no generator is available, the verdict path degrades to NaN.** `run_flores()` only builds the
   union when `len(available) >= 1` (`:184`), but `verdict_for()` still computes `comb=nan` and
   `pct_ceil=nan` if `COMBINED` is absent. Not triggered in the stored run, but an empty/mis-specified
   `--generators` list would produce a confusing artifact rather than a clean error.
8. **`real_it` is hard-coded as the ceiling in the plot and verdict.** The dashed line at
   `arms["real_it"]` (`:383-385`) is labeled "ceiling"; when the union is above it the plot visually
   contradicts the label. Use "real-IT reference (1501 rows)".
9. **Toxic is even less volume-matched than FLORES.** all_combined has 16000 rows (2 x 8000) while
   the singles have 8000 and real_it has 18472. The 0.2170 F1 is not comparable to the 0.5811 real_it
   F1 on any matched-volume basis. Do not promote this arm.
10. **`write_outputs()` runs after each dataset** (`:487`, `:511`, `:513`), so an interrupted toxic
    run can leave a valid FLORES-only JSON with `completed_datasets=["flores"]`. That is acceptable,
    but there is no explicit `pending` entry for a crash, only for "no cache at all".

## Missing scripts

- **No missing core script.** E32 is fully implemented by `all_paraphrases.py` on top of
  `gen_compare.py`; all inputs and caches exist.
- **No volume-matched control script/artifact.** The 1501-row subsample, 3x-duplication and 2-generator
  controls in this audit were ad hoc; the repo has no script that produces them. This is the main
  missing piece needed to support the entry's causal claim.
- **No E32 reproduction entry in `REPRODUCE.md` or `README.md`.** `grep -i "all_paraphrases|E32|
  gen_compare"` returns nothing in either file. A fresh user cannot find the command from the docs.
- **Toxic SmolLM2 generation is incomplete.** No completed `gen_..._toxic_8000_*.json` exists; the
  partial is 4800/8000. The E32 toxic arm cannot be completed without rerunning that generation.
- **No test for partial-cache handling.** The `.partial.json` glob bug (Bugs item 2) has no coverage.

   114% with 114.4% and state the 3x-row caveat in the same sentence.
4. **Correct 1.145 to 1.1445 (full precision)**, or explicitly say "1.145 from the 4-dp table";
   keep 1.151 for /best_single.
5. **Correct the AUC sentence:** pooled AUC 0.8821 is ~equal to the best single (0.8823) and below
   real_it (0.8838); it does not tie at the top.
6. **Report toxic as PARTIAL (2/3) in the entry**, with n_train 16000 and `SmolLM2 pending`; or omit
   it and say only FLORES is claimed. Rename the toxic table row "Qwen0.8 + Qwen2B (2/3)".
7. **Fix `toxic_ready()`** (`:412-420`) to require the exact full filename (exclude `.partial.json`)
   and, ideally, `len(cached) == 8000` before adding the generator.
8. **Add a `partial`/`gaps` note to the MD table header** and set `pending["toxic"]` whenever
   `gaps` is non-empty, so `completed_datasets` is honest.
9. **Add E32 commands to `REPRODUCE.md`** (FLORES-only and full), and note that the FLORES path needs
   only cached embeddings (no GPU), while a cold run needs `gen_compare.py` generation first.
10. **Label `n_train` as train+val (997+504)** in the tables, or add a `n_unique` column (1501) so
    the 3x duplication is visible.
11. **Run >=3 seeds or bootstrap the 505-row test** before quoting a 0.01-scale difference; the
    current single-seed point estimate cannot distinguish 0.4089 from 0.4125.
