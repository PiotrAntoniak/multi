## 2. Discrepancies

**D1 — Artifact timestamps do not match a 793 s run (provenance).**
`agg_pr_2models.py` mtime 2026-10-11 20:48:57; PNGs 20:49:14-20:49:17; `agg_pr2.json`/`.md`
20:49:17. A full run takes `elapsed_sec = 793.35` and writes md/json **before** the PNGs
(`main`, `:807-808`), so a genuine run would place the script ~13 min *before* the outputs. The
observed 20 s gap equals a re-emit (measured 2.9 s). Conclusion: the shipped JSON/md/PNGs were
last written by `--reemit-from-json`, and `elapsed_sec` describes an earlier, non-shipped run.
Numbers are unaffected (re-emit is byte-deterministic), but the artifacts are not the direct
output of the run they quote.

**D2 — Test-set F1 values are not exactly reproducible.** With the stored params and the
reconstructed split, the 4 reconstructible cells give (F1-opt, EN test / IT test):

| cell | stored EN / IT | recomputed EN / IT |
|---|---|---|
| 210m raw | 0.6593 / 0.4710 | 0.6505 / 0.4525 |
| 210m l2_thenZ | 0.6357 / 0.5078 | 0.6272 / 0.5121 |
| 610m raw | 0.6423 / 0.5398 | 0.6540 / 0.5171 |
| 610m l2_thenZ | 0.6360 / 0.6103 | 0.6304 / 0.6121 |

Max |delta| = 0.023 (610m raw IT). Val AUC matched within 0.005 (V7), so this is not a wrong
split/label/param; it is numerical drift amplified by a 139-document test set. Sensitivity probe
on 210m raw: `n_jobs=2,seed=0` -> EN 0.6505 / IT 0.4525; `n_jobs=1,seed=0` -> 0.6572 / 0.4494;
`n_jobs=2,seed=1` -> 0.6749 / 0.4681. Changing only the thread count or seed moves IT F1 by
0.002-0.02, i.e. the same order as the D2 gap. Verdict: stored numbers are inside reproduction
noise, but the stored 4-dp precision is not meaningful and the run cannot be reproduced exactly.

**D3 — `inlp_610_meta.final_acc` does not reproduce.** Stored 0.26553625340262316 (round 1);
recomputed 0.1788 (rank 3 confirmed). Both are <= the 0.30 stop threshold, so the *decision* is
unchanged, but the exact probe accuracy on which "reached chance" rests is not reproducible with
the current sklearn. The basis itself (`lang_inlp_agg_610.npz`) is missing, so the stored numbers
for `inlp` / `pc+inlp` cannot be checked at all.

**D4 — Ten cells, five parameter vectors.** `raw` (210m) = `raw` (610m) = `inlp` (610m), and
`pc` (610m) = `l2_thenZ` (610m), and `inlp` (210m) = `pc+inlp` (210m), and `pc` (210m) =
`l2_thenZ` (210m). With a seeded TPE sampler over 20 trials this can happen (the same trial index
wins several studies), but the JSON stores only `best_params`, never the per-trial table, so the
TPE trajectory cannot be verified. No trials CSV is produced by this script (contrast
`xgboost_topic_optuna.py:1016-1026`, which does write one).

**D5 — Docstring provenance claim is unverifiable.** `agg_pr_2models.py:11-12` says the five
methods are "identical to `agg_pr_methods.py` / `agg_pr_lang.py`". Neither file exists, so the
claim that the transforms match the earlier experiments cannot be checked. The same holds for
`pc_ablation_flores.py` (`:16`) and `crosslingual_topic_agg.py` (`:21-22`).

**D6 — 210m basis shape is not recorded.** `backbones.210m.inlp_basis` is a free-text string
("lang_inlp_agg.npz (existing)"); only the 610m meta has `n_removed`/`rounds`/`acc_curve`. The
210m basis dimensionality is asserted only in the md prose ("3 dirs", `agg_pr2.md:18`).

## 3. Bugs / risks

**R1 (methodological, highest impact) — F1-optimal thresholds are chosen on the test split.**
`tune_cell` sweeps thresholds on the test probabilities and reports `at_optimal` at the test
argmax (`agg_pr_2models.py:350-356`; `optimal_f1_t` is per language). With 51 grid points and 139
test documents this is a max-over-51 oracle choice; every P/R/F1 pair in the md, the EN-IT gap
table, the "best method per backbone" section and the "does 610m help" conclusion inherit that
bias. The drawing dots are also placed at these oracle thresholds (`_draw_lang`, `:625-630`).

**R2 — Statistical thinness.** 139 test docs (1,529 pairs), one split, one seed, no CIs, no paired
test despite EN/IT being the same rows. Reporting four decimals implies ~1e-4 resolution on a
quantity whose seed-to-seed spread is ~1e-2 (D2).

**R3 — The 610m "inlp" intervention is 3 of 1,152 dimensions (0.26 %).** INLP stops after one
round because the language probe hits the 0.30 threshold immediately. At that width "inlp" is a
near-no-op, so "INLP does not help at 610m" (IT 0.5116 vs raw 0.5398) is mechanically expected
and should not be read as evidence about language subspaces. Same at 210m (3/768 = 0.39 %), though
there the post-projection probe really does collapse (0.03), so 3 directions do carry the language
signal at 210m; the two backbones are not comparable in this respect.

**R4 — INLP basis is fitted on all 562 rows per language** (`get_basis_610` passes
`{lg: X610[lg] for lg in LANGS}` unfiltered, `:261`), i.e. train+val+test features. Label-free, so
not leakage in the supervised sense, but it is transductive and differs from the "TRAIN pool"
phrasing used for `pc` in the md (`agg_pr2.md:17`). The same is presumably true of
`lang_inlp_agg.npz` (built by the missing `crosslingual_topic_agg.py`).

**R5 — Precision is stored as 0 when the denominator is 0.** At t above the largest predicted
probability TP+FP = 0, and `sweep_prf` records 0.0 (`at_f1_opt`/`curves` in the JSON). This draws
a hard 1.0 -> 0 cliff in every panel (e.g. 210m raw EN at t=0.96, IT at t=0.46) that looks like a
model collapse and is really "undefined". The md text never explains it, and the `optimal` choice
is unaffected only because F1 is 0 there too.

**R6 — Non-monotone precision is expected but unexplained.** Because the predicted positive set is
nested but shrinkable, micro precision wobbles (8-14 downward steps per cell, e.g. 0.792 -> 0.783
at 210m raw EN). Not a bug; worth one caption line so it is not read as a plotting error.

**R7 — Checkpoint lives in `%TEMP%` and is not referenced in the JSON.**
`ckpt_path = %TEMP%\agg_pr2_optuna_partial.json` (`:753-754`). It is absent today, so `--resume`
is a silent no-op and none of the 200 trials can be recovered; the JSON does not record the path,
the trial table, or the code version. Combined with `--resume` skipping cells without any version
stamp (`:785-789`), a future partial rerun can silently mix cells produced by different code.

**R8 — `--reemit-from-json` rewrites the JSON in place** (`:713-715`), adding/replacing `outputs`.
Benign here (verified byte-identical), but it means `agg_pr2.json` is not an immutable record and
its mtime does not date the run (see D1).

**R9 — Minor perf, not correctness:** `load_agg_embeddings_610("mean", n_rows)` is called inside a
per-language comprehension (`:765-766`), so each of the four `.npy` files is read four times
(16 `np.load` calls instead of 4).

**R10 — No environment fingerprint.** JSON has no python/xgboost/sklearn/optuna/numpy versions, no
start timestamp, no input checksums. Given D2/D3 this is the single biggest obstacle to
re-verification.

## 5. Recommended changes

1. **Restore provenance (smallest fix to make this auditable):** re-add `agg_pr_methods.py` (or
   vendor `load_data`, `build_method_features`, `onehot`, `sweep_prf`, `optimal`, `at_index` into
   `agg_pr_2models.py`), plus `pc_ablation_flores.py`, `crosslingual_topic_agg.py`,
   `agg_pr_lang.py`, `lang_inlp_agg.npz`, `lang_inlp_agg_610.npz`. Add a local `--methods raw,l2_thenZ`
   fallback so the two missing-basis methods can be skipped instead of aborting the whole run.
2. **Store the provenance in the JSON:** python/xgboost/sklearn/optuna/numpy versions, run start
   time, `ckpt_path`, and SHA-256 of every input (csv, 8 npy, both npz). Also store both bases'
   `shape`/`n_removed` in `backbones` (fixes D6).
3. **Store the Optuna trial table** (per-trial params + EN-val metric) per cell, as
   `xgboost_topic_optuna.py:1016-1026` already does. Without it D4 cannot be settled.
4. **Fix the threshold story (R1):** either select the threshold on EN val and apply it to both
   languages, or keep the oracle threshold but rename the columns to
   `F1@test-argmax-t (oracle)` and add F1 at a fixed t (e.g. 0.5) and at the EN-val-selected t.
   Report bootstrap CIs over documents for every P/R/F1 (the EN/IT rows are paired, so use a
   paired bootstrap).
5. **Make undefined precision explicit (R5):** store `None`/NaN when TP+FP = 0 and say so in the
   caption; this also removes the 1.0 -> 0 cliff from the figures.
6. **Add a sentence on non-monotone precision (R6)** and on the 610m INLP width (R3) — the audit
   verified 3/1152 dims, so the `inlp` label at 610m deserves an explicit "3 dimensions removed"
   note in the results text, not just in the tuning section.
7. **Store the IT/EN ratios and the per-language test AUC.** This experiment currently stores no
   ratio, so it cannot be compared with the 0.975 bar without an ad-hoc derivation; storing
   `test_ovr_macro_auc` per (cell, language) would also make it cross-checkable against E18.
8. **Re-run once with a recorded environment and re-emit the artifacts from that run** so that
   `elapsed_sec` belongs to the artifacts on disk (D1), and `--reemit-from-json` writes to new
   filenames instead of mutating the JSON (R8).
